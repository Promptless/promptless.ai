Connect Promptless to an MCP-capable editor and start documentation tasks by asking in plain language. The connection authorizes over OAuth, so there's no API key to create, paste, or rotate. Every org member can set it up for themselves.

One command connects Claude Code:

```bash
claude mcp add --transport http promptless https://api.gopromptless.ai/mcp
```

After that, run `/mcp`, pick **promptless**, and approve the connection in the browser tab that opens.

## The problem

Starting a Promptless task from outside the editor meant switching context: open the dashboard, create a task, come back. For interactive use, that's friction. The API trigger exists for this, but it's designed for server-to-server automation and CI pipelines, and it requires managing an API key.

For engineers and writers who spend time in Claude Code or Cursor, there was no path that matched the interactive, low-friction feel of asking the editor a question.

## What it does now

After connecting, your editor surfaces four tools and calls them when you ask:

- **`submit_documentation_task`**: Start a documentation task. Provide instructions and, optionally, a `doc_collection_id` to target a specific collection.
- **`list_doc_collections`**: List your documentation collections and their IDs.
- **`get_task_status`**: Check the status of any task in your organization by its ID. Covers tasks started from Slack, a GitHub PR, the dashboard, or the API, not just MCP submissions.
- **`search_suggestions`**: Search existing suggestions by keyword and status. Use it before submitting to avoid duplicating work that's already in flight.

Ask in plain language. "List my Promptless doc collections, then start a task to document the new authentication flow in the API docs collection." Your editor maps that to `list_doc_collections` followed by `submit_documentation_task`.

Tasks submitted over MCP show up on the Triggers page with an **MCP Task** pill and a byline: `<client name> · submitted by @<username>`.

## Who benefits most

Engineers and technical writers who spend time in Claude Code or Cursor and want to trigger documentation work from their current context, without switching to the dashboard.

`search_suggestions` is worth using before submitting a task. If the work is already covered by an open suggestion, you'll find out before creating a duplicate. Ask your editor to check first: "Before submitting a task for the webhook retries change, search existing suggestions for 'webhook retries.'"

Teams already using the API trigger for automation aren't affected. The API key path and MCP are independent surfaces that route through the same pipeline.

## How to use it

Connect Claude Code with one command, then authorize in the browser:

```bash
claude mcp add --transport http promptless https://api.gopromptless.ai/mcp
```

For Cursor, add an HTTP MCP server named `promptless` pointing to `https://api.gopromptless.ai/mcp` in your Cursor MCP settings, then click **Needs login** and approve.

The server URL is also available in the dashboard under **Settings** in the **Editor connection (MCP)** section. Each organization member connects and authorizes separately. The connection refreshes automatically and lasts 90 days before requiring a re-consent in the browser.
