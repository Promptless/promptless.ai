Promptless now resolves its own citation threads on generated documentation pull requests and merge requests. Repositories that require every review thread resolved before merging can merge a Promptless-generated docs PR without anyone touching citation threads by hand.

## The problem

When Promptless creates a documentation suggestion, it posts citation comments as review threads on the generated docs PR. Each one links a specific claim in the suggestion to the source it was drawn from: a PR description, a changelog entry, an issue, a code comment. That trace is useful for reviewers who want to verify the suggestion before approving it.

The problem is that many repositories enforce branch protection rules that block merging until every open thread is resolved. GitHub calls this "Require conversation resolution before merging." GitLab has equivalent merge request approval rules. These are common in documentation repositories, where teams want reviews to be deliberate before anything goes live.

Every citation Promptless posted was an open thread. On a documentation suggestion with several citations, a reviewer would finish their review and then have to go close each citation thread by hand before clicking merge. Some teams turned the protection off. Others added "resolve citations" to their merge checklist. Neither is a good answer.

## What changed

Promptless resolves each citation thread shortly after posting it. On GitHub, it uses GitHub's native review thread resolution. On GitLab, it uses GitLab's native discussion resolution.

The thread closes, but the citation doesn't disappear. The link to the source material and the referenced text stay attached to the diff. The evidence is still there for anyone who looks at the PR history. It's just closed, not gone.

Human replies take precedence. If a reviewer replies to a citation thread before Promptless resolves it, the thread stays open. If Promptless resolves a thread and a reviewer later reopens it or replies, it stays in the state the reviewer left it. Promptless only resolves threads with no human reply.

## Who benefits most

Teams with "require all conversations resolved" branch protection (GitHub) or equivalent merge request settings (GitLab) on their documentation repository.

If your team was manually resolving citation threads before every merge, that step is now gone. The protection stays on. The citations stay visible on the diff. The only difference is the threads are closed.

It's also useful for reviewers who found citation threads cluttered their open thread list. Citations contain evidence, not action items. Closing them automatically keeps the review list clean while preserving the audit trail.

## Nothing to configure

This behavior is on for every organization with no opt-in. If your team wants to keep a citation thread open for discussion, reply to it before Promptless resolves it, or reopen it afterward. A reply from any reviewer keeps the thread open regardless of Promptless's default.
