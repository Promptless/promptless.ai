Promptless for Agent Instructions runs as a loop with six stages. You author instructions and compile them into the plugins your fleet installs; the fleet's hosts collect evidence as agents work; a worker you deploy analyzes that evidence into findings; and a remediation agent turns high-confidence findings into pull requests you review. Each stage below names the one interface you touch and links to the page that covers it in depth.

## Author

Humans author governed instructions in an **Instruction Hub** — a versioned Git repository you own. Instructions come in six asset kinds: `skill`, `rule`, `agent`, `command`, `hook`, and `mcp` (skills are `SKILL.md` directories; the others are referenced as `kind:id`). Portable Agent Skills and MCP configurations are the headline. The hub governs all six kinds; skills and MCP are two of them, not the whole set.

You group assets into **packages** and declare them in `hub.yaml`. Every hub ships a required `pig` package that carries the managed update skill and host runtime the toolchain injects at compile time.

The interface here is the config files in the repository. See [Set up your Instruction Hub](/docs/governance/get-started/set-up-your-instruction-hub).

## Compile

The `pig` command-line tool validates the hub and compiles each package into target-native plugins. There are exactly four compile targets: Claude, Codex, Cursor, and Gemini. `pig` runs in CI and never as a long-running service.

The interface here is the `pig` CLI in your pipeline. See [Compile and publish](/docs/governance/get-started/compile-and-publish).

## Install and enroll

Publishing commits the compiled output to a release branch and rewrites the marketplace manifests your fleet installs from. Installing the compiled Claude and Codex plugins places the `promptless-host-runtime` executable on each host — the host runtime, a host-side CLI, distinct from the hosted Promptless Runtime that is the control plane. Enrollment points a host at a worker you have already deployed, so stand up the worker (see the Ingest stage below) before you enroll hosts. You then enroll a host with `promptless-host-runtime enroll`, which opens a browser approval; a signed-in org member approves, and the host runtime caches a one-time per-host credential. Collection then runs on its own through generated lifecycle hooks — detached and non-blocking, so it never slows an agent session.

The interface here is the `promptless-host-runtime` CLI on each host. See [Enroll a host](/docs/governance/get-started/enroll-a-host).

## Ingest

The **worker** is a service you deploy in your own infrastructure. It ingests evidence from exactly three sources: Claude Code, Claude Desktop, and Codex. Each host uploads only the new bytes past a local watermark; the worker stores the raw slices and a canonical trace object per session in the S3 bucket and Postgres database you own. For what leaves each host, what stays local, and what hosted Promptless ever receives, see [Trust and data model](/docs/governance/start-here/trust-and-data-model).

The interface here is the worker's deployment configuration. See [Plan your deployment](/docs/governance/deploy-the-worker/plan-your-deployment).

## Analyze

The **Friction Analyzer** runs inside the same worker. It analyzes one parent session per run, dispatches concurrent investigators that each read only the ranges they cite, and produces findings backed by append-only evidence. Analysis is opt-in — you enable it once the worker is running.

The interface here is the analysis environment-variable group. See [How analysis works](/docs/governance/findings-and-remediation/how-analysis-works).

## Remediate

Only high-confidence findings are eligible for remediation. A finding's confidence is either low or high, and it rises to high as more session evidence points to the same failure; see the [Findings reference](/docs/governance/findings-and-remediation/findings-reference) for the field. An isolated agent in the worker checks out a fresh branch of your hub repository, drafts a fix, and opens a ready pull request against the hub's default branch.

<Aside type="caution">
  Human pull request review is the gate. Nothing merges automatically, and there is no automated evaluation gate in this loop. Merging a fix re-runs the publish workflow, so the change recompiles and redistributes to the fleet, which picks it up on the next startup refresh.
</Aside>

The interface here is the GitHub pull request. See [Remediation pull requests](/docs/governance/findings-and-remediation/remediation-pull-requests).
