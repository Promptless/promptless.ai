If you are evaluating this product, this is the page to read first. It describes where your data lives, what leaves each zone, and the design principle that governs every transfer: data minimization. Trace content — the record of what your agents actually did — stays in infrastructure you control.

## The three trust zones

Promptless for Agent Instructions spans three zones with different owners:

- **Your Git repository** holds the Instruction Hub. You own it and its history.
- **Your own infrastructure** runs the worker along with the S3 bucket and Postgres database it uses. Raw trace bytes and canonical trace objects live here and nowhere else.
- **Hosted Promptless** is the control plane. It coordinates enrollment and projects findings to GitHub, but it never receives trace content.

## What crosses each zone

**Host to worker (both in infrastructure you control).** A host uploads verbatim native trace bytes — only the new ledger byte ranges past its local watermark, gzip- and base64-encoded and SHA-256 verified. Alongside the bytes it sends:

- batch metadata: batch id, source, host, session identity when present, and plugin, policy, and collector versions;
- optional analysis-context snapshots: instruction availability and installed hub release identity;
- check-in reports: a config hash, booleans, and redacted drift;
- one-time enrollment metadata: host instance id, a host label derived from username and hostname, and platform.

**Stays local on the host (owner-only).** The source ledger — the byte offsets already read — never leaves the host, and neither does the cached per-host credential. The ledger only starts recording at enrollment, so history from before you enrolled a host is never uploaded.

**Worker to hosted Promptless (metadata projection only).** The worker sends the control plane a limited metadata projection:

- worker, session, and lineage ids;
- host instance id and label;
- lifecycle, ingestion, and analysis status;
- timestamps;
- event and turn counts.

This projection deliberately excludes all trace content — prompts, tool activity, working directories, git metadata, model names, and source fingerprints. Findings are also written to hosted Promptless so their provenance lives server-side, but a finding's text is model-authored prose describing the session; it can reference session detail without being verbatim trace content.

**Worker to your model provider.** To produce findings, the Friction Analyzer sends trace-derived analysis input — a session digest and trace — to the external model provider you configure. That is a provider you choose and authenticate, distinct from the hosted-Promptless projection. See [Enable the Friction Analyzer](/docs/governance/deploy-the-worker/enable-the-friction-analyzer).

## Credentials and configuration

The system uses four credentials, and the worker holds no shared plugin secret — it verifies every incoming host credential through hosted introspection, scoped to a deployment instance and target so a credential for one host family cannot authenticate as another. The full credential list, the environment variables that carry secrets, and the ingest-source and endpoint tables live in one place. See [Worker configuration and data](/docs/governance/reference/worker-configuration-and-data).

## Current limitation

<Aside type="caution">
  The signed policy a host fetches is shape-checked, not cryptographically verified; transport security relies on HTTPS. Cryptographic signature verification is a known gap noted in the code and not yet shipped. Treat host-policy integrity as resting on transport security today.
</Aside>
