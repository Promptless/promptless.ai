This is the single source for the worker's full configuration surface and the data facts behind it. The deploy pages show the subsets you need for a given task and link here for the complete tables. Every environment variable is prefixed `INSTRUCTION_HUB_`.

## Required environment variables

The worker needs these seven to start and serve:

| Variable                                 | Secret | Purpose                                           |
| ---------------------------------------- | ------ | ------------------------------------------------- |
| `INSTRUCTION_HUB_RUNTIME_BASE_URL`       | No     | The hosted control-plane base URL.                |
| `INSTRUCTION_HUB_INSTALL_TOKEN`          | Yes    | The worker's install token for hosted Promptless. |
| `INSTRUCTION_HUB_DEPLOYMENT_NAME`        | No     | The name of this deployment.                      |
| `INSTRUCTION_HUB_DEPLOYMENT_INSTANCE_ID` | No     | The identifier of this deployment instance.       |
| `INSTRUCTION_HUB_CONFIG_HASH`            | No     | The hash of the deployed configuration.           |
| `INSTRUCTION_HUB_CUSTOMER_POSTGRES_DSN`  | Yes    | The DSN for the Postgres database you own.        |
| `INSTRUCTION_HUB_TRACE_OBJECT_S3_BUCKET` | No     | The S3 bucket for trace slices and objects.       |

## Analysis environment variables

Set this group together to enable the Friction Analyzer; all are prefixed `INSTRUCTION_HUB_ANALYSIS_`:

| Variable                                        | Secret | Purpose                                             |
| ----------------------------------------------- | ------ | --------------------------------------------------- |
| `INSTRUCTION_HUB_ANALYSIS_ACTIVATION_AT`        | No     | When analysis becomes active.                       |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_PROVIDER`       | No     | `openai`, `azure_openai`, or `aws_bedrock`.         |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_AUTHENTICATION` | No     | How the analyzer authenticates to the provider.     |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_BASE_URL`       | No     | The provider base URL.                              |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_NAME`           | No     | The model to use. Defaults to `gpt-5.6-sol`.        |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_API_KEY`        | Yes    | The provider API key.                               |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_URL`       | No     | The hub repository URL.                             |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_ID`        | No     | The hub repository identifier.                      |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_FULL_NAME` | No     | The hub repository full name.                       |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_TOKEN`     | Yes    | The repository token.                               |
| `INSTRUCTION_HUB_ANALYSIS_QUIET_WINDOW_HOURS`   | No     | How long a session must go without new activity before analysis runs. Defaults to 0.5. |
| `INSTRUCTION_HUB_ANALYSIS_MIRROR_ROOT`          | No     | The local root for the repository mirror.           |

## Helm observability values

These Helm values and the environment they render control observability. See [Observability](/docs/governance/deploy-the-worker/observability) for behavior.

| Value or variable               | Purpose                                                               |
| ------------------------------- | --------------------------------------------------------------------- |
| `observability.datadog.enabled` | Enables Datadog APM. Disabled by default.                             |
| `observability.datadog.*`       | The `env`, `service`, `agentUrl`, and `site` settings for Datadog.    |
| `DD_TRACE_ENABLED`              | Set to `false` in the image; rendered `true` when Datadog is enabled. |
| `observability.sentry.enabled`  | Enables Sentry error reporting. Disabled by default.                  |
| `existingSecretName`            | The Kubernetes secret holding the Sentry DSN.                         |
| `dsnKey`                        | The key within that secret that holds the DSN.                        |
| `SENTRY_DSN`                    | The process environment the chart maps the DSN into.                  |

<Aside type="note">
  Point `existingSecretName` and `dsnKey` at a secret holding a DSN for a separate Sentry project provisioned for the worker. The chart maps it into `SENTRY_DSN`.
</Aside>

## Credentials

The system uses four credentials:

| Credential          | Prefix        | Held by           | Purpose                                                                                      |
| ------------------- | ------------- | ----------------- | -------------------------------------------------------------------------------------------- |
| Install token       | `plih_`       | Worker            | Authenticates the worker to hosted Promptless; supplied via `INSTRUCTION_HUB_INSTALL_TOKEN`. |
| Per-host credential | `plihost_`    | Host              | Authenticates a host to the worker; cached once at enrollment.                               |
| Enrollment codes    | `plihenroll_` | Enrollment flow   | Browser-approval and polling codes used during enrollment.                                   |
| Repository token    | —             | Remediation agent | A repository-scoped GitHub token for a single repository.                                    |

The worker holds no shared plugin secret. It verifies every incoming host credential through hosted introspection, keyed on deployment instance id, credential hash, and target. Because introspection is target-scoped, a credential issued for one host family or deployment cannot authenticate as another. Hosted Promptless projects findings to GitHub itself, so worker ingestion and analysis never touch GitHub credentials.

## Ingest sources

The worker accepts exactly three sources:

| Display name   | Source id        | Trace path                           |
| -------------- | ---------------- | ------------------------------------ |
| Claude Code    | `claude`         | `~/.claude/projects/**/*.jsonl`      |
| Codex          | `codex`          | `${CODEX_HOME:-~/.codex}/**/*.jsonl` |
| Claude Desktop | `claude-desktop` | `**/audit.jsonl`                     |

Claude Desktop uses the Claude record parser but is a distinct source; it maps to the `claude` credential family for enrollment only.

## API endpoints

The worker exposes four endpoints:

| Method and path                      | Purpose                            |
| ------------------------------------ | ---------------------------------- |
| `GET /healthz`                       | Liveness and readiness check.      |
| `GET /v0/host-enrollment/policy`     | Return the host-enrollment policy. |
| `POST /v0/host-enrollment/check-ins` | Accept host check-in reports.      |
| `POST /v0/traces/batches`            | Accept uploaded trace batches.     |

## Trace object and upload path

The worker stores a canonical trace object per session (schema v1). It has eight top-level fields:

- `session`
- `lifecycle`
- `sources`
- `rollups`
- `context_artifacts`
- `preamble`
- `pending`
- `turns`

Events are a discriminated union with a global monotonic `seq`, over eight kinds:

- `user_message`
- `assistant_message`
- `reasoning`
- `tool_call`
- `tool_result`
- `compaction`
- `session_event`
- `other`

A host uploads only the new bytes past its local ledger watermark, gzip- and base64-encoded and SHA-256 verified, through `POST /v0/traces/batches?target=<host>`.

## Known limitation

The signed policy a host fetches is shape-checked, not cryptographically verified. See [Trust and data model](/docs/governance/start-here/trust-and-data-model) for what that means for host-policy integrity today.
