Once a host installs your Claude or Codex plugins, the injected [host runtime](/docs/governance/start-here/key-concepts) (`promptless-host-runtime`, version 0.2.7) is ready to enroll with your worker deployment and collect that host's session traces.

## Enroll a host

Enrollment uses a browser approval so a signed-in member of your organization authorizes each host.

<Steps>
  1. **Run enroll on the host**, naming the host family with `--host`:

     ```bash
     promptless-host-runtime enroll --host claude
     ```

     Use `--host codex` or `--host claude-desktop` for those families.

  2. **Approve in the browser.** The runtime opens the enrollment page and listens on a `127.0.0.1` loopback callback. A signed-in organization member approves the host there.

  3. **Let the runtime cache the deployment details.** After approval, the runtime polls for its one-time per-host credential (a `plihost_` token), the worker deployment identifier, and the deployment public key. It caches them locally.
</Steps>

<Aside type="note">
  The per-host credential is returned in plaintext exactly once and stored owner-only on the host. For how it is verified, see [Trust and data model](/docs/governance/start-here/trust-and-data-model).
</Aside>

## How collection runs

After enrollment, collection runs on its own through generated lifecycle hooks — you do not schedule it:

- On **`SessionStart`**, the Codex and Claude Code hooks ensure the host configuration and run a quiet collection pass. The Claude Code hook also runs a best-effort pass for `--host claude-desktop`.
- On **terminal events** — `Stop`, `SessionEnd`, and `SubagentStop` where supported — the hooks run collection only.

Every collection pass runs detached and non-blocking, so a worker, policy, or upload problem never interrupts the agent session. The runtime encrypts new byte ranges to the deployment key and sends them through the outbound Promptless relay. Your worker retrieves and decrypts the batches inside your infrastructure. For what those uploads contain and how sessions are reconstructed, see [Trace object and sources](/docs/governance/reference/trace-object-and-sources).

## Check status or reset

To inspect a host's enrollment and configuration, run:

```bash
promptless-host-runtime status
```

To clear a host's local enrollment state — for example, before re-enrolling — run:

```bash
promptless-host-runtime reset
```
