The Instruction Hub is a versioned Git repository that holds every governed instruction your fleet runs on. You author assets, group them into packages, and declare the whole hub in a `hub.yaml` manifest. The interface for this stage is the repository's config files and the `pig` command-line tool; see the [Command-line reference](/docs/governance/reference/command-line-reference) for every subcommand.

## Asset kinds

Instructions come in six kinds, referenced as `kind:id`:

- `skill` — a `SKILL.md` directory.
- `rule` — a standing instruction the agent always applies.
- `agent` — a subagent definition.
- `command` — a slash command.
- `hook` — a lifecycle hook.
- `mcp` — an MCP server configuration.

Portable Agent Skills and MCP configurations are the headline of what a hub carries. A hub governs all six kinds; skills and MCP are two of them. Design your hub around the assets your fleet actually uses.

## Packages

A package groups related assets. Declare each one in `packages/<id>.yaml` with:

- `id` — the package identifier.
- `name` — the display name.
- `owners` — the people or teams responsible for the package.
- `includes` — the assets the package ships.

Packages are yours to define around how your teams own instructions. There is no fixed set of packages you must create.

## The required `pig` package

Every hub ships a `pig` package (display name `PIG`) with an empty `includes` list. It always ships because the toolchain injects a managed update skill and the host runtime into it at compile time — that is what places `promptless-host-runtime` on your fleet's hosts. Keep this package in the hub and list it in `stable_packages`.

## The `hub.yaml` manifest

The root `hub.yaml` declares the hub:

- `org` — your organization identifier.
- `plugin_id` — the plugin identifier the fleet installs.
- `plugin_name` — the plugin display name.
- `plugin_version` — a SemVer version string.
- `stable_packages` — the packages that ship in the stable release. This list must include `pig`.
- `targets` — an optional override of the compile targets.

## Scaffold a hub

<Steps>
  1. Run `pig init` in a new repository to scaffold `hub.yaml` and the `packages/` layout.
  2. Author your assets, then run `pig scan` to discover them and see how they map to packages.
  3. Add each package to `stable_packages` in `hub.yaml`, keeping `pig` in the list.
  4. Run `pig validate` to check the manifest and asset references before you compile.
</Steps>

<Aside type="tip">
  Once the hub validates, continue to [Compile and publish](/docs/governance/get-started/compile-and-publish) to build target-native plugins and cut a release.
</Aside>
