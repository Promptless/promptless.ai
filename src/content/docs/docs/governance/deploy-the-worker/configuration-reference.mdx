{/*
  Docs-driven product contract:
  - The generated Helm values are the supported operator interface.
  - The chart and worker support AWS S3, Google Cloud Storage, and Azure Blob Storage.
  - Durable and provider credentials are referenced from native secret managers,
    never copied into a values file.
  - The one-time install token is a bootstrap input, not a runtime credential.

The [installation workflow](/docs/governance/deploy-the-worker/deploy-the-analyzer-worker) generates the worker's Helm values. You should rarely set runtime environment variables yourself. The chart translates non-secret values into environment variables and resolves credentials through the cloud's native secret manager.

## Generated Helm values

The Terraform modules produce a `promptless-worker-values.yaml` file with these top-level groups:

| Group | Purpose |
| --- | --- |
| `controlPlane` | Hosted Promptless and outbound relay URLs, deployment identity, and configuration hash |
| `storage.postgres` | Provider-specific reference to the Secret that contains the Postgres connection |
| `storage.objectStore` | `aws_s3`, `gcp_gcs`, or `azure_blob`, plus the bucket or container and object prefix |
| `serviceAccount` | Kubernetes ServiceAccount name and workload-identity configuration |
| `resources` | Worker requests and limits based on the deployment size |
| `bootstrap` | Name of the one-time Kubernetes bootstrap Secret; remove this value after the first successful install |

The file contains resource identifiers and Secret references, not credentials. It is safe to review and commit.

## Required runtime variables

The chart owns these variables and supplies them to the worker. They are listed here for debugging and for operators who maintain their own chart wrapper.

| Variable | Description |
| --- | --- |
| `INSTRUCTION_HUB_CONTROL_PLANE_BASE_URL` | Base URL for bootstrap, configuration, heartbeats, and findings. |
| `INSTRUCTION_HUB_RELAY_BASE_URL` | Base URL for the worker's outbound encrypted-relay connection. |
| `INSTRUCTION_HUB_DEPLOYMENT_CREDENTIAL` | Chart-managed credential created when the bootstrap token is exchanged. |
| `INSTRUCTION_HUB_DEPLOYMENT_NAME` | Human-readable worker deployment name. |
| `INSTRUCTION_HUB_DEPLOYMENT_INSTANCE_ID` | Stable identifier for the worker deployment. |
| `INSTRUCTION_HUB_CONFIG_HASH` | Hash of the hosted and customer-managed configuration. |
| `INSTRUCTION_HUB_POSTGRES_SECRET_REF` | Cloud-native Secret reference for the Postgres connection. |
| `INSTRUCTION_HUB_OBJECT_STORE_PROVIDER` | Object store implementation: `aws_s3`, `gcp_gcs`, or `azure_blob`. |
| `INSTRUCTION_HUB_OBJECT_STORE_URI` | Bucket or container URI for raw and canonical trace objects. |
| `INSTRUCTION_HUB_TRACE_OBJECT_PREFIX` | Prefix used for worker-owned objects. Defaults to `trace-objects`. |

<Aside type="caution">
  `INSTRUCTION_HUB_DEPLOYMENT_CREDENTIAL` is Secret data. The chart reads it from `promptless-worker-identity`; do not put its plaintext value in Helm values or an environment manifest.
</Aside>

## Analysis variables

The `INSTRUCTION_HUB_ANALYSIS_*` variables turn on and configure the [Friction Analyzer](/docs/governance/findings-and-remediation/understand-findings). They are set together — the analyzer needs its model and repository configured to run.

| Variable                                        | Description                                                                           |
| ----------------------------------------------- | ------------------------------------------------------------------------------------- |
| `INSTRUCTION_HUB_ANALYSIS_ACTIVATION_AT`        | When analysis becomes active for this deployment.                                     |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_PROVIDER`       | The model provider: `openai`, `azure_openai`, or `aws_bedrock`.                       |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_AUTHENTICATION` | How the worker authenticates to the provider.                                         |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_BASE_URL`       | The provider's base URL.                                                              |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_NAME`           | The analysis model to use. Defaults to `gpt-5.6-sol`.                                 |
| `INSTRUCTION_HUB_ANALYSIS_MODEL_API_KEY_SECRET_REF` | Cloud-native Secret reference for the provider API key, when API-key authentication is used. |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_URL`       | The Instruction Hub repository the analyzer reads and remediates against.             |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_ID`        | The repository identifier.                                                            |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_FULL_NAME` | The repository's full `owner/name`.                                                   |
| `INSTRUCTION_HUB_ANALYSIS_REPOSITORY_TOKEN_SECRET_REF` | Cloud-native Secret reference for the repository-scoped remediation token. |
| `INSTRUCTION_HUB_ANALYSIS_QUIET_WINDOW_HOURS`   | How long a session stays quiet before it is eligible for analysis. Defaults to `0.5`. |
| `INSTRUCTION_HUB_ANALYSIS_MIRROR_ROOT`          | Local root for the analyzer's repository mirror.                                      |

<Aside type="caution">
  Secret references are safe to put in generated Helm values. The referenced API key and repository token are credentials; keep their plaintext values in your cloud secret manager.
</Aside>
