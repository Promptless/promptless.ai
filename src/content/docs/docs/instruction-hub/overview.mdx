Instruction Hub governs the instructions your coding agents actually run on — skills, agent definitions, `AGENTS.md` and `CLAUDE.md` files, MCP configuration, hooks, and commands. It reads the sessions those instructions produced, identifies where they caused friction, and proposes fixes as pull requests.

## Why this exists

Instruction assets are written once and then drift. A skill that was accurate when it shipped starts steering agents into dead ends after the code underneath it changes; a `CLAUDE.md` rule that solved one problem quietly causes another. Nobody has evidence about which instructions are helping and which are costing time and tokens, because the only record of what happened lives in scattered local session logs.

Instruction Hub closes that loop. It treats the sessions your agents already ran as evidence, finds the instructions behind repeated friction, and hands you a reviewable change instead of a hunch.

## The two halves

Instruction Hub runs across a trust boundary you control.

- **The worker** is deployed in your environment. It receives native session ledgers, stores them in your own S3 and Postgres, runs analysis, and holds every raw artifact.
- **Hosted Promptless** — reachable through the dashboard — issues install tokens, signs the enrollment policy your hosts read, and stores findings, evidence, and remediation records.

## What stays in your environment

Raw trace bodies, digests, prompts, tool activity, model and provider traffic, shell activity, repository contents, and credentials never leave your infrastructure. The worker keeps each of these in your own S3 and Postgres.

What reaches hosted Promptless is narrower: the finding record, its evidence occurrences, and a limited trace projection carrying identity, host attribution, lifecycle counters, and analysis status. See [Deploy the worker](/docs/instruction-hub/worker/deploy) to learn how the worker is isolated in your cluster.

## Supported hosts

Instruction Hub collects sessions from three coding agents — Claude Code, Claude Desktop, and Codex. See [Enroll your hosts](/docs/instruction-hub/enroll-hosts) for host-specific requirements.

## Get started

Owners start by seeing how it works, enrolling hosts, reviewing findings, and remediating; operators running the self-hosted worker go on to deploying, upgrading, and managing worker limits and budgets.
