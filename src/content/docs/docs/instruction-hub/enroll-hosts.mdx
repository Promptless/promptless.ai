Every machine running a Promptless-managed agent plugin carries its own credential. There is no shared enrollment secret, and any single host can be revoked without affecting the others.

<Aside type="note">
  Installing the Promptless-managed agent plugin on each host, and troubleshooting a failed enrollment, are not yet documented here.
</Aside>

## Supported hosts

Instruction Hub enrolls three coding agents:

- Claude Code
- Claude Desktop
- Codex

Claude Desktop is collected on a best-effort basis: a Claude Desktop host reports sessions only when its audit-store sources and an enrolled credential are both present.

## Approving a host

<Steps>
  1. **The plugin bootstrap starts enrollment.** It reads the worker's deployment identity and opens hosted Promptless with a loopback callback URL and the host metadata it displays for approval.

  2. **An organization member approves in the browser.** The approval page names the machine that is asking so the approver knows which host they are enrolling.

  3. **The bootstrap claims the credential.** Approval redirects to the local callback, and the bootstrap polls hosted Promptless for a one-time credential.

  4. **The plugin stores the credential locally.** It uses that credential for policy reads, trace uploads, and check-ins — periodic authenticated calls the plugin makes to the worker. On each check-in, the worker validates the credential and the host-reported policy version, rejects a stale version, and acknowledges acceptance. A separate policy read returns the current enrollment policy.
</Steps>

Once claimed, the host uses that credential for all three, and you can confirm the host from the dashboard.

Enrollment sessions are one-time and time-boxed. A pending session can be approved once, an approved session can be exchanged for exactly one credential, and a consumed session cannot mint another.

## What the worker trusts

The worker validates each credential against hosted Promptless before it returns policy or accepts a check-in or upload.

Authentication requires a concrete host target, so a credential minted for one host family or deployment cannot authenticate as another. The same validation supplies the host instance ID and label the worker uses to attribute traces.

## Revoking a host

Revoke a host from the dashboard.

The worker caches only active validation results, and only for as long as hosted Promptless says it may. It never caches a revocation or a failure, so the delay between revoking a host and the worker rejecting it is limited to that returned lifetime.

## Requiring a minimum host runtime version

The enrollment policy carries an optional version gate. When it is set, the worker checks the version each host reports before it accepts a check-in or upload:

- A SemVer value is treated as a minimum.
- A non-SemVer value, such as a release tag, requires an exact match.
- The worker rejects a missing or unsatisfied version and does not record it.

When the gate is omitted, the worker records whatever version the host reports. Set the minimum version in the enrollment policy from the dashboard when you need to force a fleet past a known-bad collector build — for example, requiring the release that fixes a collection regression before any host in the fleet can upload again. The host-introspection contract is versioned in lockstep with the worker, so plan a version gate alongside a worker upgrade; see [Upgrade the worker](/docs/instruction-hub/worker/upgrade).
