A finding is a claim about your instructions, backed by the sessions that produced it. Findings live at the organization level, so the same problem seen on three machines is one finding with three pieces of evidence rather than three separate reports.

- Evidence occurrences are append-only. Nothing already recorded is rewritten.
- Each occurrence carries the host it came from, the range of the digest it cites, and the Instruction Hub release installed at the time.

## Confidence

Findings start at low or high confidence. A low-confidence finding is promoted once accumulated evidence clearly establishes negative impact.

## Evidence and deduplication

An occurrence is unique by finding, installation, analyzer identity and version, source, session, source fingerprint, and digest range. Replaying the exact same evidence from the same host is idempotent and keeps the original host label.

A later trace revision or a newer analyzer version can record the same range again as a separate occurrence, which is how you see that a finding survived a change.

## Tracking findings as issues

Findings are projected into your Instruction Hub repository as GitHub issues.

- Promptless-managed body content carries each evidence occurrence and its investigation coordinates.
- Host attribution is deliberately excluded from issue bodies.
- Updates change managed content and labels without touching issue state or anything a human wrote.
