## How the workload runs

The chart supports exactly one replica and uses the `Recreate` strategy, so a rollout never runs two workers at once.

Both the worker and the migration hook run hardened by default:

- UID and GID 10001, never root
- Read-only root filesystem
- All Linux capabilities dropped
- The runtime-default seccomp profile

`/tmp` is the only writable application path provisioned by default. Enabling trace analysis also mounts an ephemeral writable volume at `/var/lib/instruction-hub` for repository mirrors and analysis workspaces.

## Health checks

| Endpoint   | Checks                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| `/healthz` | Process liveness only. No dependency checks.                                                                           |
| `/readyz`  | The local metadata repository, including the required Postgres schema and index contract, plus a usable cached policy. |

`/readyz` never calls hosted Promptless. A cached policy counts as usable until its signed expiry, and for at most five minutes after the worker cached it.

<Aside type="note">
  Set the readiness probe timeout above the worker's own internal limit so a slow local check surfaces as a probe failure rather than a timeout race.
</Aside>

## Network exposure

The service is `ClusterIP` by default. Set `gateway.enabled=true` to render an Ingress for customer-managed exposure.

The default gateway routes only `/healthz`, the two credential-protected host-enrollment endpoints, and the trace batch endpoint. It deliberately does not expose broad host-enrollment prefixes.

## Cloud identity

Set `serviceAccount.annotations` when the worker needs cloud identity for your storage — for example, an AWS IRSA role that can write to the configured S3 bucket.
