Source control is where Promptless watches for changes and publishes documentation. A provider connection can activate triggers, supply code context, and open documentation pull requests, and each job needs different access. This page covers what each connection does, the access it grants, and how to keep that access minimal.

## What each provider connects

| Provider                                                                     | Used for                                            |
| ---------------------------------------------------------------------------- | --------------------------------------------------- |
| [GitHub](/docs/for-docs/reference/integrations/github)                       | Triggers, context, and publishing                   |
| [GitHub Enterprise](/docs/for-docs/reference/integrations/github-enterprise) | Triggers, context, and publishing (Server or Cloud) |
| [GitLab](/docs/for-docs/reference/integrations/gitlab)                       | Triggers, context, and publishing                   |

Promptless opens pull requests on GitHub repositories and merge requests on GitLab projects. For publishing to GitLab, see [GitLab projects (docs as code)](/docs/for-docs/connect/doc-locations/gitlab-projects).

Promptless also has a [read-only GitHub app](/docs/for-docs/reference/integrations/github-read-only) that grants read access and webhooks only and publishes to public repositories through a fork.

## How each connection authenticates

Each provider limits Promptless to the repositories and actions you authorize.

### GitHub

Promptless connects through its official GitHub App, which authenticates with JWTs from the app installation. During installation, choose the repositories to grant, typically your source code and, if your docs live in GitHub, your documentation repo. The app gets read and write access to them, and you or Promptless can revoke it at any time.

To change access later, open your GitHub organization settings, go to **Third-party Access → GitHub Apps**, find **Promptless**, and click **Configure**. Switch between **All repositories** and **Only select repositories**, and add or remove repositories. The **Manage repository access** button on the doc collection setup screen links to these settings. If you can't grant write access, install the [GitHub (read-only) app](/docs/for-docs/reference/integrations/github-read-only).

### GitHub Enterprise

GitHub Enterprise Server and Cloud users configure a custom GitHub App with an explicit permission set. Promptless requires these repository permissions:

- **Pull requests: read and write**, to read pull request content, create documentation pull requests, and comment for feedback.
- **Contents: read and write**, to read repository files and create or update documentation files.
- **Commit statuses: read only**, to understand the state of pull requests and commits.
- **Checks: read only**, to detect and fix failed CI checks on documentation pull requests.
- **Issues: read only**, to read repositories and pull requests during research and receive pull request comments.
- **Webhooks: read and write**, to manage webhook configuration and receive repository events.

<Aside type="note">
  If your GitHub Enterprise instance is behind a firewall or IP restrictions, allow Promptless's IP addresses so webhooks and API calls can reach it. The [GitHub Enterprise setup guide](/docs/for-docs/reference/integrations/github-enterprise) lists them. GitHub.com organizations can enforce IP allow lists too. See [Organization IP allow lists](/docs/for-docs/reference/integrations/github#organization-ip-allow-lists).
</Aside>

### GitLab

GitLab connects with a group access token or personal access token that has the read-write `api` scope. Publishing uses the same token. For a team rollout, use a group access token: your organization owns it, so it keeps working when people leave. A personal access token works only while its owner keeps access.

Connecting requires only the `api` scope. Promptless checks access per project, so a token with a low group role still connects. Promptless installs merge-request webhooks on the projects where the token has the **Maintainer** role. Projects below Maintainer stay available for context and publishing. To get triggers from one, a project Maintainer or Owner adds a webhook in GitLab. Promptless writes only to the projects you configure as doc collections.

For a hard limit, scope a group access token to a group or subgroup that holds only your documentation projects. See [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations).

## Scope publishing access to your docs

Publishing needs write access to your documentation repository: the GitHub App on GitHub, or the connected access token on GitLab. Use **path scope** to limit where those writes land.

Specify directories during doc collection setup, and Promptless modifies only files that match one of those paths or sit inside them. With no directories set, it can modify files anywhere in the repo. Entries can be directories or files: `docs/` allows any file under that directory, and `CHANGELOG.md` allows only that file. Promptless rejects a suggestion that changes files outside the scope, with an error listing them. Path scope helps in monorepos where docs live beside source code.

For full doc collection setup, see [GitHub repos (docs as code)](/docs/for-docs/connect/doc-locations/github-repos) and [GitLab projects (docs as code)](/docs/for-docs/connect/doc-locations/gitlab-projects).

## Keep access least-privilege

To keep each connection to the access its job needs:

- **Select only the repositories Promptless needs.** On GitHub, choose **Only select repositories** and manage the list from your GitHub organization settings.
- **Use read-only access where you don't publish.** For a public open-source repository, the [GitHub (read-only) app](/docs/for-docs/reference/integrations/github-read-only) opens documentation pull requests from a fork, without write access to your repo. For GitLab, scope a group access token to a group or subgroup that holds only your documentation projects, as described in [GitLab](#gitlab).
- **Revoke access at any time.** You or Promptless can revoke the GitHub App connection. You can rotate or remove a GitLab access token in GitLab.

For how source-control access fits Promptless's broader security posture, see [Network architecture](/docs/for-docs/security/network-architecture) and [Data handling and classification](/docs/for-docs/security/data-handling-and-classification).
