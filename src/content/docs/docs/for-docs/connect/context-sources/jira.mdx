## Overview

Connect Jira as a context source so Promptless documents what a feature is meant to do. Your team records those requirements and acceptance criteria on its Jira issues. Promptless reads Jira in two ways:

- When a GitHub PR or another trigger references a Jira issue, such as `PROJ-123`, Promptless reads that issue. This starts as soon as Jira is connected.
- Promptless runs JQL (Jira Query Language) searches for related issues, epics, and dependencies.

From each issue, Promptless reads:

- Summary and description
- Status, type, priority, and resolution
- Labels, components, and affected and fix versions
- Parent, subtasks, and linked issues
- Comments
- Organization-defined custom fields, such as a `Documentation` field

Promptless reads only what the connected Jira account can see. It queries Jira in real time when a documentation task needs it, and doesn't store your Jira data. Reading context never creates, updates, or deletes an issue.

<Aside type="note">
  Jira is also a trigger source. Through the [Jira trigger](/docs/for-docs/connect/triggers/jira), Promptless starts work from an issue and replies on it. On request, Promptless also creates Jira issues. See [Create a Jira issue on request](/docs/for-docs/reference/integrations/atlassian#create-a-jira-issue-on-request). Both are write capabilities, separate from the read-only context source.
</Aside>

### Example

A developer merges a GitHub PR whose description references `PROJ-412`, the Jira issue for a new bulk-import feature. The issue records the business requirements: the supported file formats and a 10,000-row import cap. It also records that imports run asynchronously and send an email notification on completion.

When Promptless picks up the merged PR, it reads `PROJ-412` and runs a JQL search for related issues in the same epic. Its suggestion carries the acceptance criteria into the docs: the supported formats, the row limit, and the asynchronous import with its email notification. The docs then describe what the feature is meant to do, beyond what the diff shows.

## Limit Promptless to specific projects

Promptless can read every project the connected Jira account can see. To keep it to the projects that hold relevant work, scope the Jira context source:

1. On the **Context sources** tab of the [Configuration page](https://app.gopromptless.ai/configuration), expand the Jira source. If it isn't listed, select **Add a context source**, and then select **Jira**.
2. In **Which Jira projects should Promptless read?**, add the key of each project.
3. Select **Save changes**. For a new source, select **Add context source**.

In YAML, the scope is the `project_keys` list on a `jira` entry:

```yaml
context_sources:
  jira:
    source_type: jira
    project_keys:
      - DOCS
      - PLATFORM
      - ENG
```

An entry with no project keys, or no entry, gives Promptless every project the account can see. For every context source field, see the [Configuration Reference](/docs/for-docs/reference/configuration-reference#context-sources).
