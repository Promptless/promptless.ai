Coda integration provides **read-only** access to your team's Coda docs for documentation automation. When Coda is configured as a context source, Promptless searches Coda and reads page content when creating suggestions. It never modifies your Coda content.

## How it works as a context source

When Coda is enabled as a context source:

- **Doc Search**: Promptless finds a Coda doc by its name when creating documentation suggestions. Search matches doc names, not the body text of pages.
- **Page Reading**: Promptless reads the page content of a matched doc and pulls its product specs, internal notes, and reference material into new documentation.

<Aside type="tip">
  Because Doc Search matches on the name, give each Coda doc a title that names the feature or subject it covers. If a suggestion misses a Coda doc you expected, check that the doc's title matches the feature name.
</Aside>

<Aside type="note">
  Promptless reads Coda pages as plain text, so it captures the words but not link targets, inline formatting, or tables.
</Aside>

## Example

A developer merges a GitHub PR that adds a configurable batch size to your data export pipeline. The feature was documented in a Coda doc named "Bulk Export Design." That doc holds the official feature name ("Bulk Export Batching"), the default and maximum batch sizes, and the reasoning behind the cap.

When Promptless picks up the merged PR, it searches your Coda docs by name and finds "Bulk Export Design." It reads that doc's pages and carries the agreed details into the suggestion. That means the same feature name, the default batch size of 500, the 2,000-row maximum, and the rationale your team recorded. The docs PR then matches the spec your product and engineering teams wrote.

## Configuration

Coda authenticates with a personal API token that you generate in Coda and paste into Promptless. To connect Coda:

1. In Coda, generate a personal API token under **Account Settings > API Settings** (see [Coda's API documentation](https://coda.io/developers/apis/v1)). The token inherits the Coda access of the account that created it, and you can restrict it to specific docs. We recommend generating it from a dedicated service account so Promptless gets least-privilege access. A dedicated service account is a Coda account you control and use for integrations like this one. Whichever account you use must have access to the Coda docs you want Promptless to read. If you use a service account, add it as a collaborator on those docs, or on the workspace, so Promptless can read them.
2. Go to the [Integrations page](https://app.gopromptless.ai/integrations) in your Promptless dashboard.
3. Click **Connect** on the Coda integration card.
4. Paste the token and click **Connect**. Promptless validates the token when you connect.

The Coda card on the [Integrations page](https://app.gopromptless.ai/integrations) shows the connection status. Use it to confirm the connection works and to spot a later problem, such as a token revoked in Coda. See [Connection health & troubleshooting](/docs/for-docs/connect/connection-health).

By default, Promptless reads every Coda doc the connected token can access. To narrow that, add `doc_ids` to the `coda` context source in your `promptless.yaml` and list only the docs Promptless should read. See the [Configuration Reference](/docs/for-docs/reference/configuration-reference#context-sources) for the full schema.

## Data privacy

Promptless queries Coda in real time and doesn't store any of your Coda content. All searches happen on demand when documentation updates are needed. Promptless caches results briefly to improve performance and refreshes them when your Coda content changes.

Promptless only reads from Coda. It never creates, updates, or deletes Coda content.
