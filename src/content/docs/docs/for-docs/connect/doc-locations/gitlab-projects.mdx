## Overview

In Promptless, a doc collection is a place where your documentation lives. When your docs are in GitLab, on gitlab.com or self-hosted, the doc collection is a GitLab project. You can limit Promptless to specific paths in that project.

To set this up, connect the GitLab group that holds the project, then select the project on the Configuration page.

You can also ask Promptless in Slack or Microsoft Teams to add the doc collection for you. For example, "@Promptless add my acme/docs GitLab project as a doc collection." See [Ask Promptless to update your configuration](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).

## Before you start

- An admin role in your Promptless organization.
- A [connected GitLab group](#connect-gitlab) that holds your docs project.

## Add a GitLab doc collection

<Steps>
  1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), select **Add doc collection**.

  2. Under **Which repository should Promptless document?**, select your GitLab project. To list only your GitLab projects, search for `gitlab`.

  3. Set the docs framework, published URL, and [path scope](/docs/for-docs/connect/doc-locations/github-repos#path-scope-documentation-directories). These settings work the same as for a [GitHub doc collection](/docs/for-docs/connect/doc-locations/github-repos#configuration).

  4. Select **Add collection**.
</Steps>

If the picker doesn't list your project, [connect the group](#connect-gitlab) that holds it.

### Configure a GitLab doc collection in YAML

Set `platform: gitlab` and use the project's full path as the key. For a self-hosted project, also set `host`:

```yaml
doc_collections:
  acme/docs:                              # gitlab.com project
    platform: gitlab
    docs_framework: docusaurus
  acme/platform/developer-docs:           # self-hosted, nested namespace
    platform: gitlab
    host: gitlab.acme.com
    docs_framework: mkdocs
```

See the [configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for every field a doc collection accepts.

## Automatic merge request creation

Onboarding turns on automatic PR creation (`publishing.auto_create_pr`), so Promptless opens a merge request for each suggestion. Keep it on. Reviewers then get suggestions in GitLab with their other merge requests.

With it off, suggestions stay in the Promptless dashboard until someone opens a merge request for each one by hand.

Change the setting in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies).

<Aside type="caution" title="GitLab auto-merge does not wait for pipelines">
  With auto-merge (`publishing.auto_merge`) on, Promptless attempts one squash merge when it opens the merge request and doesn't retry. If the merge fails, the merge request stays open for you to merge.
</Aside>

If your project has merge request templates in `.gitlab/merge_request_templates/`, Promptless writes merge request descriptions to them. Add `[Open in Promptless]({suggestion_url})` to a template to place the link to the suggestion yourself. See [Use your own PR template](/docs/for-docs/get-the-most-out/use-your-own-pr-template).

## Pipeline failures

If a pipeline fails on a Promptless merge request, add a comment to the merge request. Mention `@promptless` in the comment and paste the output of the failed job. Promptless reads the output and pushes a fix to the merge request branch.
