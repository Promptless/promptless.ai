## Overview

A GitLab doc collection is the GitLab project where your documentation lives and where Promptless opens merge requests with documentation updates. Your docs platform publishes from that project, so your documentation stays under version control alongside the rest of your work. GitLab doc collections work on both gitlab.com and self-hosted GitLab.

Promptless reaches the project using your connected GitLab group access token, which needs the `api` scope. When your documentation needs an update, Promptless pushes a branch directly to your docs project and opens a merge request. Your documentation platform then syncs the changes from GitLab.

## Before you start

- An admin role in your Promptless organization, to connect GitLab and create doc collections.
- A connected GitLab group whose access token reaches your docs project. The connected group access token must have the write-capable `api` scope so Promptless can push a branch and open a merge request. To connect a group, see [Connect GitLab](#connect-gitlab).

## Add a GitLab doc collection

<Steps>
  1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), select **Add doc collection**.

  2. Under **Which repository should Promptless document?**, select your GitLab project. To list only your GitLab projects, search for `gitlab`.

  3. Set the docs framework, published URL, and the directories Promptless can modify. These settings work the same as for a [GitHub doc collection](/docs/for-docs/connect/doc-locations/github-repos#configuration).

  4. Select **Add collection**.
</Steps>

The picker lists every connected GitLab project, on gitlab.com and self-hosted GitLab alike, by its full path including every namespace segment, such as `acme/platform/developer-docs`. Promptless sets the platform and the **GitLab host** from the connection that reaches the project. **GitLab host** is blank for gitlab.com, and holds the bare hostname, such as `gitlab.acme.com`, for self-hosted GitLab.

If the picker lists none of your GitLab projects, GitLab isn't connected yet. If it lists other projects but not yours, the connected group token's project inventory doesn't include that project. To connect a group, see [Connect GitLab](#connect-gitlab). To scope the token to the right group, see [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations).

### Configure a GitLab doc collection in YAML

In YAML, a GitLab collection sets `platform: gitlab` and is keyed by the project's full path, including every namespace segment. A self-hosted project also sets `host`:

```yaml
doc_collections:
  acme/docs:                              # gitlab.com project
    platform: gitlab
    docs_framework: docusaurus
  acme/platform/developer-docs:           # self-hosted, nested namespace
    platform: gitlab
    host: gitlab.acme.com
    docs_framework: mkdocs
```

See the [configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for every field a doc collection accepts.

## Automatic merge request creation

When automatic PR creation (`auto_create_pr`) is on in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), Promptless opens a merge request in your documentation project with the suggested changes. Promptless tracks merge request status the same way it tracks GitHub pull request status. GitLab has no draft flag at creation time, so Promptless marks a draft merge request with a `Draft:` title prefix.

When Promptless opens or updates a merge request, it posts the suggestion's citations as diff-positioned discussion threads. Reviewers see each source at the line it supports. A citation that can't be anchored to the diff posts as an unanchored merge request thread that names the file and line.

Shortly after it opens the merge request, Promptless resolves each citation discussion. The evidence stays on the diff, and projects that require all discussions resolved can still merge. Promptless leaves a discussion alone after you reply to it or reopen it. This behavior applies to every organization, with no setting to configure.

To have Promptless merge its documentation changes automatically, turn on automatic merging (`auto_merge`) in your publishing policies. On GitLab, Promptless attempts an immediate squash merge as soon as it opens the merge request. See [Policies](/docs/for-docs/reference/configuration-reference#policies) for how publishing rules resolve.

<Aside type="caution" title="GitLab auto-merge does not wait for pipelines">
  On GitLab, Promptless attempts the merge once, right when it opens the merge request. It doesn't use GitLab's "merge when pipeline succeeds", doesn't wait for a pipeline, and doesn't retry later. If the merge request can't merge at that moment, GitLab reports a failure. Promptless then leaves the merge request open for you to merge manually. For example, a required pipeline hasn't passed, approvals are pending, or the branch has conflicts.
</Aside>

Merge request bodies carry the same generated extras as GitHub pull requests. These are the "Open in Promptless" link, the trigger events that prompted the update, and a tip. To omit them, set `publishing.suppress_pr_description_extras: true` in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies). The body then contains only the suggestion's own description. See [Trigger events in pull request descriptions](/docs/for-docs/connect/doc-locations/github-repos#trigger-events-in-pull-request-descriptions) for what this content covers.

## Path scope (documentation directories)

Path scope sets which files Promptless can modify in your documentation project, the same way it does for GitHub repositories. Set it with the directories you specify during doc collection setup:

- With no directories, Promptless can create and modify files anywhere in the project.
- With directories, Promptless can modify only files that match one of those paths exactly or sit inside one of those directories.

A scope entry can be a directory or a single file. An entry such as `CHANGELOG.md` allows only that file, and `docs/` allows any file under that directory. Promptless rejects a suggestion that changes files outside the configured scope, with an error that lists those files. For examples, see [Path scope](/docs/for-docs/connect/doc-locations/github-repos#path-scope-documentation-directories).
