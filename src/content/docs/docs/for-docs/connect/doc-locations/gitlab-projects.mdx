Store your documentation in a GitLab project, on gitlab.com or self-hosted GitLab, and Promptless publishes updates there through merge requests.

<Aside type="note">
  **Prerequisite**: [Connect GitLab](/docs/for-docs/reference/integrations/gitlab) on the Integrations page first. The token needs the `api` scope so Promptless can push a branch and open a merge request. If the repository picker is missing the project you want, check that GitLab is connected and that the token can reach the project.
</Aside>

## How it works

1. Your documentation files live in a GitLab project.
2. Promptless reaches the project with your connected GitLab token.
3. When documentation needs to change, Promptless pushes a branch to the project and opens a merge request.
4. Your documentation platform syncs changes from GitLab.

## Configuration

Add a GitLab doc collection on the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration).

Under **Which repository should Promptless document?**, pick a connected GitHub or GitLab repository or type its path. Type the project's full path, including every namespace segment, such as `acme/platform/developer-docs` for a project in a nested subgroup. The picker lists connected GitLab projects from gitlab.com and self-hosted instances alike.

Promptless sets the platform from the connection that reaches the repository and shows it under **Where this repo lives**. For GitLab, the text reads "GitLab" followed by "Promptless opens merge requests on this project directly."

In the **GitLab host** field, enter a self-hosted hostname such as `gitlab.acme.com`, without `https://` or a path. Leave it blank for gitlab.com.

The remaining fields match a GitHub doc collection: docs framework, published URL, and the directories Promptless can modify.

In YAML, a GitLab collection sets `platform: gitlab` and uses the project's full path as its key:

```yaml
doc_collections:
  acme/docs:                              # gitlab.com project
    platform: gitlab
    docs_framework: docusaurus
  acme/platform/developer-docs:           # self-hosted, nested namespace
    platform: gitlab
    host: gitlab.acme.com
    docs_framework: mkdocs
```

See the [configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for every field a doc collection accepts.

## Automatic merge request creation

When automatic PR creation (`auto_create_pr`) is enabled in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), Promptless opens a merge request in your documentation project with the suggested changes. Promptless tracks its status the same way as a GitHub pull request. GitLab has no draft flag at creation time, so Promptless marks a draft merge request with a `Draft:` title prefix.

Promptless posts the suggestion's citations as discussion threads on the merge request diff, at the lines they support. A citation that can't be anchored to the diff becomes an unanchored thread that names the file and line.

Promptless resolves each citation discussion shortly after opening the merge request, so projects that require resolved discussions can still merge. If you reply to a discussion or reopen one, Promptless leaves it alone. No setting is needed.

With automatic merging (`auto_merge`) enabled in your publishing policies, Promptless attempts a squash merge as soon as it opens the merge request. See [Policies](/docs/for-docs/reference/configuration-reference#policies) for how publishing rules resolve.

<Aside type="caution" title="GitLab auto-merge does not wait for pipelines">
  Promptless attempts the merge once, right away. It doesn't use GitLab's "merge when pipeline succeeds" or retry later. The merge request might not be ready, for example because a required pipeline hasn't passed, approvals are pending, or there are conflicts. GitLab then reports a failure, and Promptless leaves the merge request open for you to merge.
</Aside>

Merge request bodies include the same extras as GitHub pull requests: the "Open in Promptless" link, the trigger events behind the update, and a tip. To omit them, set `publishing.suppress_pr_description_extras: true` in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies). See [Trigger events in pull request descriptions](/docs/for-docs/connect/doc-locations/github-repos#trigger-events-in-pull-request-descriptions).

## Path scope (documentation directories)

Path scope limits which files Promptless can modify in your documentation project, the same as for GitHub repositories:

- **All files allowed (default):** With no directories specified, Promptless can create and modify files anywhere in the project.
- **Scoped to specific paths:** Promptless modifies only files that match a listed path or sit inside a listed directory.

Entries can be directories or files: `docs/` allows any file under that directory, and `CHANGELOG.md` allows only that file. Promptless rejects a suggestion that changes files outside the scope, with an error listing them.
