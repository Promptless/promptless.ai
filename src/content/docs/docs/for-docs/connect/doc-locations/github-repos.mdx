## Overview

A GitHub doc collection is the GitHub repository where your documentation lives and where Promptless opens documentation pull requests. Your docs platform publishes from that repository, so your documentation stays under version control alongside your code.

The Promptless GitHub App has write access to your docs repository. When your documentation needs an update, Promptless opens a pull request there. Your documentation platform then syncs the changes from GitHub.

Each repository is its own doc collection. Promptless can publish to several doc collections from the same triggers and context sources. To give one collection its own publishing or notification settings, scope a [policy rule](/docs/for-docs/reference/configuration-reference#rule-matching) to it with `doc_collection`.

<Aside type="note">
  Before you create a GitHub doc collection, [connect GitHub](#connect-github). The repository picker lists only the repositories that your GitHub connection can reach.
</Aside>

## Supported platforms

Promptless publishes to any docs platform or framework whose content lives in a repository. The **Docs framework** setting recognizes these platforms:

| Platform            | `docs_framework` value |
| ------------------- | ---------------------- |
| Docusaurus          | `docusaurus`           |
| Fern                | `fern`                 |
| GitBook             | `gitbook`              |
| Hugo                | `hugo`                 |
| mdBook              | `mdbook`               |
| Mintlify            | `mintlify`             |
| MkDocs              | `mkdocs`               |
| ReadMe (Refactored) | `readme`               |
| Sphinx              | `sphinx`               |
| Starlight (Astro)   | `starlight`            |

Promptless also publishes to Ghost, Nextra, Vocs, and custom platforms, as long as the content is in a repository.

To publish through a Git host other than GitHub or GitLab, contact [help@gopromptless.ai](mailto\:help@gopromptless.ai). The Promptless team can also help you choose a new docs platform and set it up. See [Choose a docs platform](/docs/for-docs/migrate/choose-a-platform).

## Configuration

After setting up the GitHub integration, add a doc collection in the dashboard:

1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), select **Add doc collection**.
2. Under **Which repository should Promptless document?**, pick your docs repository.
3. If you want, set the **Docs framework** and **Where are these docs published?** fields. To limit which folders Promptless can modify, open **More filters (optional)** and add them under **Only watch these folders**.
4. Select **Add collection**.

In YAML mode, doc collections are defined in the `doc_collections` section of `promptless.yaml`, keyed by repository name:

```yaml
doc_collections:
  acme/documentation:
    docs_framework: docusaurus
    docs_root_url: https://docs.acme.com
    filter:
      - docs/
```

Triggers that start documentation updates live in the separate `triggers` section. See the [configuration reference](/docs/for-docs/reference/configuration-reference) for the complete schema.

Each doc collection takes these settings:

| Dashboard field                 | YAML field                      | What it sets                                                                                                    |
| ------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Repository                      | The key under `doc_collections` | The repository Promptless publishes to, as `owner/repo`.                                                        |
| GitHub Enterprise host          | `host`                          | Your GitHub Enterprise hostname, such as `github.acme.com`. Applies only to GitHub Enterprise.                  |
| Docs framework                  | `docs_framework`                | The framework your site builds with. See [Supported platforms](#supported-platforms).                           |
| *Framework* config file         | `config_file_path`              | The path to your framework's config file, such as `docusaurus.config.js`, when it isn't at the repository root. |
| Where are these docs published? | `docs_root_url`                 | Your public documentation site URL.                                                                             |
| Only watch these folders        | `filter`                        | The directories and files Promptless can modify. See [Path scope](#path-scope-documentation-directories).       |
| Default branch                  | `default_branch`                | The branch documentation PRs target. Without it, Promptless targets the repository's default branch.            |
| Vale config path                | `vale_config_path`              | Turns on Vale linting with the config at this path.                                                             |
| Doc Detective config path       | `doc_detective.config_path`     | Turns on [Doc Detective](/docs/for-docs/audit/doc-detective) testing with the config at this path.              |

Promptless sets the platform from the integration that reaches the repository. In YAML, `platform` defaults to `github`. See the [configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for the other platform values.

### Edit doc collection settings

You can change every setting in the table from the dashboard:

  2. Change the settings.

  3. Select **Save changes**.

## Path scope (documentation directories)

Path scope sets which files Promptless can create and modify in your documentation repository. Set it with **Only watch these folders** in the dashboard or `filter` in YAML. With no entries, Promptless can change any file in the repository. With entries, a file must match an entry exactly or sit inside an entry's directory.

Each entry is a directory or a single file:

| Scope entry    | Promptless can modify                                                        | Promptless can't modify                     |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------- |
| None           | Any file in the repository                                                   | Nothing                                     |
| `docs/guides`  | `docs/guides/getting-started.md` and `docs/guides/advanced/configuration.md` | `README.md` and `src/components/Button.tsx` |
| `CHANGELOG.md` | `CHANGELOG.md`                                                               | Every other file                            |

Promptless rejects a suggestion that changes files outside the scope, with an error that lists those files. Path scope keeps changes inside your documentation area, which matters in a monorepo where docs live alongside source code.

## Pull request publishing

These behaviors apply to the documentation pull requests Promptless opens. Set them in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies):

| Behavior                 | What Promptless does                                                                                                             | How to change it                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Automatic PR creation    | Opens a pull request in your documentation repository for each suggestion.                                                       | Set `publishing.auto_create_pr: true`.                                   |
| Code PR comment          | For GitHub PR triggers, links the documentation PR in a comment on the original code PR.                                         | Set `publishing.suppress_source_pr_comments: true` to stop the comments. |
| Auto-merge               | Merges the documentation PRs Promptless opens automatically.                                                                     | Set `publishing.auto_merge: true` along with `auto_create_pr`.           |
| PR description extras    | Adds an "Open in Promptless" link, the [trigger events](#trigger-events-in-pull-request-descriptions), and a tip to the PR body. | Set `publishing.suppress_pr_description_extras: true` to omit them.      |
| CI check and build fixes | Watches the PR for failed checks and build problems, and pushes fixes to the PR branch.                                          | Always on. See [CI check and build fixes](#ci-check-and-build-fixes).    |

With auto-merge on, a documentation PR from a [commit trigger](/docs/for-docs/connect/triggers/github-commits) merges as soon as Promptless creates it. A documentation PR for an open code PR merges after the code PR merges. Auto-merge skips a documentation PR whose base branch is protected, or whose repository uses the read-only GitHub app. Merge those PRs yourself.

### CI check and build fixes

Promptless watches each documentation PR it opens for quality problems. These include failed CI checks, linting errors, Vale rule warnings, and broken links or build problems that your documentation host reports. When one occurs, Promptless analyzes it and pushes a fix to the PR branch.

The Promptless GitHub App needs no extra setup for this. A custom [GitHub Enterprise](/docs/for-docs/reference/integrations/github-enterprise) app needs the **Checks** read permission and a subscription to the **Check suite** webhook event. Promptless learns about CI failures only through check suite events.

### Read-only integrations (public repositories)

To publish to a public repository without granting write access, back its doc collection with the [GitHub (read-only)](#connect-the-read-only-app) integration. Promptless then creates its own fork and opens a pull request from the fork into your upstream base branch. Private repositories need the [standard GitHub App](#connect-github). See [How publishing works](/docs/for-docs/reference/integrations/github-read-only#how-publishing-works) for the fork flow.

## Trigger events in pull request descriptions

Each documentation PR description lists the trigger events that led to its changes, so reviewers can trace an update back to where it started. Each entry links to the original source, such as a Slack thread, GitHub PR, or support ticket, and briefly describes what prompted the update.

For Slack triggers, the link label names where the message came from, followed by a snippet of the message:

| Message source | Example link label                                                |
| -------------- | ----------------------------------------------------------------- |
| Public channel | "Message in Slack channel #docs: please update the API guide"     |
| Direct message | "Private Slack DM with Jane Doe: can we add an example here"      |
| Group message  | "Private Slack group message: the onboarding flow needs updating" |

Slack shows an error page to a reviewer who opens a link to a private conversation they're not in. The "Private Slack DM" and "Private Slack group message" labels tell reviewers the link is restricted. For these messages, Promptless adds a second link to the suggestion's Triggers & Analysis tab in the dashboard. Anyone with dashboard access can read the full message there, whatever their Slack permissions.

<Aside type="tip">
  You can omit this generated content from the PR body: the "Open in Promptless" link, the trigger events section, and the tip. Set `publishing.suppress_pr_description_extras: true` in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), and the body contains only the suggestion's own description.
</Aside>

## Frequently asked questions

When the repository picker can't find a repository, it shows "No connected repository matches that." These are the usual causes:

| Problem                                            | Cause                                                | Fix                                                                                                                                                      |
| -------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The picker lists none of your GitHub repositories. | GitHub isn't connected.                              | [Connect GitHub](#connect-github). Then return to the doc collection.                                                                                    |
| One repository is missing from the picker.         | The Promptless GitHub App doesn't have access to it. | Add the repository to the app's access in GitHub. See [Manage repository access](/docs/for-docs/reference/integrations/github#manage-repository-access). |
