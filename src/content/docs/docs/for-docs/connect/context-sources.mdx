Context sources are integrations that give Promptless read-only access to the tools where your team keeps product knowledge. These include issue trackers, wikis, and shared documents. A code change shows what changed. The issue, spec, or design doc behind it often explains why, and sets the names and limits the docs should use. Promptless reads that material while it drafts a documentation suggestion.

Context sources are optional. Without them, Promptless still creates suggestions from the triggering change and your existing docs.

<Aside type="note">
  Context sources are one-way. Promptless reads from these services and never writes to them through a context source. Your Jira issues, Linear issues, Confluence pages, and other content stay unchanged.
</Aside>

## Use cases

Each context source answers a question the code change alone can't:

| When the answer lives in…                                                                                       | Connect                                                                                                                                                                              | Promptless then                                                                                                       |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| An issue that records the requirements, such as a 10,000-row import cap or a plan restriction                   | [Jira](/docs/for-docs/connect/context-sources/jira) or [Linear](/docs/for-docs/connect/context-sources/linear)                                                                       | Reads the issue the pull request references, finds related issues, and carries the requirements into the suggestion. |
| A wiki page of team conventions, such as the pagination parameter names every API endpoint uses                | [Confluence](/docs/for-docs/connect/context-sources/confluence)                                                                                                                      | Finds the page and documents the new feature with the same conventions.                                               |
| A spec or PRD that settles a feature's official name, limits, and rationale, such as a "Rate Limiting v2" doc | [Notion](/docs/for-docs/connect/context-sources/notion), [Google Drive](/docs/for-docs/connect/context-sources/google-drive), or [Slite](/docs/for-docs/connect/context-sources/slite) | Reads the spec the pull request links to, or finds it by search, and reuses its exact names, numbers, and reasoning.  |

Each context source page walks through a full example.

## How context sources work

When a trigger starts documentation work, Promptless reads the triggering change and any issue, page, or file it links to in a connected source. It also searches your connected sources for related material, then drafts the suggestion with what it finds.

## Configure context sources

Connect each source on the [Integrations page](https://app.gopromptless.ai/integrations). Promptless can read a source as soon as it's connected, up to everything the connected account can reach.

To narrow a source to specific projects, spaces, teams, databases, drives, or folders, scope it on the **Context sources** tab of the [Configuration page](https://app.gopromptless.ai/configuration). The tab edits the `context_sources` section of your `promptless.yaml` file. A source with no scope, or no entry at all, stays fully readable. Each context source page shows how to scope that source, and the [Configuration Reference](/docs/for-docs/reference/configuration-reference#context-sources) lists every field.

## Data privacy and security

Context sources follow the same data handling as Promptless's other integrations. See [Data handling and classification](/docs/for-docs/security/data-handling-and-classification).

<details>
  <summary>Real-time queries only</summary>

  Promptless doesn't store your organization's data from context sources. It queries each source's API when a documentation task needs it, and reads only the information that task requires. Some sources cache results briefly during a documentation session, then discard them.
</details>

<details>
  <summary>Secure authentication</summary>

  Context sources connect through OAuth 2.0, except Slite, which connects with an API key. Every connection:

  - Reads with the permissions of the account that authorized it
  - Encrypts data in transit with TLS 1.2 or higher
  - Uses token-based access that you can revoke at any time
</details>
