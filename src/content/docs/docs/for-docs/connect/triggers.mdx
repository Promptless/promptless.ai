Triggers are events that initiate automated documentation updates in Promptless. When a trigger event occurs, Promptless analyzes the context and determines if documentation updates are needed.

## How triggers work

When a trigger event occurs:

1. **Event Detection**: Promptless receives notification of the event (PR opened, message posted, etc.)
2. **Context Analysis**: The system analyzes the event content, including code changes, conversations, or support interactions
3. **Relevance Assessment**: Promptless determines if the event requires documentation updates
4. **Suggestion Creation**: If relevant, Promptless creates documentation suggestions based on the trigger content and connected context sources

## Configure triggers

Triggers are configured in your organization's [Configuration page](https://app.gopromptless.ai/configuration) using the `triggers` section of your `promptless.yaml` file. For each trigger, you can:

- Specify which repositories or channels to monitor
- Configure trigger-specific settings (e.g., directory filters, branch targeting)
- Set up publishing behavior through policy rules

See the [Configuration Reference](/docs/for-docs/reference/configuration-reference) for the complete YAML schema.

<Aside type="note">
  Need a trigger type that isn't currently supported? Contact us at [help@gopromptless.ai](mailto\:help@gopromptless.ai) - we regularly add new trigger types based on user feedback.
</Aside>

## Connect a provider before you add its triggers

To add, rename, or modify a provider-backed trigger, first connect its provider on the [Integrations page](https://app.gopromptless.ai/integrations). Only organization administrators can connect integrations, so if you're not an admin, ask one.

If you disconnect a provider, its triggers stay in your `promptless.yaml` and show as inactive until you reconnect it. You can remove an inactive trigger at any time. To edit or rename one, reconnect its provider first.

Connections are organization-wide, so disconnecting a provider affects every team's triggers for it.

For how these states appear in the editor, see [Provider connection and trigger availability](/docs/for-docs/reference/configuration-reference#provider-connection-and-trigger-availability). To check a connection, see [Connection health](/docs/for-docs/connect/connection-health).

## Automatic PR creation

When automatic PR creation is enabled in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), Promptless automatically creates pull requests in your documentation repository with suggested changes. For [commit triggers](/docs/for-docs/connect/triggers/github-commits), you can optionally enable auto-merge to automatically merge documentation PRs as soon as they're created.

Automatic PR creation is available for all Git-hosted documentation platforms.

## Trigger events in documentation PRs

When Promptless creates a pull request for documentation updates, it automatically includes a list of trigger events in the PR description. These are the events that led to those changes. This provides valuable context for reviewers and creates clear traceability between documentation updates and their originating events.

## Follow what a trigger did

The Triggers page in the dashboard records every event that triggered Promptless over the last 30 days and what came of it. Use it to confirm Promptless caught a change, follow a long-running task, or find out why a change produced no suggestion. Each event reports its outcome: researching, suggestion created, suggestion updated, no suggestion, or suggestion closed.

<img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/triggers-page-rows-status-pill-c11cab79.png" alt="Triggers page row list grouped under a Today header, each row showing the time, source icon, action verb, PR or thread reference, and headline, with a status pill on the right reporting the trigger's outcome" />

For each event, you can see the suggestions it created, updated, or closed, along with when the event arrived and when the run finished. Search covers your full trigger history, so you can find an older event by PR details, Slack thread topic, task name, or date range. You can also group events by date or by event source.

### See what Promptless researched

Each trigger includes a research breakdown of what Promptless read before drafting or skipping documentation. It appears on the Triggers page and on the suggestion the trigger produced. Use it to check that Promptless worked from the right sources. The breakdown lists items in roughly the order the agent worked:

- Source and documentation files the agent opened, webpages it fetched, and Slack threads it read.
- Knowledge base files, such as contribution guidelines or style rules, each linked to the file in the [Agent Knowledge Base editor](/docs/for-docs/get-the-most-out/agent-knowledge-base#view-files).
- Content and filename searches, each marked with whether it ran against your doc collection or the agent's own working directory.
- Research delegated to a specialized subagent, with the subagent type and how many tool calls it made.
- Any of [your own skills](/docs/for-docs/connect/doc-locations/how-promptless-learns-your-docs#use-your-existing-skills) the agent used.

## Backfill suggestions

Backfill runs Promptless on pull requests that already exist. Use it to catch up on documentation for work that merged before a trigger was watching. It's available on saved GitHub PR and GitLab merge request triggers. Any organization member can view a backfill's status, progress, and the suggestions it produced. Only admins can launch one.

Choose a window of the last 7, 14, or 30 days. Before you launch, preview the pull requests opened or merged in that window that the trigger matches. The preview applies the same repository, topic, directory, and branch filters the trigger uses for live events. For a trigger scoped by [repository topic](/docs/for-docs/connect/triggers/github-prs#repository-topics), only repositories that carry a matching topic contribute pull requests. Backfill covers up to 1,000 pull requests per repository in the window.

Backfill also replays first approvals for GitHub PR triggers that activate only on first approval. The preview then includes open pull requests whose first approval landed within the selected window, even those opened before it. GitLab merge request and Bitbucket PR triggers don't replay approvals, so a first-approval trigger on those platforms returns no backfill results.

When you launch a backfill, Promptless processes each pull request live, exactly as it does for a new event. Your publishing policy applies, so backfilled pull requests can create documentation PRs and send notifications. Progress updates as the run works through the list.

<Aside type="caution">
  Launching a backfill runs every matched pull request live. With automatic PR creation or auto-merge enabled, a backfill can create or merge documentation PRs and send notifications across all of those pull requests. Preview the list first so you know exactly which pull requests Promptless processes.
</Aside>
