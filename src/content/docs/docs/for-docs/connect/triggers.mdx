Triggers are events that initiate automated documentation updates in Promptless. When a trigger event occurs, Promptless analyzes the context and determines if documentation updates are needed.

## How triggers work

When a trigger event occurs:

1. **Event Detection**: Promptless receives notification of the event (PR opened, message posted, etc.)
2. **Context Analysis**: The system analyzes the event content, including code changes, conversations, or support interactions
3. **Relevance Assessment**: Promptless determines if the event requires documentation updates
4. **Suggestion Creation**: If relevant, Promptless creates documentation suggestions based on the trigger content and connected context sources

## Configure triggers

Triggers are configured in your organization's [Configuration page](https://app.gopromptless.ai/configuration) using the `triggers` section of your `promptless.yaml` file. For each trigger, you can:

- Specify which repositories or channels to monitor
- Configure trigger-specific settings (e.g., directory filters, branch targeting)
- Set up publishing behavior through policy rules

See the [Configuration Reference](/docs/for-docs/reference/configuration-reference) for the complete YAML schema.

<Aside type="note">
  Need a trigger type that isn't currently supported? Contact us at [help@gopromptless.ai](mailto\:help@gopromptless.ai) - we regularly add new trigger types based on user feedback.
</Aside>

## Connect a provider before you add its triggers

To add, rename, or modify a provider-backed trigger, first connect its provider on the [Integrations page](https://app.gopromptless.ai/integrations). Only organization administrators can connect integrations, so if you're not an admin, ask one.

Promptless checks only the triggers you add, rename, or modify, so existing triggers and unrelated settings save as usual. A configuration pushed directly to your Agent Knowledge Base is validated as a whole. If any trigger added or changed in that push lacks its integration, Promptless rejects the entire push and keeps your last valid configuration active.

Each provider-backed trigger type needs its matching integration:

- GitHub PR and commit triggers need GitHub (including GitHub OSS or GitHub Enterprise).
- GitLab merge-request triggers need GitLab.
- Bitbucket PR triggers need Bitbucket.
- Slack triggers need Slack.
- Microsoft Teams triggers need Microsoft Teams.
- ClickUp triggers need ClickUp.
- LaunchDarkly flag triggers need LaunchDarkly.
- Jira triggers need Jira, connected through Atlassian.
- Schedule triggers need no integration.

An integration counts as connected once its credentials are in place, even if no channels, repositories, or projects appear yet.

If you disconnect a provider, its triggers stay in your `promptless.yaml` and show as inactive until you reconnect it. You can remove an inactive trigger at any time. To edit or rename one, reconnect its provider first, or convert it into a [Schedule trigger](/docs/for-docs/connect/triggers/schedule), which saves right away.

Connections are organization-wide, so disconnecting a provider affects every team's triggers for it.

For how these states appear in the editor, see [Provider connection and trigger availability](/docs/for-docs/reference/configuration-reference#provider-connection-and-trigger-availability). To check a connection, see [Connection health](/docs/for-docs/connect/connection-health).

## Automatic PR creation

When automatic PR creation is enabled in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), Promptless automatically creates pull requests in your documentation repository with suggested changes. For [commit triggers](/docs/for-docs/connect/triggers/github-commits), you can optionally enable auto-merge to automatically merge documentation PRs as soon as they're created.

Automatic PR creation is available for all Git-hosted documentation platforms.

## Trigger events in documentation PRs

When Promptless creates a pull request for documentation updates, it automatically includes a list of trigger events in the PR description. These are the events that led to those changes. This provides valuable context for reviewers and creates clear traceability between documentation updates and their originating events.

## Follow what a trigger did

The Triggers page in the dashboard lists every event that triggered Promptless over the last 30 days, one row each. Use it to confirm Promptless caught a change, follow a long-running task, or find out why a change produced no suggestion. A status pill on each row reports the outcome: **researching**, **suggestion created**, **suggestion updated**, **no suggestion**, or **suggestion closed**.

<img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/triggers-page-rows-status-pill-c11cab79.png" alt="Triggers page row list grouped under a Today header, each row showing the time, source icon, action verb, PR or thread reference, and headline, with a status pill on the right reporting the trigger's outcome" />

Expand a row to see its timeline. The timeline shows when the event arrived, each suggestion the run created, updated, or closed, and when the run finished. Each suggestion entry carries a chip showing whether its PR is open (**PR Open**), merged (**Published**), or closed without merging (**Closed**). Select a suggestion to open it. When the run recorded a final response, an **Agent Response:** block previews it. That response often explains why a run finished with **No suggestion created**.

To find an older event, search by PR details, Slack thread topic, task name, or other summary text. Search and the **From** and **To** date fields both cover your full trigger history. **Group by** organizes rows by **Date** (the default), **Event source**, or **None**.

### See what Promptless researched

Each expanded trigger includes a research breakdown of what Promptless read before drafting or skipping documentation. It appears on the Triggers page and in a suggestion's **Triggers & Analysis** tab. A summary line counts the files, knowledge base files, and searches. Select **Show details** to list each item in roughly the order the agent worked. The list covers the source and documentation files the agent opened, the external webpages it fetched, and the Slack threads it read. It also shows these items:

- Each knowledge base file, such as contribution guidelines or style rules, links to that file in the [Agent Knowledge Base editor](/docs/for-docs/get-the-most-out/agent-knowledge-base#view-files).
- Each content or filename search carries a chip showing whether it ran against your doc collection or the agent's own working directory (**sandbox**).

Research delegated to a specialized subagent appears as an indented branch labeled "Delegated research to `<subagent-type>`." The branch shows a count of that subagent's tool calls. When the agent used one of [your own skills](/docs/for-docs/connect/doc-locations/how-promptless-learns-your-docs#use-your-existing-skills), a "Used N of your skills" callout appears next to the summary.

## Backfill suggestions

Backfill suggestions lets you run Promptless on pull requests that already exist. You can catch up on documentation for work that merged before a trigger was watching. It's available on saved pull request and merge request triggers: GitHub PRs and GitLab merge requests.

Any organization member can view backfill status, progress, and the suggestions a backfill produced, but only admins can select Launch a backfill.

Open the **Backfill suggestions** panel on a trigger row. Choose a window of the **last 7 days**, **last 14 days**, or **last 30 days**, and select **Preview**. The preview lists the pull requests opened or merged in that window that the trigger matches. It applies the same repository, topic, directory, and branch filters the trigger uses for live events. A trigger can scope repositories by GitHub topic (the **Trigger on repos with certain topics** option, covered in [Repository topics](/docs/for-docs/connect/triggers/github-prs#repository-topics)). For such a trigger, the preview lists pull requests only from repositories that carry a matching topic. Backfill covers up to 1,000 pull requests per repository in the window.

Backfill also replays first approvals for GitHub PR triggers that activate only on first approval. The preview then includes open pull requests whose first approval landed within the selected window, even those opened before it. GitLab merge request and Bitbucket PR triggers don't replay approvals, so a first-approval trigger on those platforms returns no backfill results.

When the preview looks right, select **Launch backfill** to run it. Promptless processes each pull request live, exactly as it does for a new event. Your publishing policy applies, so backfilled pull requests can create documentation PRs and send notifications. The panel updates with progress as the run works through the list.

<Aside type="caution">
  Launching a backfill runs every matched pull request live. With automatic PR creation or auto-merge enabled, a backfill can create or merge documentation PRs and send notifications across all of those pull requests. Preview the list first so you know exactly which pull requests Promptless processes.
</Aside>
