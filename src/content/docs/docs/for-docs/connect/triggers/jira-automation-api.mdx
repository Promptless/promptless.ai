A Jira Automation rule can call the [API trigger](/docs/for-docs/connect/triggers/api) with a **Send web request** action. Each call starts a documentation update. Use this custom integration when you want Jira Automation's conditions to decide when Promptless runs.

<Aside type="note">
  The [built-in Jira paths](/docs/for-docs/connect/triggers/jira) are the recommended way to trigger from Jira. They handle labels, mentions, assignments, and configured Jira triggers, and Promptless replies on the ticket.
</Aside>

## When to use this path

Use a rule when the built-in paths don't match the event you need. For example, the built-in assignment path starts a session only when a ticket is assigned to the account Promptless acts as. A rule can start one when a ticket is assigned to any docs owner. Jira's audit log records each run.

Jira plans [limit automation executions](https://support.atlassian.com/cloud-automation/docs/automation-service-limits/), and site admins can block outgoing web requests. Check both before you rely on this path.

## Before you start

You need:

- The project's **Manage automation rules** permission, or Jira admin access.
- A connected [Atlassian workspace](/docs/for-docs/reference/integrations/atlassian).
- An active Promptless API key from **Settings > API Access**. See [Generate an API key](/docs/for-docs/connect/triggers/api#generate-an-api-key), or ask whoever manages API access in your organization.

## Build the automation rule

This rule starts a documentation update when a ticket is assigned to a docs owner.

<Steps>
  1. In Jira, open **Project settings > Automation** and create a rule.

  2. Add the **Work item assigned** trigger.

  3. Add an **Issue fields condition** or **User condition** that checks the assignee against your docs-owner account or group.

  4. Add a **Send web request** action. Set the method to **POST** and the URL to `https://api.gopromptless.ai/triggers`.

  5. Add the headers `Authorization: Bearer sk-pl-your-api-key` and `Content-Type: application/json`.

  6. Enter the request body from the next section, then save the rule.
</Steps>

## Request body

Send `instructions`, which says what to update, and `context`, which appears in trigger history. Jira [smart values](https://support.atlassian.com/cloud-automation/docs/jira-smart-values-issues/) such as `{{issue.key}}` resolve at run time, so each run records its ticket.

```json
{
  "instructions": "Update the documentation affected by this Jira work item.",
  "context": {
    "work_item_key": "{{issue.key}}",
    "assignee": "{{issue.assignee.displayName}}"
  }
}
```

## Where the result lands

Each run creates a suggestion in your Promptless dashboard. Your publishing policy decides whether Promptless also opens a docs PR and sends Slack or Microsoft Teams notifications. To have Promptless comment on the ticket with the PR link, use the [built-in Jira paths](/docs/for-docs/connect/triggers/jira).

## Confirm it works

- In Jira, open the rule's **Audit log**. A successful run shows a `202 Accepted` response with a `trigger_event_id`:

  ```json
  {
    "trigger_event_id": "abc123-..."
  }
  ```

  For any other status, see [Error responses](/docs/for-docs/connect/triggers/api#error-responses).

- In Promptless, find the event and its `context` in [trigger history](/docs/for-docs/connect/triggers/api#view-api-triggers) on the [Triggers page](https://app.gopromptless.ai/triggers).
