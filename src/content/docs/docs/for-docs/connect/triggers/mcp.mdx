## Overview

Ask for documentation updates from the AI editor or agent you already work with. When you finish a code change in Cursor or Claude Code, ask Promptless to document it. Your client follows the task in the same conversation and reports the outcome and the docs pull request link. You review and approve the change.

[MCP](https://modelcontextprotocol.io) (Model Context Protocol) is the open protocol that AI editors and agents use to connect to tools. The Promptless MCP server needs no API key and no `promptless.yaml` entry. Connect your client, approve the connection once in the browser, and run a test prompt to confirm the connection.

To start tasks from CI or a script, use the [API trigger](/docs/for-docs/connect/triggers/api). An agent that runs without a person present can connect after one browser approval, as [Unattended agents](/docs/for-docs/reference/mcp-server#unattended-agents) describes. To connect a chat app, see [Use Promptless from Claude](/docs/for-docs/work-the-queue/claude) or [Use Promptless from ChatGPT](/docs/for-docs/work-the-queue/chatgpt).

## Before you start

- An MCP client that supports HTTP transport and OAuth, such as Claude Code, Cursor, VS Code, or Codex CLI.
- Your organization's [Promptless setup](https://app.gopromptless.ai/configuration) finished, to start documentation tasks.
- An active membership in the organization. Any member can connect, whatever their [organization role](/docs/for-docs/security/access-and-permissions). If you don't have an organization yet, create one when you [authorize](#authorize-in-the-browser), or [let a coding agent create one](#let-a-coding-agent-create-your-account).

## Connect the server

Connect to `https://api.gopromptless.ai/mcp` when your client works in a local copy of your documentation repository or doesn't need file tools. Editors such as Cursor, CLI agents such as Claude Code, and custom agents use this URL. A client with no local copy, such as a chat app, uses `https://api.gopromptless.ai/mcp/with-direct-edits`, which adds tools that search, read, and edit documentation files. Follow the steps for your client, then [authorize in the browser](#authorize-in-the-browser). The dashboard also shows the URL and the Claude Code command under **Settings** > **Editor connection (MCP)**.

### Claude Code

<Steps>
  1. In a terminal, add the `promptless` server:

     ```bash
     claude mcp add --transport http promptless https://api.gopromptless.ai/mcp
     ```

  2. In Claude Code, run `/mcp` and select **promptless**. A browser tab opens to the consent page.
</Steps>

### Cursor

<Steps>
  1. Add the `promptless` server to `mcp.json`. The `url` key tells Cursor to use HTTP transport.

     ```json
     {
       "mcpServers": {
         "promptless": {
           "url": "https://api.gopromptless.ai/mcp"
         }
       }
     }
     ```

     Or select [Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=promptless\&config=eyJ0eXBlIjoiaHR0cCIsInVybCI6Imh0dHBzOi8vYXBpLmdvcHJvbXB0bGVzcy5haS9tY3AifQ%3D%3D) to add the same server in one step.

  2. In Cursor's MCP settings, select **Needs login** next to **promptless**. A browser tab opens to the consent page.
</Steps>

### VS Code

<Steps>
  1. In a terminal, add the `promptless` server:

     ```bash
     code --add-mcp "{\"name\":\"promptless\",\"type\":\"http\",\"url\":\"https://api.gopromptless.ai/mcp\"}"
     ```

  2. In the Command Palette, run **MCP: List Servers** and start **promptless**. A browser tab opens to the consent page.
</Steps>

### Codex CLI

<Steps>
  1. In a terminal, add the `promptless` server. Codex infers HTTP transport from the `--url` flag.

     ```bash
     codex mcp add promptless --url https://api.gopromptless.ai/mcp
     ```

  2. Start authorization:

     ```bash
     codex mcp login promptless
     ```

     A browser tab opens to the consent page.
</Steps>

### Other MCP clients

Add an HTTP server named `promptless` with the URL `https://api.gopromptless.ai/mcp`, then start the client's OAuth login. The exact steps vary by client.

## Authorize in the browser

Every client on this URL uses the same consent page. Approve the connection there once.

<Steps>
  1. On the consent page, choose the Promptless organization to connect. The picker selects your active organization by default. If you don't belong to an organization yet, enter a name for a new one.

  2. Check the **Returns to** row. It shows where Promptless sends access when you approve. Promptless doesn't verify the client name, so go by this row. A local editor such as Claude Code or Cursor returns to a local address with a port, like `127.0.0.1:54321`. An app that opens through its own link scheme shows a callback like `myapp://claude.ai/cb`, and any app on your device that handles `myapp://` links receives the access. Cancel if you didn't start this connection from that client.

  3. Select **Authorize as \{your email}**. For a new organization, the button reads **Create organization and authorize as \{your email}**. Your client stores the token, and the tab returns you to the client.
</Steps>

The connection acts with your access in the organization you chose. It can read any task and change any suggestion in that organization. A connection covers one organization. To connect another organization, authorize again and choose that organization. The [MCP server reference](/docs/for-docs/reference/mcp-server) lists the token lifetimes and what a connection can access. It also shows how the approval page for this URL differs from the one for `/mcp/with-direct-edits`.

## Test the connection

Right after you approve, confirm that the client reaches the right organization. Enter this prompt in your client:

```text
Which documentation repositories is Promptless connected to?
```

The client calls `list_doc_collections`, a read-only tool, and lists the doc collections of the organization you chose by name, such as `acme/docs`. If the client asks to approve the call, approve it. The connection works when you see your organization's documentation repositories.

If the list is empty or shows repositories you don't recognize, check which organization is connected. Enter `Which Promptless organization am I connected to?`

- **The organization name is wrong**: Remove the `promptless` server from your client. Then add it again with the steps for your client, and choose the correct organization.
- **The organization name is right, and the list is empty**: The organization has no doc collections yet. To add your first one, connect your docs repository as the [quickstart](/docs/for-docs/start-here/quickstart#complete-the-setup-wizard) describes. To see the setup steps that remain, enter `What is my Promptless setup status?`

## Connect integrations from your editor

Promptless needs integrations, such as GitHub and Slack, to watch for changes and publish suggestions. A person approves each connection in a browser, so your client creates a link for that person with the [`connect_integration`](/docs/for-docs/reference/mcp-tools#connect_integration) tool. This works from any connection, including an [agent-created account](#let-a-coding-agent-create-your-account).

<Steps>
  1. Ask your client to connect an integration, for example: "Connect Slack to Promptless." Your client returns a link.

  2. Send the link to someone who can grant access to that integration. The link works for 24 hours.

  3. That person signs in to Promptless, then opens the link.

  4. That person selects **Continue to \{provider}** and approves access with the provider.

  5. Ask your client to check the connection. It calls [`get_account_status`](/docs/for-docs/reference/mcp-tools#get_account_status), which lists the connected integrations.
</Steps>

Only a member of the organization can connect an integration. On an unclaimed agent-created account, the first person to open a link claims the account and becomes its admin.

## Let a coding agent create your account

A coding agent, such as Claude Code or Codex, can create a Promptless organization and connect to it before anyone signs in. You then claim the account to become its admin. Until someone claims it, the agent can only check the account's status and [create links for connecting integrations](#connect-integrations-from-your-editor). The agent's token works only for the organization it created. To act in an existing organization, an agent connects with OAuth, as [Unattended agents](/docs/for-docs/reference/mcp-server#unattended-agents) describes.

<Steps>
  1. Create the account. The request needs no authentication, and the organization name is 1–100 characters:

     ```bash
     curl -X POST https://api.gopromptless.ai/agent-signups \
       -H "Content-Type: application/json" \
       -d '{"organization_name": "Acme Docs"}'
     ```

     The response carries an `access_token` for the MCP server and a `claim_url` for the person who claims the account. Save both, because Promptless shows them only once. Keep the token secret, because it acts for the organization until someone claims it.

  2. Connect the agent with the token. In Claude Code, run:

     ```bash
     claude mcp add --transport http promptless https://api.gopromptless.ai/mcp \
       --header "Authorization: Bearer <access_token>"
     ```

     In Codex, set `PROMPTLESS_ACCESS_TOKEN` to the token, then run:

     ```bash
     codex mcp add promptless --url https://api.gopromptless.ai/mcp \
       --bearer-token-env-var PROMPTLESS_ACCESS_TOKEN
     ```

  3. Within 72 hours, sign in to Promptless or create an account, then open the `claim_url`. Promptless deletes an account that nobody claims in that time.

  4. Select **Claim account**. You become the organization's admin, and the agent's access token stops working.

  5. Remove the token-based `promptless` server from the agent, and [connect the server](#connect-the-server) with OAuth. The new connection acts as you.
</Steps>

## Ask your client

Ask in plain language, and your client picks the tools. For example:

- "Document the new authentication flow in the API docs collection."
- "Triage my open Promptless suggestions, label the P0s, and close anything we've decided against."

Your client can auto-approve the read-only tools. Tools that start or change work ask before they run. For what each tool does and which tools are read-only, see the [MCP tools reference](/docs/for-docs/reference/mcp-tools).

## Answer a clarifying question

A task can finish by asking you one clarifying question. If your client supports MCP forms (elicitation), it shows a **Your answer** field. Otherwise, reply in the same conversation. Promptless continues the work in a new task that carries your request and your answer, and your client follows that task too.

## Workflow skills

Promptless also offers skills, step-by-step guidance for workflows that chain several tools, such as backlog triage. Skills reach your client over the draft MCP Skills extension (SEP-2640), which many clients don't support yet. A client without it calls the same tools directly.

## See your MCP tasks in the dashboard

On the [Triggers page](https://app.gopromptless.ai/triggers), a task started over MCP shows an **MCP Task** pill with a byline reading `<client name> · submitted by @<username>`. Tasks submitted with an `sk-pl-` API key show an **API Task** pill.

To find MCP-originated suggestions on the [Suggestions list](https://app.gopromptless.ai/suggestions), set the **Trigger source** filter to "API". That filter includes both MCP and API-key submissions.

## Manage and revoke your connection

A connection lasts 90 days from approval, and your client refreshes its access automatically until then. After 90 days, authorize in the browser again.

To revoke a connection, remove the `promptless` server from your client. The dashboard's **Editor connection (MCP)** section shows setup instructions only. Promptless also revokes the connection if you lose active membership in the organization. Each member manages their own connection, and an admin can't revoke another member's connection.

## Troubleshooting

- **The consent tab doesn't open, or consent was denied, canceled, or expired**: Repeat the last step for your client under [Connect the server](#connect-the-server). A consent request expires after 30 minutes.
- **No promptless entry under `/mcp` in Claude Code**: Confirm that the `claude mcp add` command ran, then restart Claude Code.
- **Cursor's Needs login button doesn't respond**: Remove the `promptless` server and add it again.
- **The organization is not in the picker**: You aren't an active member of that organization. Ask an admin of the Promptless organization to invite you.
- **A tool you expect is missing**: Your client loads the tool list when it connects. Reconnect the `promptless` server or start a new conversation.
- **A tool call from an unclaimed agent-created account fails**: The agent can only check the account's status and create connect links. [Claim the account](#let-a-coding-agent-create-your-account), then connect with OAuth.
- **The agent's access token returns `401`**: A person claimed the account, or Promptless deleted it unclaimed after 72 hours. After a claim, [connect with OAuth](#connect-the-server). Otherwise, create a new account.
- **A connect link says you aren't a member**: Another person claimed the agent-created account first, or an admin removed you. Ask a member to invite you.
- **A connect link says it's invalid or expired**: Ask your client for a new link. A link works for 24 hours, and copying can cut it short.

For an error a tool returns, such as `task_finished` or `stale_head`, see [Tool errors](/docs/for-docs/reference/mcp-tools#tool-errors).
