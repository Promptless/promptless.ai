## Overview

Use the Promptless MCP server to ask for documentation updates from the AI editor or chat app you already work in. When you finish a code change in Claude Code or Cursor, ask Promptless to document it. Promptless drafts the docs change, and your editor reports back in the same conversation with the outcome and the docs pull request link. You review and approve the change.

From the same conversation, you can also:

- Check on any Promptless task in your organization, including tasks started from Slack or GitHub.
- Ask Promptless to revise a suggestion, or label, assign, retitle, or close it.
- Work through a backlog of suggestions.
- Edit doc files on a suggestion's branch yourself.
- Report a problem to the Promptless team.

[MCP](https://modelcontextprotocol.io) (Model Context Protocol) is the open protocol that AI editors use to connect to tools. The server is always on: it needs no API key and no `promptless.yaml` entry, and you authorize once in the browser. To start tasks from CI or a script, use the [API trigger](/docs/for-docs/connect/triggers/api). To use Promptless from the Claude.ai or ChatGPT web app, see [Use Promptless from Claude.ai or ChatGPT](/docs/for-docs/work-the-queue/claude-and-chatgpt).

## Before you start

Before you connect, your organization must have [finished setting up Promptless](https://app.gopromptless.ai/configuration).

## Connect the server

Promptless has two server URLs. Each is a separate connection that you authorize on its own.

| URL                                                 | Use it                                                                                                                                              |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `https://api.gopromptless.ai/mcp`                   | Day to day. Promptless drafts doc changes, and you review them.                                                                                     |
| `https://api.gopromptless.ai/mcp/with-direct-edits` | When you want your client to [edit doc files itself](#read-and-edit-documentation-directly). Its six extra tools use more of your client's context. |

The steps below use `/mcp`. The **Editor connection (MCP)** section of the dashboard's **Settings** page shows the same URL and command.

### Claude Code

<Steps>
  1. Add the server:

     ```bash
     claude mcp add --transport http promptless https://api.gopromptless.ai/mcp
     ```

  2. Run `/mcp` and select **promptless**.

  3. [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Cursor

<Steps>
  1. Add the server with the [Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=promptless\&config=eyJ0eXBlIjoiaHR0cCIsInVybCI6Imh0dHBzOi8vYXBpLmdvcHJvbXB0bGVzcy5haS9tY3AifQ%3D%3D) link. Or add this entry to `mcp.json`:

     ```json
     {
       "mcpServers": {
         "promptless": {
           "url": "https://api.gopromptless.ai/mcp"
         }
       }
     }
     ```

  2. Select **Needs login**.

  3. [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### VS Code

<Steps>
  1. Add the server:

     ```bash
     code --add-mcp "{\"name\":\"promptless\",\"type\":\"http\",\"url\":\"https://api.gopromptless.ai/mcp\"}"
     ```

  2. Run **MCP: List Servers** from the Command Palette and start **promptless**.

  3. [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Codex CLI

<Steps>
  1. Add the server:

     ```bash
     codex mcp add promptless --url https://api.gopromptless.ai/mcp
     ```

  2. Run `codex mcp login promptless`.

  3. [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Claude

<Steps>
  1. In Claude, open **Customize** > **Connectors**, select **+**, then select **Add custom connector**.

  2. Enter `https://api.gopromptless.ai/mcp`, then select **Add**.

  3. Select **Connect**, then [authorize in the browser](#authorize-in-the-browser).
</Steps>

On a Team or Enterprise plan, an Owner first adds the connector under **Organization settings** > **Connectors**. To use it in a conversation, turn it on from the **+** menu under **Connectors**.

### Other MCP clients

Any client that supports HTTP transport and OAuth can connect at either URL.

## Authorize in the browser

<Steps>
  1. In the browser tab that opens, choose the organization to connect.

  2. Check the **Returns to** row, which shows where Promptless sends access. Promptless doesn't verify the client name, so trust this row. A local editor returns to a local address such as `127.0.0.1:54321`. An app returns to its own link scheme, such as `myapp://claude.ai/cb`. Cancel if you didn't start this connection.

  3. Select **Authorize as \{your email}**.
</Steps>

A connection acts with your access. It can read every task and suggestion in your organization, and its write tools act on any suggestion, not only yours. Any active member can connect, and access can't be limited by [role](/docs/for-docs/security/access-and-permissions). To control what Promptless publishes, use [publishing policies and relevance filtering](/docs/for-docs/tune/noise-and-relevance-filtering).

A connection covers one organization. To connect another, authorize again and pick it. Some clients don't name the server URL when they authorize. Their token works at both URLs, so the consent page lists file reading and editing.

## Ask your editor

Ask in plain language, and your editor picks the tools. Tools that change work ask you before they run.

| Ask                                                                                           | Tool                                                                  |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| "Document the new authentication flow in the API docs collection."                            | `list_doc_collections`, then `submit_documentation_task`              |
| "Check whether a suggestion already covers webhook retries."                                  | `search_suggestions`                                                  |
| "What's the status of Promptless task `<id>`?"                                                | `get_task_status`                                                     |
| "Tell Promptless task `<id>` to also cover the error responses."                              | `send_task_message`                                                   |
| "Revise Promptless suggestion `<id>` to also cover single sign-on."                           | `request_changes`                                                     |
| "Assign suggestion `<id>` to @alex, retitle it 'SSO setup,' and open its docs PR."            | `update_suggestion`                                                   |
| "Close suggestion `<id>`. We decided not to document this."                                   | `close_suggestion`                                                    |
| "What are my recent Promptless tasks?"                                                        | `list_recent_tasks`                                                   |
| "Triage my open suggestions, label the P0s, and close anything we've decided against."        | The [`triage-suggestions` skill](#workflow-skills), or the tools above |
| "Change webhook retries from 3 to 5 on the open webhook retries suggestion, and open the PR." | The [direct-edit tools](#read-and-edit-documentation-directly)        |

A task takes several minutes. Your editor follows it with `wait_for_task_update` and reports the outcome and docs pull request link when it finishes.

## Available tools

Both server URLs carry these 12 tools. Your editor can auto-approve the read-only tools. The others ask before each run.

| Tool                                                        | What it does                                        | Read-only |
| ----------------------------------------------------------- | --------------------------------------------------- | --------- |
| [`submit_documentation_task`](#submit_documentation_task)   | Starts a documentation task.                        | No        |
| [`list_doc_collections`](#list_doc_collections)             | Lists your collections and their IDs.               | Yes       |
| [`get_task_status`](#get_task_status)                       | Reads a task's state, outcome, and conversation.    | Yes       |
| [`wait_for_task_update`](#wait_for_task_update)             | Waits for a running task to change.                 | Yes       |
| [`send_task_message`](#send_task_message)                   | Adds an instruction to a running task.              | No        |
| [`answer_task_question`](#answer_task_question)             | Answers a task's clarifying question.               | No        |
| [`request_changes`](#request_changes)                       | Asks Promptless to revise a suggestion.             | No        |
| [`update_suggestion`](#update_suggestion)                   | Sets labels, assignees, or title, or opens the PR.  | No        |
| [`close_suggestion`](#close_suggestion)                     | Closes a suggestion and its docs pull request.      | No        |
| [`list_recent_tasks`](#list_recent_tasks)                   | Lists your organization's recent tasks.             | Yes       |
| [`search_suggestions`](#search_suggestions)                 | Searches suggestions by keyword, status, and label. | Yes       |
| [`message_promptless_support`](#message_promptless_support) | Sends a report to the Promptless team.              | No        |

If a tool is missing, reconnect the `promptless` server. In Claude Code, run `/mcp` and select **promptless** again. In Cursor, remove the server and add it again.

### `submit_documentation_task`

Starts a documentation task. It returns the task ID (`trigger_event_id`) and a `next_call` that your editor uses to follow the task.

| Argument            | Required | Description                                                                                                                                                                               |
| ------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `instructions`      | Yes      | What you want documented.                                                                                                                                                                 |
| `doc_collection_id` | No       | The collection to target, from `list_doc_collections`. Omit it to route across all collections. [Relevance filtering](/docs/for-docs/tune/noise-and-relevance-filtering) applies to each. |
| `context`           | No       | Metadata attached to the request. It appears in trigger history.                                                                                                                          |
| `attachments`       | No       | Links to material that explains the change, such as a screenshot or spec. Each is a URL with an optional description. Promptless skips links it can't reach.                              |

### `list_doc_collections`

Lists your documentation collections and their IDs.

### `get_task_status`

Reads the current state of any task in your organization, wherever it started. The response includes:

- Whether the task has finished, and then its `outcome`: `suggestions_created`, `no_change_needed`, `needs_input`, or `failed`. `outcome` is `null` for tasks that didn't start from the API or MCP.
- A `resolution` note on how the task ended.
- The suggestions the task produced, each with its docs pull request link and status: `draft`, `open`, `merged`, or `closed`.
- `messages`, the task's conversation, oldest first, up to the latest 100. Only tasks started from the API or MCP, or by `request_changes`, have one. Each message has an `id`, `sequence`, `author` (`type` is `promptless` or `customer`), `created_at`, and `message`.
- `status_guidance`, advice from the server on following the task.

### `wait_for_task_update`

Waits up to 30 seconds for a running task to change, then returns what changed. Your editor calls it repeatedly to follow a task.

| Argument           | Required | Description                                                                 |
| ------------------ | -------- | --------------------------------------------------------------------------- |
| `trigger_event_id` | Yes      | The task to follow.                                                         |
| `cursor`           | No       | The `cursor` from the previous call. Omit it to get a snapshot of the task. |
| `wait_seconds`     | No       | How long to wait, from 0 to 30. Defaults to 30.                             |

Each call returns new `messages`, a `cursor`, `has_more_messages`, `finished`, a `result` that matches the outcome from `get_task_status`, and an `update_type` of `snapshot`, `changed`, or `timeout`. It also returns a `next_call`. Your editor keeps following `next_call` until it's null, which happens once the task has finished and no messages remain. A `timeout` is normal. Retrying with the same `cursor` is safe, and your editor drops repeated messages by `id`. Stopping doesn't cancel the task.

### `send_task_message`

Adds an instruction to a running task without starting a new one. It works for tasks started from the API or MCP, or by `request_changes`, including tasks other members started. A finished task rejects messages. To answer a finished task's question, use [`answer_task_question`](#answer_task_question).

| Argument           | Required | Description                                                                                                              |
| ------------------ | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| `trigger_event_id` | Yes      | The running task.                                                                                                        |
| `message`          | Yes      | The instruction, up to 20,000 characters.                                                                                |
| `idempotency_key`  | No       | A key for safe retries. A retry with the same key and text returns the stored message. The same key with new text fails. |

It returns the stored `message` and `deduplicated`, which is `true` when a retry matched a stored message.

<a id="answer-a-clarifying-question" />

### `answer_task_question`

A task you started over MCP can finish by asking one clarifying question. Your editor sees the `question` and a `next_call` that points to this tool. Answering starts a new task that carries the original request, context, clarification history, and links to any results.

| Argument              | Required | Description                                                                    |
| --------------------- | -------- | ------------------------------------------------------------------------------ |
| `trigger_event_id`    | Yes      | The finished task that asked the question.                                     |
| `question_message_id` | Yes      | The question's message ID.                                                     |
| `answer`              | No       | Your answer, 1–8000 characters. Omit it to have your editor ask you in a form. |

If your client supports MCP elicitation, it shows a **Your answer** field. The `outcome` is one of:

- `submitted`: Promptless starts the new task. Your editor follows it through `next_call`.
- `already_answered`: An earlier answer won. Follow the task the returned `trigger_event_id` names.
- `unavailable`: Your client can't show a form. Your editor asks in chat, then calls the tool again with your answer.
- `decline` or `cancel`: No new task starts, and following stops. Anything the original task produced remains.

### `request_changes`

Asks Promptless to revise a suggestion. Promptless updates the suggestion's existing docs pull request. It returns a task ID and a `next_call` to follow the revision.

| Argument        | Required | Description                                                     |
| --------------- | -------- | --------------------------------------------------------------- |
| `suggestion_id` | Yes      | The suggestion, from `search_suggestions` or `get_task_status`. |
| `instructions`  | Yes      | What to change.                                                 |

If Promptless can no longer revise the suggestion's pull request, the tool says so. Start a new task instead.

### `update_suggestion`

Sets a suggestion's labels, assignees, or title, and can open its docs pull request. It can't change the description.

| Argument            | Required | Description                                                                            |
| ------------------- | -------- | -------------------------------------------------------------------------------------- |
| `suggestion_id`     | Yes      | The suggestion to update.                                                              |
| `labels`            | No       | Replaces the stored labels. Pass an empty list to clear them.                          |
| `assignees`         | No       | Replaces the stored assignees. Pass an empty list to clear them.                       |
| `title`             | No       | The new title.                                                                         |
| `open_pull_request` | No       | Pass `true` to open the docs pull request, after any label and assignee changes apply. |

`labels` and `assignees` replace the whole list, so read the current values with `search_suggestions` first. While the pull request is open, Promptless pushes a title change to GitHub or GitLab. If the host rejects it, the call fails and the title stays the same, but label and assignee changes stay applied. Repeating a call is safe, and opening a pull request that's already open returns it.

It returns `labels`, `assignees`, `title`, `docs_pr_url`, and `pull_request_opened`.

### `close_suggestion`

Closes a suggestion and its docs pull request. No MCP tool reopens it, so to pick the change up again, start a new task. Your editor can't auto-approve this tool.

| Argument        | Required | Description                  |
| --------------- | -------- | ---------------------------- |
| `suggestion_id` | Yes      | The suggestion to close.     |
| `reason`        | No       | A note saved with the close. |

If the host refuses to close the pull request, the suggestion stays open and the tool says why. A merged pull request can't be closed. The close records you and your client's name. It doesn't turn on the dashboard's **Remember this feedback for future suggestions** option.

It returns the `suggestion_id`, `status`, and a `message`.

### `list_recent_tasks`

Lists your organization's recent tasks, newest first, with their IDs. It includes tasks started from Slack, GitHub, and the dashboard. Look up an API task by its ID with `get_task_status`.

### `search_suggestions`

Searches suggestions by keyword. Use it to check whether a change is already covered, or to find a suggestion to revise.

| Argument | Required | Description                                                                         |
| -------- | -------- | ----------------------------------------------------------------------------------- |
| `query`  | Yes      | Text to match in titles and descriptions, at least 3 characters.                    |
| `status` | No       | One of `draft`, `open`, `merged`, or `closed`.                                      |
| `labels` | No       | Returns suggestions with any of these labels. Matching is exact and case-sensitive. |
| `limit`  | No       | Maximum results. Defaults to 25, up to 100.                                         |

Each result includes its `labels`, `assignees`, and `branch_name`, so you can check out an open suggestion's branch locally. `truncated` is `true` when more suggestions matched than were returned.

### `message_promptless_support`

Sends a problem report or a request for help to the Promptless team. Use it when a task, suggestion, or tool doesn't behave the way you expect.

| Argument   | Required | Description                                                                              |
| ---------- | -------- | ---------------------------------------------------------------------------------------- |
| `concern`  | Yes      | What went wrong or what you need, 1–2000 characters. Include any task or suggestion IDs. |
| `severity` | Yes      | `low`, `medium`, or `high`.                                                              |

The report includes your organization, name, email, and client name. The tool returns `sent: true` and a confirmation `message`. Replies don't come back through the tool. For other ways to reach the team, see [Get support](/docs/for-docs/reference/getting-help).

## Read and edit documentation directly

These six tools are available only at `https://api.gopromptless.ai/mcp/with-direct-edits`. Use them when you'd rather make a doc change yourself than describe it. Your client finds the pages, edits them on an open suggestion's branch, checks the diff, and opens the pull request with `update_suggestion`. To change something no open suggestion covers, start a task first, then edit the suggestion it creates.

Your client can auto-approve the four read tools. `write_documentation_file` and `edit_documentation_file` ask before each run.

`list_documentation_files`, `read_documentation_file`, and `search_documentation` read only the paths Promptless maintains, and take two optional arguments:

| Argument            | Description                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| `doc_collection_id` | The collection to read. Required when you have several collections and don't pass `suggestion_id`. |
| `suggestion_id`     | Reads that suggestion's branch. Omit it to read the default branch.                                |

Each read returns a `ref` whose `sha` you pass as `expected_head_sha` when you write.

### `list_documentation_files`

Lists file paths in sorted order. Pass `path_prefix`, such as `docs/api/`, to narrow the list, and `limit` to cap it (default 500, up to 2,000). When `truncated` is `true`, narrow the prefix.

### `read_documentation_file`

Reads one text file by its repository-relative `path` and returns its `content` and `size_bytes`. It refuses binary files and files over 256 KB.

### `search_documentation`

Finds lines that match text or a regular expression across a collection's text files.

| Argument         | Required | Description                                                                                           |
| ---------------- | -------- | ----------------------------------------------------------------------------------------------------- |
| `query`          | Yes      | The text to find, up to 256 characters.                                                               |
| `regex`          | No       | Pass `true` to treat `query` as an RE2 regular expression, which has no backreferences or lookaround. |
| `case_sensitive` | No       | Pass `true` to match case exactly.                                                                    |
| `path_prefix`    | No       | Searches only paths that start with this prefix.                                                      |
| `limit`          | No       | Maximum matching lines. Defaults to 50, up to 200.                                                    |

Each match returns its `path`, `line`, and `text`. A search reads up to 400 files of up to 128 KB each, within 10 seconds. If `files_skipped` is above zero, search again with a narrower `path_prefix`.

### `get_suggestion_diff`

Takes a `suggestion_id` and returns a unified diff for each changed file against the base branch, with each file's `status`: `added`, `modified`, `removed`, or `renamed`. It also returns the branch's `head_sha`. Diff text is capped at 200,000 characters; files past the cap have a `diff` of `null`.

### `write_documentation_file`

Creates or replaces a whole file on an open suggestion's branch. For a change to part of a page, use `edit_documentation_file`.

| Argument            | Required | Description                                                                                 |
| ------------------- | -------- | ------------------------------------------------------------------------------------------- |
| `suggestion_id`     | Yes      | The open suggestion to commit to.                                                           |
| `path`              | Yes      | The repository-relative file path.                                                          |
| `content`           | Yes      | The complete file content, up to 256 KB.                                                    |
| `expected_head_sha` | No       | The `sha` from your last read or write. The write fails if the branch has moved since then. |

### `edit_documentation_file`

Replaces exact text in one file on an open suggestion's branch. It takes `suggestion_id`, `path`, and `expected_head_sha` like `write_documentation_file`, plus `edits`: 1 to 50 entries, each with an `old_text` and a `new_text`. Each `old_text` must match exactly one place in the file. An empty `new_text` deletes the match.

Each write makes one commit, `Update from <your email> via <client name>`, and returns the new `head_sha`, `docs_pr_url`, and `status`. If your edits leave no changes against the base branch, Promptless closes the suggestion and its pull request. No tool deletes a file. To remove a page, ask for it with `request_changes`.

## Workflow skills

Clients that support the draft MCP Skills extension (SEP-2640) get step-by-step guides for workflows that chain several tools:

- `triage-suggestions`, at both URLs, works through a backlog of suggestions. It checks `truncated` so it doesn't miss part of the queue. It gives each suggestion one outcome: a label or assignee, a revision request, or a close.
- `edit-documentation`, at the direct-edit URL, walks through one direct edit, from finding pages to opening the pull request.

Skills use the same tools, and those tools still ask before they change anything. Clients without skills support call the tools directly.

## See your MCP tasks in the dashboard

On the [Triggers page](https://app.gopromptless.ai/triggers), an MCP task shows an **MCP Task** pill and the byline `<client name> · submitted by @<username>`. On the [Suggestions list](https://app.gopromptless.ai/suggestions), set **Trigger source** to "API" to find suggestions from MCP and API tasks.

## Manage and revoke your connection

Your editor refreshes the connection automatically for 90 days. After that, authorize again in the browser.

To revoke a connection, remove the `promptless` server from your editor, or the connector from **Customize** > **Connectors** in Claude. The dashboard has no revoke button. Promptless checks your membership on every call, so a member who leaves the organization loses access. Each member manages their own connection.

## Troubleshooting

Tool errors reach your editor as `code: message`.

| Problem                                                        | Fix                                                                                                                                                       |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The consent tab doesn't open, or consent was denied or expired | Authorize again. In Claude Code, run `/mcp` and select **promptless**. In Cursor, select **Needs login**.                                                 |
| No **promptless** entry under `/mcp` in Claude Code            | Confirm the add command ran, then restart Claude Code.                                                                                                    |
| Cursor's **Needs login** doesn't respond                       | Remove the server and add it again.                                                                                                                       |
| "This organization has not finished setting up Promptless."    | Finish setup on the [Configuration page](https://app.gopromptless.ai/configuration), or ask an admin to.                                                  |
| "The requested doc collection is not configured."              | Pass an `id` from `list_doc_collections`.                                                                                                                 |
| A read names no collection, and you have several               | Pass a `doc_collection_id` from the list the tool returns, or a `suggestion_id`.                                                                          |
| Invalid `suggestion_id` or `doc_collection_id`                 | Get a valid ID from `search_suggestions` or `list_doc_collections`.                                                                                       |
| `search_suggestions` rejects the request                       | Use a `query` of at least 3 characters and a `status` of `draft`, `open`, `merged`, or `closed`.                                                          |
| `request_changes` says the suggestion can't be revised         | Start a new task with `submit_documentation_task`.                                                                                                        |
| `update_suggestion` won't open the pull request                | The suggestion closed without merging. Labels, assignees, and title still update.                                                                         |
| `close_suggestion` fails                                       | The pull request already merged, the suggestion is already closed, or the host refused. The tool says which.                                              |
| `task_finished`                                                | Start a new task. If the task asked a question, use `answer_task_question`.                                                                               |
| `unsupported_task_source`                                      | Only API and MCP tasks accept messages. Read the task with `get_task_status` instead.                                                                     |
| `invalid_message`                                              | Send a message of 1 to 20,000 characters.                                                                                                                 |
| `idempotency_conflict`                                         | Resend with a new `idempotency_key`, or with the original text.                                                                                           |
| `invalid_cursor`                                               | Omit `cursor` to start from the beginning.                                                                                                                |
| `task_read_timeout`                                            | Retry with the same task and cursor.                                                                                                                      |
| `continuation_conflict`                                        | Start a new task with `submit_documentation_task`, restating your request and answer.                                                                     |
| `continuation_unavailable`                                     | Retry `answer_task_question` with the same arguments.                                                                                                     |
| A path outside the paths Promptless maintains                  | Get a valid path from `list_documentation_files`.                                                                                                         |
| `search_documentation` reports an invalid RE2 expression       | Remove backreferences and lookaround, or set `regex` to `false`.                                                                                          |
| A file over 256 KB, or a binary file                           | The file tools can't read or write it.                                                                                                                    |
| A write to a closed suggestion                                 | Pick an open suggestion, or start a new task.                                                                                                             |
| A write before the suggestion's task finishes                  | Wait for the task to finish, then retry.                                                                                                                  |
| `stale_head`                                                   | Read the file again, then retry with the commit the error names as `expected_head_sha`.                                                                   |
| An `old_text` matches no place or several places               | Read the file again and copy enough surrounding text to match one place.                                                                                  |
| `message_promptless_support` refuses the report                | Keep `concern` to 1–2000 characters and use a `severity` of `low`, `medium`, or `high`. If the tool returns a retry delay, wait that long and send again. |
| `message_promptless_support` can't confirm delivery            | The report may have arrived, so don't resend it. To be sure, email [help@gopromptless.ai](mailto\:help@gopromptless.ai).                                  |
