## Overview

Ask for documentation updates from the AI editor you already work in. When you finish a code change in Claude Code or Cursor, ask Promptless to document it. Promptless drafts the docs change, and your editor reports back in the same conversation with the outcome and the docs pull request link. You review and approve the change. From the same conversation, you can also check on a task, ask Promptless to revise a suggestion, or triage your open suggestions.

[MCP](https://modelcontextprotocol.io) (Model Context Protocol) is the open protocol that AI editors use to connect to tools. The Promptless MCP server is always on. It needs no API key and no `promptless.yaml` entry, and you authorize once in the browser. To start tasks from CI or a script, use the [API trigger](/docs/for-docs/connect/triggers/api). To connect Claude or ChatGPT, see [Use Promptless from Claude](/docs/for-docs/work-the-queue/claude) or [Use Promptless from ChatGPT](/docs/for-docs/work-the-queue/chatgpt).

## Before you start

- An MCP-capable editor, such as Claude Code or Cursor, or a chat app that accepts custom connectors, such as Claude.
- Your organization's [Promptless setup](https://app.gopromptless.ai/configuration) finished.
- An active membership in the organization. MCP needs no API key and no particular organization role.

## Connect the server

Connect each editor once, at `https://api.gopromptless.ai/mcp`. Promptless drafts the documentation changes, and you review them. For Claude Code, one command sets it up:

```bash
claude mcp add --transport http promptless https://api.gopromptless.ai/mcp
```

The same URL and command also appear in the [dashboard](https://app.gopromptless.ai) under **Settings**, in the **Editor connection (MCP)** section, which every organization member can see.

### Claude Code

<Steps>
  1. Run the add command shown above.

  2. Run `/mcp` and pick **promptless**.

  3. Authorize the connection in the browser tab that opens. See [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Cursor

<Steps>
  1. Add an HTTP MCP server named `promptless`. Use the URL `https://api.gopromptless.ai/mcp`, either in Cursor's MCP settings or by adding the entry to `mcp.json`:

     ```json
     {
       "mcpServers": {
         "promptless": {
           "url": "https://api.gopromptless.ai/mcp"
         }
       }
     }
     ```

     The `url` key tells Cursor to use HTTP transport. Or add the server in one step with the [Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=promptless\&config=eyJ0eXBlIjoiaHR0cCIsInVybCI6Imh0dHBzOi8vYXBpLmdvcHJvbXB0bGVzcy5haS9tY3AifQ%3D%3D) deep link, which registers the `promptless` server for you.

  2. Click **Needs login**.

  3. Authorize the connection in the browser tab that opens. See [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### VS Code

<Steps>
  1. Add the `promptless` server with the `code` CLI:

     ```bash
     code --add-mcp "{\"name\":\"promptless\",\"type\":\"http\",\"url\":\"https://api.gopromptless.ai/mcp\"}"
     ```

  2. Run **MCP: List Servers** from the Command Palette and start **promptless**.

  3. Authorize the connection in the browser tab that opens. See [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Codex CLI

<Steps>
  1. Add the `promptless` server. Codex infers HTTP transport from the `--url` flag:

     ```bash
     codex mcp add promptless --url https://api.gopromptless.ai/mcp
     ```

  2. Run `codex mcp login promptless` to start authorization.

  3. Authorize the connection in the browser tab that opens. See [Authorize in the browser](#authorize-in-the-browser).
</Steps>

### Other MCP clients

Any client that supports HTTP transport and OAuth connects at the same URL. The exact steps vary by client.

## Authorize in the browser

Your editor handles authorization automatically over OAuth. You approve the connection once in the browser.

<Steps>
  1. A browser tab opens to the Promptless consent page.

  2. Choose the organization to connect. The picker defaults to your active organization.

  3. Check the **Returns to** row. It shows where Promptless sends access when you approve. Promptless doesn't verify the client name, so go by this row. A local editor such as Claude Code or Cursor returns to a local address with a port, like `127.0.0.1:54321`. An app that opens through its own link scheme shows a callback like `myapp://claude.ai/cb`, and any app on your device that handles `myapp://` links receives the access. Cancel if you didn't start this connection from that editor or app.

  4. Select **Authorize as \{your email}**. Your editor stores the token and returns you to the editor.
</Steps>

<Aside type="note">
  An approved client acts with the same access as the member who approved it. It can read any task and change any suggestion in your organization, including ones other members started. Any active organization member can authorize a connection, whatever their [organization role](/docs/for-docs/security/access-and-permissions). To control what gets submitted, use your [publishing policies and relevance filtering](/docs/for-docs/tune/noise-and-relevance-filtering).
</Aside>

A token is tied to one organization. To connect a second organization, authorize again and pick that organization at consent. Your editor can hold one Promptless connection per organization.

## Approve tool calls

Your editor lists the Promptless tools when it connects. Each tool's MCP annotations mark it as read-only or as one that changes data. Your editor can auto-approve the read-only tools, so routine status checks stop prompting you each time. Tools that queue or change work ask before they run. For each tool's arguments, results, and annotation, see the [MCP tools reference](/docs/for-docs/reference/mcp-tools).

<Aside type="note">
  Your editor loads the tool list when it connects. To pick up tools Promptless added or changed since then, refresh or reconnect the `promptless` server. In Claude Code, run `/mcp` and pick **promptless** again, or start a new conversation. In Cursor, remove the `promptless` server and add it again.
</Aside>

## Answer a clarifying question

A task you started over MCP can finish by asking you one clarifying question. Your editor shows the question as it follows the task. If your editor supports MCP forms (elicitation), it shows a **Your answer** field. Otherwise, it asks in chat, and you reply in the same conversation. Promptless continues the work in a new task that carries your original request and your answer, and your editor follows that task too.

## Workflow skills

If your editor supports it, Promptless hands it step-by-step guidance for multi-step workflows that chain several [Promptless tools](/docs/for-docs/reference/mcp-tools) together. A skill adds no tools of its own. The editor decides when to load a skill, and you ask for what you want as usual.

A skill only guides the sequence. The work-changing tools a skill calls still prompt before each run, just as they do when you call them directly.

<Aside type="note">
  Skills reach your editor over the draft **Skills extension (SEP-2640)**. The MCP endpoint declares it as the `io.modelcontextprotocol/skills` capability in its `initialize` response. Many clients don't support the extension yet and show no skills. To check whether yours does, see its MCP settings or release notes. Because the extension is still a draft, its shape can change.
</Aside>

A client that doesn't support the extension, or ignores it, sees the same tools and calls them directly.

## Ask your editor

Ask in plain language, and your editor picks the tools. For example: "Document the new authentication flow in the API docs collection." Your editor starts the task, follows it in the same conversation, and reports the outcome and docs pull request link back to you.

To work through a backlog, ask for a triage pass: "Triage my open Promptless suggestions, label the P0s, and close anything we've decided against." The tools that change work still prompt before they run, so you stay in control of what changes.

For what each tool does, see the [MCP tools reference](/docs/for-docs/reference/mcp-tools).

## See your MCP tasks in the dashboard

On the [Triggers page](https://app.gopromptless.ai/triggers), a task started over MCP shows an **MCP Task** pill with a byline reading `<client name> · submitted by @<username>`. Tasks submitted with an `sk-pl-` API key show an **API Task** pill.

To find MCP-originated suggestions on the [Suggestions list](https://app.gopromptless.ai/suggestions), set the **Trigger source** filter to "API". That filter includes both MCP and API-key submissions.

## Manage and revoke your connection

Connections re-authorize automatically. The connection you approve lasts 90 days. After that, automatic refresh stops, and you approve the connection in the browser again, the way you did at setup.

To revoke a connection, remove the `promptless` server from your editor, such as from Cursor's MCP settings. For Claude, see [Reconnect or disconnect](/docs/for-docs/work-the-queue/claude#reconnect-or-disconnect). For ChatGPT, see [Reconnect or disconnect](/docs/for-docs/work-the-queue/chatgpt#reconnect-or-disconnect). The dashboard's **Editor connection (MCP)** section shows setup instructions only, so revoke from your editor or chat app.

Promptless checks your organization membership on every call, and revokes the connection if you lose active membership. Each member manages their own connection. An admin can't revoke another member's connection for them.

## Troubleshooting

For an error a tool returns, such as `task_finished` or `stale_head`, see [Tool errors](/docs/for-docs/reference/mcp-tools#tool-errors) in the MCP tools reference.

- **Denied, canceled, or expired consent**: re-run the authorize step. In Claude Code, run `/mcp` and pick **promptless** again. In Cursor, click **Needs login** again.

### Setup issues

First-run snags usually clear with a retry:

- **The browser consent tab doesn't open**: re-run the authorize step. In Claude Code, run `/mcp` and pick **promptless**. In Cursor, click **Needs login**.
- **No promptless entry under `/mcp` in Claude Code**: confirm the add command ran, then re-open the client.
- **Cursor's Needs login button doesn't respond**: remove the server and add it again.
