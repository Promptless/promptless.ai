## Overview

Mention @Promptless in a GitHub issue to turn a documentation request into a suggestion. Promptless reads the issue's title, description, and comments, decides whether the request needs a documentation update, and creates suggestions when it does.

Issue mentions fit when:

- Contributors or users open issues that ask for specific documentation improvements.
- Community members in an open-source project want to request docs updates without access to your other tools.
- Your team tracks documentation gaps as issues and wants Promptless to act on them.

The GitHub issue trigger is built in. It needs no YAML configuration and works in every repository where the Promptless GitHub App is installed.

## Before you start

- The GitHub organization that holds the repository, connected to Promptless through the Promptless GitHub App. If it isn't connected yet, [connect it](#connect-github) first.
- Your organization's Promptless setup finished on the [Configuration page](https://app.gopromptless.ai/configuration).

## Request a documentation update from an issue

<Steps>
  1. Open an issue, or go to an existing one, in a repository where the Promptless GitHub App is installed.

  2. Mention `@Promptless` in the issue's title or description, or in a comment, and describe the documentation change you want.
</Steps>

Promptless adds an eyes (👀) reaction to the issue, or to your comment, when it starts working. It then decides whether the request warrants a documentation update. If it does, Promptless creates documentation suggestions and posts the results back to the issue.

If your organization hasn't finished setting up Promptless, Promptless replies on the issue with a link to the dashboard so you can complete setup.

Suggestions from issues publish and notify according to your [policies](/docs/for-docs/reference/configuration-reference#policies), like suggestions from any other trigger.
