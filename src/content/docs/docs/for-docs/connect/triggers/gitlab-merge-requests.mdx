Promptless monitors your GitLab projects for merge requests. When a merge request opens or updates, Promptless analyzes the changes and creates documentation suggestions if needed.

## How it works

When a merge request opens or updates in a monitored project, Promptless:

1. Receives the merge request event.
2. Reads the diff, title, and description.
3. Decides whether documentation needs to change.
4. Creates documentation suggestions if it does.

<Aside type="note">
  Promptless processes merge request data in real time and doesn't store it.
</Aside>

## Configuration

Configure GitLab merge request triggers in the `triggers` section of your [Configuration page](https://app.gopromptless.ai/configuration):

```yaml
triggers:
  gitlab-mrs:
    trigger_type: gitlab_mr
    match:
      - repos:
          - acme/backend
          - acme/api
        trigger_on:
          - opened
          - merge
        trigger_directories:
          - src/
```

See the [Configuration Reference](/docs/for-docs/reference/configuration-reference#triggers) for all available options.

## Project selection

You pick from the GitLab projects whose webhook setup Promptless has verified. The **All webhook-enabled repositories** toggle selects all of them. In YAML, use `repos: all`.

If a project you expect isn't listed, check its state on the connection card. An ineligible project needs Maintainer access and a webhook first. See [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations).

A GitLab connection made before webhook verification existed shows **Webhook verification pending** on its card, and the picker can be empty until Promptless verifies its webhooks. The daily connection check does this automatically, or click **Check now** on the card. You don't need to reconnect or reinstall. Saved selections stay in your configuration, including selections whose project isn't active on the connection card.

## Webhook delivery status

On your [Configuration page](https://app.gopromptless.ai/configuration), each saved GitLab merge request trigger shows when Promptless last received any webhook from its projects, including push and comment events:

- Green: within the last 4 days.
- Yellow: 4 or more days ago.
- Red: 14 or more days ago.

A red box, or "No webhook recorded yet" while the trigger's projects have recent merge requests, means webhooks probably aren't reaching Promptless. See [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations) and the [GitLab integration FAQ](/docs/for-docs/reference/integrations/gitlab#frequently-asked-questions).

## Replay recent merge requests

When you set up a new GitLab MR trigger, enable "Replay recent MRs" to process merge requests from the last 30 days. Use the resulting suggestions to:

- Calibrate Promptless with your documentation style before going live
- Catch up on documentation that may have been missed
- See how Promptless handles your typical MR content

Your Project card shows the replay progress:

- **Processing last 30 days of MRs** with a spinner while replay runs
- **Processed recent MRs** with a checkmark when replay completes

<Aside type="note">
  Replay runs in the background. Promptless still processes new MRs immediately.
</Aside>

## Directory-specific triggers

Use the `trigger_directories` field to consider only merge requests that change files in those directories.

## Automatic PR creation

When automatic PR creation is enabled in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies), Promptless opens a PR in your documentation repository with the suggested changes.

## Source MR comments

Promptless comments on the source merge request with links to its documentation suggestions, so reviewers see proposed documentation updates alongside the code.

<Aside type="tip">
  Slack notifications follow your project's notification settings, separately from source MR comments.
</Aside>

## Request documentation via merge-request comments

To request documentation work on a merge request, tag Promptless in a comment. Promptless reviews that merge request even when its project isn't in your [triggers' repo lists](/docs/for-docs/reference/configuration-reference#triggers), if your GitLab connection can access it. GitHub [PR comments](/docs/for-docs/connect/triggers/github-prs#request-documentation-via-pr-comments) work the same way.

### How to use

Post a comment that tags `@promptless` anywhere in its text. Matching is case-insensitive. OSS projects use `@promptless-for-oss`.

```
@promptless please update the docs for this API change
```

GitLab also recognizes `/promptless` at the start of a comment line. If `/promptless` doesn't get a response, use `@promptless`.

Promptless reads mentions only in new comments. Mentions in a comment edit or in the merge request's title or description don't start documentation work.

### What happens

- On a merge request Promptless opened for your documentation, the comment revises that documentation suggestion.
- On any other merge request, the comment starts a new documentation review of that merge request.

Promptless responds whether the merge request is open, merged, or closed. A mention from an automated account, such as a CI service account, counts the same as one from a teammate.

With a personal access token, the comments and merge requests Promptless posts appear under the token owner's GitLab account. Promptless recognizes its own comments, so the owner can still tag `@promptless` to request documentation work.

### When to use

Use a comment mention when:

- The merge request predates your trigger setup.
- You want documentation for a merge request that's already merged or closed.
- The automatic trigger didn't activate.
- You want to give specific instructions about what to document.

## Comment mention acknowledgment

When you mention `@promptless` in a merge request comment, Promptless adds a 👀 reaction to show it saw the request. This works on source merge requests and on merge requests Promptless opened for your documentation.

<Aside type="note">
  The reaction appears even when Promptless decides no documentation change is needed.
</Aside>

## Configuration files and dot-directories

Promptless skips merge requests that change only dot-directories (like `.gitlab/`, `.gitlab-ci/`) or root-level dot-files (like `.gitignore`, `.gitlab-ci.yml`), which usually hold CI and tooling configuration. A merge request that also changes other files is processed normally.
