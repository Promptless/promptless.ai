## Overview

A GitLab merge request trigger starts documentation work from merge requests in the GitLab projects you monitor. When a merge request in a monitored project opens or merges, Promptless reads its code diff, title, and description. If the changes need a documentation update, Promptless creates documentation suggestions.

Promptless skips a merge request whose changes are all in dot-directories, such as `.gitlab/` and `.gitlab-ci/`, or in root-level dot-files, such as `.gitignore` and `.gitlab-ci.yml`. These files typically hold CI and tooling configuration. A merge request that changes regular source files along with dot-files gets the normal analysis.

<Aside type="note">
  Promptless processes merge request information in real time and doesn't store it. Analysis runs only when a configured trigger event occurs.
</Aside>

<Aside type="tip">
  You can also ask Promptless in Slack or Microsoft Teams to set up the trigger for you. For example, "@Promptless add a GitLab merge request trigger for my acme/backend project." See [Ask Promptless to update your configuration](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).
</Aside>

## Before you start

- An admin role in your Promptless organization, to connect GitLab and edit the [Configuration page](https://app.gopromptless.ai/configuration).
- The GitLab group that holds the projects you want to monitor, connected to Promptless. Promptless can't save a GitLab merge request trigger until it is. If the group isn't connected yet, [connect it](#connect-a-gitlab-group) first.

## Add a merge request trigger

1. On the [Configuration page](https://app.gopromptless.ai/configuration), switch to **YAML** mode.

2. In the `triggers` section, add a `gitlab_mr` trigger with a match clause for the projects you want to monitor:

   ```yaml
   triggers:
     gitlab-mrs:
       trigger_type: gitlab_mr
       match:
         - repos:
             - acme/backend
             - acme/api
           trigger_on:
             - opened
             - merge
           trigger_directories:
             - src/
   ```

3. Save the configuration.

Each match clause takes these fields:

| Field                 | Required | Description                                                                                         |
| --------------------- | -------- | --------------------------------------------------------------------------------------------------- |
| `repos`               | Yes      | The GitLab projects to monitor, or the literal `all`.                                               |
| `trigger_on`          | Yes      | The merge request events that start an analysis: `opened`, `merge`, or both.                        |
| `trigger_directories` | No       | Only merge requests that change files in these directories trigger documentation updates.           |
| `branches`            | No       | Only merge requests that target these branches trigger documentation updates. Omit it to match any. |

For every field, including project exclusions, see the [Configuration Reference](/docs/for-docs/reference/configuration-reference#triggers).

To catch up on merge requests that opened or merged before you configured the trigger, run a [backfill](/docs/for-docs/connect/triggers#backfill-suggestions) from the saved trigger. Review the first batch of suggestions to calibrate Promptless with your documentation style before you go live.

## Check webhook delivery status

Each saved GitLab merge request trigger on your [Configuration page](https://app.gopromptless.ai/configuration) shows when Promptless last received a merge request webhook from the trigger's projects. Its color shows how long ago:

| Color  | Last webhook received     |
| ------ | ------------------------- |
| Green  | Within the last 4 days    |
| Yellow | Between 4 and 14 days ago |
| Red    | 14 or more days ago       |

A red status, or "No webhook recorded yet" on a trigger whose projects have recent merge requests, means webhooks probably aren't reaching Promptless. Check [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations) and [Fix common connection problems](/docs/for-docs/reference/integrations/gitlab#fix-common-connection-problems).

## Set how Promptless publishes suggestions

Set where Promptless reports suggestions from this trigger, and how far it automates publishing, in your [policies](/docs/for-docs/reference/configuration-reference#policies):

| Option                | Policy setting                           | Effect                                                                                                                                                  |
| --------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source MR comments    | `publishing.suppress_source_pr_comments` | Posts a summary comment on the source merge request that links to its documentation suggestions. On by default; set the field to `true` to turn it off. |
| Slack notifications   | `notification.slack_channel`             | Posts suggestion notifications to a Slack channel. Turning off source MR comments doesn't affect them.                                                  |
| Automatic PR creation | `publishing.auto_create_pr`              | Opens a documentation PR for each suggestion.                                                                                                           |

With source MR comments on, reviewers see proposed documentation updates while they review the code changes.

## Request documentation via merge-request comments

To ask for documentation work on a specific merge request, tag Promptless in a comment on it. A comment mention is an explicit request. Promptless reviews that merge request even when its project isn't in any of your [triggers' repo lists](/docs/for-docs/reference/configuration-reference#triggers). Your GitLab connection only needs access to the project. GitHub supports the same request through [PR comments](/docs/for-docs/connect/triggers/github-prs#request-documentation-via-pr-comments).

Comment mentions are useful when:

- The merge request predates your trigger setup.
- You want documentation for a merge request that's already merged or closed.
- The automatic trigger didn't activate.
- You want to give specific instructions about what to document.

What Promptless does depends on the merge request you comment on:

| Merge request                                | What Promptless does                                     |
| -------------------------------------------- | -------------------------------------------------------- |
| One Promptless opened for your documentation | Revises that documentation suggestion.                   |
| Any other merge request                      | Starts a new documentation review of that merge request. |

Promptless responds to a mention whether the merge request is open, merged, or closed. A mention from an automated account, such as a CI job's service account, counts the same as one from a teammate.

### Mention Promptless in a comment

Post a new comment that tags `@promptless` anywhere in its text. Matching is case-insensitive. In OSS projects, tag `@promptless-for-oss`.

```txt
@promptless please update the docs for this API change
```

GitLab also recognizes `/promptless` at the start of a comment line, but `@promptless` is more reliable. If `/promptless` doesn't get a response, tag `@promptless`.

Promptless reads mentions in new comments only. Mentions in a comment edit or in the merge request's title or description don't start documentation work.

### Confirm Promptless saw your mention

When you tag `@promptless` in a comment on a merge request, Promptless adds a 👀 reaction to your comment. The reaction appears on both source merge requests and merge requests Promptless opened for your documentation. It shows up even when Promptless decides no documentation change is needed, so a missing suggestion doesn't mean Promptless ignored your mention.

### Respond to comments on documentation merge requests

On a merge request Promptless opened for your documentation, your organization's [comment trigger mode](/docs/for-docs/work-the-queue/reviewing-prs#comment-trigger-modes) decides which comments Promptless acts on. The modes are **Listen to all comments** and **Require a mention**. On other merge requests, Promptless acts only on comments that mention it.

In either mode, tag `@promptless` or start a line with `/promptless` to make sure Promptless acts on a comment. Mentions work in [comments from automated accounts](/docs/for-docs/work-the-queue/reviewing-prs#mentions-from-automated-accounts) too.
