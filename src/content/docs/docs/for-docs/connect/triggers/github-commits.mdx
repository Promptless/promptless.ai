A GitHub commit trigger starts documentation work from commits pushed to a branch you monitor. Use it when changes reach your default branch without a pull request, such as direct pushes, hotfixes, and emergency changes.

## How it works

When a commit is pushed to a monitored branch, Promptless reads its diff and commit message. If the change needs a documentation update, Promptless creates documentation suggestions.

The trigger requires the GitHub integration. To connect it, see the [GitHub integration](/docs/for-docs/reference/integrations/github) setup guide.

## Use cases

| Use case                 | Why a commit trigger fits                                                               |
| ------------------------ | --------------------------------------------------------------------------------------- |
| Changelog monitoring     | Updates documentation when changelog files change. Scope it with `trigger_directories`. |
| Hotfix documentation     | Catches documentation needs from emergency fixes that skip the normal PR process.       |
| Direct-to-main workflows | Covers teams that commit directly to the default branch.                                |
| Automated updates        | Starts documentation updates from commits that automated processes push.                |

## Commit triggers vs. pull request triggers

A commit trigger activates on commits pushed to a monitored branch. A [GitHub PR trigger](/docs/for-docs/connect/triggers/github-prs) activates on pull request activity. The two overlap in a standard GitHub workflow. When a pull request merges, its merge commit lands on the default branch. The commit trigger then activates along with the PR trigger's merge event.

Use a commit trigger on its own or alongside PR triggers for the same repositories:

| Setup                  | When Promptless runs                            | Comments on PRs | Choose it when                                                                                                                               |
| ---------------------- | ----------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Commit and PR triggers | While the PR is open, and again after it merges | Yes             | You want documentation feedback during review, and suggestions updated with the final merged content.                                        |
| Commit trigger only    | After changes merge to the monitored branch     | No              | PR triggers create too much notification noise. [Configure a Slack channel](#notification-channels) so you still hear about new suggestions. |

## Configuration

<Aside type="note">
  Adding, renaming, or modifying a GitHub commit trigger requires the GitHub integration to be connected first. See [Connect a provider before you add its triggers](/docs/for-docs/connect/triggers#connect-a-provider-before-you-add-its-triggers).
</Aside>

Configure GitHub commit triggers in your [Configuration page](https://app.gopromptless.ai/configuration) using the `triggers` section:

```yaml
triggers:
  main-commits:
    trigger_type: github_commit
    match:
      - repos:
          - acme/backend
          - acme/frontend
        branches:
          - main          # omit to match only the repository's default branch
        trigger_directories:
          - src/
          - lib/
```

Each match clause takes these fields:

| Field                 | Required | Description                                                                                                       |
| --------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `repos`               | Yes      | The repositories to monitor, or the literal `all`.                                                                |
| `branches`            | No       | The branches to monitor. Omit it to monitor only each repository's default branch.                                |
| `trigger_directories` | No       | Only commits that change files in these directories trigger documentation updates, such as a changelog directory. |

For every field, including repository exclusions and topic and owner filters, see the [Configuration Reference](/docs/for-docs/reference/configuration-reference#triggers).

## Publishing options

Commit triggers don't comment on PRs, so set where Promptless tells you about suggestions and how far it automates publishing. Set these in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies):

| Option                | Policy setting               | Effect                                                                                                               |
| --------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Slack notifications   | `notification.slack_channel` | Posts to a Slack channel when Promptless creates or updates suggestions.                                             |
| Automatic PR creation | `publishing.auto_create_pr`  | Opens a documentation PR for each suggestion.                                                                        |
| Auto-merge            | `publishing.auto_merge`      | Merges documentation PRs into the default branch as soon as Promptless creates them. Requires automatic PR creation. |

### Notification channels

Send suggestion notifications to a Slack channel:

```yaml
policies:
  default:
    notification:
      slack_channel: docs-updates
```

<Aside type="note">
  For a private Slack channel, invite Promptless first by tagging `@Promptless` in the channel.
</Aside>

### Auto-merge mode

Auto-merge publishes documentation PRs without human review. Use it for internal documentation, high-confidence workflows that want full automation, or changelog updates that should publish immediately.

Turn on both automatic PR creation and auto-merge in a policy rule scoped to the commit trigger:

```yaml
policies:
  rules:
    - if:
        trigger: main-commits
      then:
        publishing:
          auto_create_pr: true
          auto_merge: true
```
