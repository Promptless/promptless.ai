## Overview

A GitHub commit trigger starts documentation work from commits pushed to a branch you monitor. Promptless reads each commit's diff and message, and creates documentation suggestions when the change needs a documentation update. Add one when changes reach your default branch without a pull request:

| Use case                 | Why a commit trigger fits                                                               |
| ------------------------ | --------------------------------------------------------------------------------------- |
| Changelog monitoring     | Updates documentation when changelog files change. Scope it with `trigger_directories`. |
| Hotfix documentation     | Catches documentation needs from emergency fixes that skip the normal PR process.       |
| Direct-to-main workflows | Covers teams that commit directly to the default branch.                                |
| Automated updates        | Starts documentation updates from commits that automated processes push.                |

This guide covers choosing between commit and PR triggers, adding the trigger, and setting how Promptless notifies you and publishes its suggestions.

<Aside type="tip">
  You can also ask Promptless in Slack or Microsoft Teams to set up the trigger for you. For example, "@Promptless add a commit trigger watching the main branch of my acme/api repo." See [Ask Promptless to update your configuration](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).
</Aside>

## Choose commit triggers, PR triggers, or both

A commit trigger activates on commits pushed to a monitored branch. A [GitHub PR trigger](/docs/for-docs/connect/triggers/github-prs) activates on pull request activity. The two overlap in a standard GitHub workflow. When a pull request merges, its merge commit lands on the default branch. The commit trigger then activates along with the PR trigger's merge event.

Use a commit trigger on its own or alongside PR triggers for the same repositories:

| Setup                  | When Promptless runs                            | Comments on PRs | Choose it when                                                                                                                                                 |
| ---------------------- | ----------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Commit and PR triggers | While the PR is open, and again after it merges | Yes             | You want documentation feedback during review, and suggestions updated with the final merged content.                                                          |
| Commit trigger only    | After changes merge to the monitored branch     | No              | PR triggers create too much notification noise. [Send notifications to a Slack channel](#send-notifications-to-a-slack-channel) to hear about new suggestions. |

## Add a commit trigger

<Steps>
  1. On the **Triggers** tab of the [Configuration page](https://app.gopromptless.ai/configuration), select **Add an automatic or scheduled trigger**, and then select **GitHub commits**.

  2. Under **Which repositories?**, select **All repositories**, or select **Specific repos** and pick the repositories to watch.

  3. Under **Which branches?**, add the branches to watch. Leave it empty to watch only each repository's default branch.

  4. Optional. Open **More filters (optional)** to narrow the trigger by folder, GitHub topic, or repository owner, or to skip specific repositories. To watch only commits that change specific folders, such as a changelog directory, add each folder under **Only when files in these folders change**.

  5. Select **Add trigger**.
</Steps>

To add the trigger in YAML instead:

<Steps>
  1. On the [Configuration page](https://app.gopromptless.ai/configuration), switch to **YAML** mode.

  2. In the `triggers` section, add a `github_commit` trigger with a match clause for the repositories you want to monitor:

     ```yaml
     triggers:
       main-commits:
         trigger_type: github_commit
         match:
           - repos:
               - acme/backend
               - acme/frontend
             branches:
               - main          # omit to match only the repository's default branch
             trigger_directories:
               - src/
               - lib/
     ```

  3. Save the configuration.
</Steps>

Each match clause takes these fields:

| Field                 | Required | Description                                                                                                       |
| --------------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `repos`               | Yes      | The repositories to monitor, or the literal `all`.                                                                |
| `branches`            | No       | The branches to monitor. Omit it to monitor only each repository's default branch.                                |
| `trigger_directories` | No       | Only commits that change files in these directories trigger documentation updates, such as a changelog directory. |

For every field, including repository exclusions and topic and owner filters, see the [Configuration Reference](/docs/for-docs/reference/configuration-reference#triggers).

## Set how Promptless publishes suggestions

Commit triggers don't comment on PRs, so tell Promptless where to report suggestions and how far to automate publishing. Set these options in your [publishing policies](/docs/for-docs/reference/configuration-reference#policies):

| Option                | Policy setting               | Effect                                                                                                               |
| --------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Slack notifications   | `notification.slack_channel` | Posts to a Slack channel when Promptless creates or updates suggestions.                                             |
| Automatic PR creation | `publishing.auto_create_pr`  | Opens a documentation PR for each suggestion.                                                                        |
| Auto-merge            | `publishing.auto_merge`      | Merges documentation PRs into the default branch as soon as Promptless creates them. Requires automatic PR creation. |

### Send notifications to a Slack channel

For a private Slack channel, first invite Promptless by tagging `@Promptless` in the channel. Then set the channel in a policy:

```yaml
policies:
  default:
    notification:
      slack_channel: docs-updates
```

### Turn on auto-merge mode

Auto-merge publishes documentation PRs without human review. Use it for internal documentation, high-confidence workflows that want full automation, or changelog updates that should publish immediately.

Turn on both automatic PR creation and auto-merge in a policy rule scoped to the commit trigger:

```yaml
policies:
  rules:
    - if:
        trigger: main-commits
      then:
        publishing:
          auto_create_pr: true
          auto_merge: true
```
