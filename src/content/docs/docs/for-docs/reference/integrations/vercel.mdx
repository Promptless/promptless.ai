**Used for: Monitoring**

Promptless is a documentation automation product, and this page covers connecting it to Vercel as a read-only monitoring source for a Starport documentation site. Connecting Vercel gives Promptless read-only access to the deployment status of your [Starport](/docs/for-docs/starport) documentation site. Starport is the managed docs-as-code framework Promptless runs on hosting you own, such as Vercel. Promptless reads whether your site built and published, then shows that status in the dashboard. It never deploys and never changes anything in your Vercel account.

This integration applies only to a Promptless-managed Starport documentation site. It is additive: Starport works without it, and connecting it adds deployment-status visibility for that site.

This is the integration behind the Promptless listing on the Vercel Marketplace, so you can install it from Vercel.

## Installation

Connecting Vercel requires Promptless organization-admin access; organization administrators manage every connected integration. Set up this connection once for your organization, not per site.

1. Click "Connect Vercel" from the [integrations page](https://app.gopromptless.ai/integrations).
2. On Vercel, review and approve the request to give Promptless read-only access.
3. Back on the integrations page, verify that Vercel shows as connected.

## Authentication model

Vercel connects through OAuth, and Promptless holds read-only access. Promptless reads your deployment status through read-only API calls. It also reads project and domain metadata to identify which Vercel project and domain host your Starport site. It never deploys, and it never changes your projects, domains, or environment variables.

## What you can do with Vercel

Promptless reads the recent production deployment status of your Starport site, so you can see whether it built and published. It shows that status in the dashboard.

The [connection health](/docs/for-docs/connect/connection-health) label on the Vercel integration card is separate. It reflects whether the connection itself is authenticated and reachable, not whether a given deployment succeeded: the daily health check verifies only the connection.

For the full set of read-only connections that monitor a Starport site, see [Starport connections](/docs/for-docs/starport/connections). To learn how Starport builds and publishes your site, see [Starport](/docs/for-docs/starport).

<Aside type="note" title="Monitoring is separate from your Starport deploy">
  Your Starport site's own deploy to Vercel runs in CI. That deploy uses the credentials you set in [Starport configuration](/docs/for-docs/starport/configuring-starport#configure-deploy-settings). This monitoring connection reads deployment status and stays separate from it.
</Aside>

## Reconnect Vercel

If the Vercel integration shows a **Needs reconnect** health state on the [integrations page](https://app.gopromptless.ai/integrations), disconnect and connect again to restore it. Click **Disconnect Vercel**, then click **Connect Vercel** and complete the OAuth authorization. Promptless then resumes reading your deployment status.

A **Temporary outage** state needs no action. Promptless rechecks on its own and returns the card to **Connected** once the check succeeds.
