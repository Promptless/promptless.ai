**Used for: Triggers, Context, and Publishing**

Promptless uses a GitLab **access token** to read merge requests, repository files, and project metadata, and to publish documentation. The token can be a group access token or a personal access token with the `api` scope. GitLab sends **webhooks** to Promptless when merge requests change. One group connection covers triggers, context, and publishing, on gitlab.com and self-hosted GitLab.

## Installation

Create an access token in GitLab, then connect it in Promptless.

<Steps>
  1. **Create a GitLab access token with the `api` scope.** Use either token type:

     - Group access token: in your group, go to **Settings > Access Tokens** and click **Add new token**. This requires the group Owner role.
     - Personal access token: open your avatar menu and go to **Edit profile > Access > Personal access tokens**.

     Name the token (for example, "Promptless"), set an expiration date (maximum one year), and select the **`api`** scope. Copy the token when you create it. GitLab shows it only once. See [GitLab's access token documentation](https://docs.gitlab.com/security/tokens/).

  2. **Open the [Integrations](https://app.gopromptless.ai/integrations) page** in the Promptless dashboard.

  3. **Start the GitLab connection.** For gitlab.com, click **Connect** on the **Connect GitLab** tile. For a self-hosted instance, use the **Connect self-hosted GitLab** tile and enter the **Instance hostname** without `https://` or a path (for example, `gitlab.acme.com`).

  4. **Enter the group path and paste the token.** In **Group path**, enter the group's full path (for example, `acme/platform`). Paste the token into **Access token**, then click **Connect**.

     <img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/gitlab-connect-modal-aeb67dd0.png" alt="Connect GitLab modal with Group path and Access token fields and a Connect button" />
</Steps>

<Aside type="caution" title="Required to connect">
  Promptless checks for the **`api`** scope when you connect and rejects a token without it. Promptless installs webhooks only on projects where the token has the **Maintainer** role. See [Token scope considerations](#token-scope-considerations).
</Aside>

<Aside type="note" title="Connect multiple GitLab groups">
  Each connection covers one group and its subgroups. To add another group, click **Connect GitLab** (or **Connect self-hosted GitLab**) again and repeat the steps with that group's token. All connected groups stay active, including nested groups and groups on different GitLab instances.
</Aside>

## Connected groups

Each connected group has its own card on the [Integrations](https://app.gopromptless.ai/integrations) page, titled `GitLab (gitlab.com)` or `GitLab · <host>`. The card shows `Host:` and `Group:` lines and lists the group's projects alphabetically by full path (for example, `promptless-engineers/<repo>`).

The card counts projects in each state:

- **Visible**: the token can see the project.
- **Webhook-eligible**: the token has Maintainer access, so Promptless can install a webhook.
- **Active**: a webhook is installed and confirmed.
- **Ineligible**: the token is below Maintainer, so Promptless doesn't install a webhook.
- **Failed**: Promptless couldn't install the webhook. Retry with the **Automatic webhooks** control, or check the token's role on that project.

A summary such as "8 of 12 project webhooks active" means 8 of the 12 webhook-eligible projects have an active webhook. The card lists visible projects below Maintainer separately as ineligible.

To pick up projects added to the group after you connect, click **Refresh** on the card.

## Project setup

### Repository access

When you set up a GitLab trigger, select the projects Promptless monitors. The picker lists projects that have a confirmed webhook. See [Project selection](/docs/for-docs/connect/triggers/gitlab-merge-requests#project-selection).

### Directory-specific triggers

To trigger documentation updates only for changes in certain directories, such as API code, and ignore tooling or test changes:

1. In your project configuration, select the GitLab project.
2. Under **Advanced Options**, enable **Directory-Specific Triggers**.
3. Enter the directories to monitor, separated by commas (for example, `src/api, docs/reference`).

## Merge request link resolution

When you share a gitlab.com merge request link in Slack or another trigger, Promptless fetches:

- MR metadata (title, state, source and target branches, author)
- Discussion comments with file positions and resolved state
- The full diff

<Aside type="note">
  Merge request link resolution works only for gitlab.com.
</Aside>

## Source code reading

When it processes a merge request or researches a documentation update, Promptless reads source files from your GitLab projects with the GitLab CLI (`glab`). This gives it details a diff doesn't show, such as code in files the merge request didn't change.

<Aside type="note">
  Source code reading works only for gitlab.com projects.
</Aside>

## Publishing documentation to GitLab

A GitLab project can also be a doc collection, where Promptless publishes documentation updates. Promptless clones the project, edits files on a new branch, pushes the branch, and opens a merge request for you to review.

Publishing uses the same `api`-scoped token. Promptless writes only to the projects you set up as doc collections.

GitLab doc collections work on gitlab.com and self-hosted GitLab. The project picker lists connected projects from every instance. For a self-hosted project, enter the hostname in the **GitLab host** field. Leave it blank for gitlab.com. See [GitLab projects](/docs/for-docs/connect/doc-locations/gitlab-projects) for setup and [the configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for the `platform: gitlab` and `host` fields.

GitLab has no draft flag at creation time, so Promptless marks a draft merge request with a `Draft:` title prefix.

On GitLab, auto-merge attempts the merge immediately, without waiting for a pipeline. See [Automatic merge request creation](/docs/for-docs/connect/doc-locations/gitlab-projects#automatic-merge-request-creation) before you enable it.

## Authentication model

The GitLab integration authenticates with a group access token or personal access token that has the `api` scope. Feature support by instance:

| Feature                       | gitlab.com | Self-hosted GitLab |
| ----------------------------- | ---------- | ------------------ |
| Webhook triggers              | Yes        | Yes                |
| Publishing (doc collections)  | Yes        | Yes                |
| Merge request link resolution | Yes        | No                 |
| Source code reading           | Yes        | No                 |

### Token scope considerations

Connecting requires only the **`api`** scope. The scope is write-capable: it lets Promptless read project content, push branches, and open merge requests. Promptless checks for it when you connect, so you can fix the token right away.

Promptless checks access per project, so a token with a low group role still connects. A token's direct project memberships can grant more access than its group role.

Merge requests and comments Promptless creates appear under the token's identity. A group access token is a GitLab bot, and Promptless gives it a bot avatar. With a personal access token, they appear under the owner's GitLab account. The owner can still tag `@promptless` in their own comments to request documentation work. For a team rollout, use a group access token: your organization owns it, so it keeps working when people leave. A personal access token works only while its owner keeps access.

Promptless installs merge-request webhooks on each project where the token has the **Maintainer** role, including through direct project membership. Projects below Maintainer stay available for context and publishing. To get triggers from one, add a webhook in GitLab by hand, which also requires the Maintainer role on that project. If you don't have it, ask a project Maintainer or Owner. To install webhooks on every eligible project at once, use the **Automatic webhooks** control on the connection's card.

To limit what Promptless can reach:

- **Token reach**: Scope a group access token to a group or subgroup that holds only your documentation projects. Do this only when your trigger and context-source projects live in that group too, because the token can't reach projects outside it. A personal access token reaches every project its owner can access, so limit the owner's memberships or use a dedicated account.
- **Doc collections and path scope**: Promptless writes only to projects you configure as doc collections, and only to files within each collection's path scope.

## Webhook management

Promptless installs webhooks on the projects where the token has Maintainer access. The webhooks notify Promptless when:

- A merge request is created or updated.
- A merge-request comment mentions Promptless. See [Request documentation via merge-request comments](/docs/for-docs/connect/triggers/gitlab-merge-requests#request-documentation-via-merge-request-comments).

The **Automatic webhooks** control on the connection's card reinstalls webhooks on those projects.

## Usage

1. When a merge request opens or updates in a monitored project, Promptless analyzes it.
2. If documentation needs to change, Promptless drafts the change.
3. Promptless comments on the merge request with a link to the suggested changes.
4. Review and approve the suggestion in the Promptless dashboard.

See [Triggers](/docs/for-docs/connect/triggers) for how triggers work in general.

## Frequently asked questions

<details>
  <summary>Promptless rejects my token when I connect. Why?</summary>

  The token is missing the `api` scope. A `read_api` token can't open merge requests or install webhooks. Create a token with the `api` scope and connect again.
</details>

<details>
  <summary>My group connected, but no merge request triggers arrive. Why?</summary>

  Check the project's state on the connection card. If the project is ineligible, the token is below Maintainer on it, so Promptless can't install a webhook. Raise the token's role to Maintainer in GitLab, or add the webhook by hand. See [Token scope considerations](#token-scope-considerations).
</details>

<details>
  <summary>A project I added to my group doesn't appear under the connected group. How do I fix it?</summary>

  Promptless syncs the project list when you connect a group. Open the group's card on the [Integrations](https://app.gopromptless.ai/integrations) page and click **Refresh**.
</details>
