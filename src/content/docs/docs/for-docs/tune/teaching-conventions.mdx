Feedback on a Promptless suggestion does two things at once. It fixes the suggestion in front of you. When you save it, it also teaches Promptless a durable convention that it applies to every future suggestion. You can give feedback from the Promptless dashboard in four ways: request changes, inline feedback, overall comments, and close feedback. You can also give it directly in a GitHub PR comment. Every method lets you request changes on the suggestion you're reviewing. Some also let you save that preference so Promptless applies it to future suggestions.

See [Giving feedback to Promptless](/docs/for-docs/work-the-queue/giving-feedback) to pick the method that fits your situation.

## 1. Request changes

Use the **Request Changes** button at the top of any suggestion to request updates. Provide multiple pieces of feedback at once, and Promptless will address them all together.

<img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/request-changes-button-7923b98a.png" alt="Request Changes button with text field and example suggestions" />

The interface includes common examples to get you started:

- "Put X file's content as a section in Y file instead of making it its own file"
- "Make the tone more conversational, and do that for all future suggestions too"
- "I always want changelog entries in their own suggestion. Please move"

Click **Submit Request** to process all your feedback.

## 2. Dashboard inline feedback

Select text in a file, or select a line number to select the whole line. Then select **Add comment or request changes**, or press ⌘M (Ctrl+M on Windows and Linux). If you've edited the file, save your edits first.

Leave **Send to Promptless** checked to have Promptless act on your comment. Clear it and Promptless won't act on the comment. To bring in a teammate, [mention them in the comment](/docs/for-docs/work-the-queue/web-interface#mention-a-teammate-in-a-comment).

Once the suggestion has a docs PR, your inline comments and replies are also posted to the PR. This includes ones you didn't send to Promptless. Replies left on the PR appear in the dashboard thread. If a later revision rewrites the lines a published comment is on, the comment moves to the replacement lines. It keeps a label with its original line. A comment that can't be matched to the current text appears above the file's diff under **Discussions without a current line**.

## 3. Overall comments

Leave general feedback about a suggestion without targeting a specific file. This is useful for high-level guidance or when your feedback applies to the entire suggestion.

<img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/overall-comments-section-d68544e8.png" alt="The overall comments section with a text field and feedback options" />

Like dashboard inline feedback, you can check **Send to Promptless** to queue the feedback. To pull a human teammate into the discussion, [mention them in the comment](/docs/for-docs/work-the-queue/web-interface#mention-a-teammate-in-a-comment). A mention notifies that person. Checking **Send to Promptless** teaches Promptless a convention, independently of any mention.

## 4. Close suggestion feedback

When closing a suggestion, provide feedback about why you're rejecting it. This helps Promptless improve future suggestions.

<img src="https://promptless-customer-doc-assets.s3.us-east-2.amazonaws.com/docs-images/org_3DaVKUzHgjyjaODgCPaDmjXezqp/close-suggestion-feedback-7f0b6b1d.png" alt="Close suggestion dialog with reason checkboxes and optional feedback field" />

Select one or more reasons:

- "I copied this change into my docs editor"
- "This change is incorrect"
- "This change is too insignificant"
- "This change was covered in another Promptless suggestion"
- "This is already in my docs"
- "This change is self-explanatory and doesn't need docs"

You can also provide additional context in the feedback field. Check "Remember this feedback for future suggestions" to save your preferences.

## 5. GitHub PR comments

After Promptless opens a documentation PR, you can leave feedback directly in GitHub. Your comments there also appear in the dashboard. Tag @Promptless in any line comment to request changes.

<Aside type="note">
  You can also @mention Promptless in comments on source code PRs to request documentation updates. See [Request documentation via PR comments](/docs/for-docs/connect/triggers/github-prs#request-documentation-via-pr-comments) for details.
</Aside>

Promptless reads all previous comments in the thread to understand context. You can give brief instructions like "same change here" or "apply this to the other sections too."

<img src="https://promptless-customer-doc-assets.s3.amazonaws.com/docs-images/org_2lvkgU9erOFxYhtEVVC0ymPrPdF/github-pr-comment-feedback-b0dd5abf.png" alt="GitHub PR comment showing feedback with @Promptless mention" />

## How feedback improves future suggestions

Every piece of feedback you submit helps Promptless learn your preferences. When you request changes, reject suggestions with explanations, or edit proposed content, Promptless updates its understanding of your documentation standards, writing style, and content preferences.
