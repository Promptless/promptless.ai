## Overview

Environment variables store credentials, API keys, and configuration values that Promptless uses when it works with your systems. The most common use is login credentials for [Promptless Capture](/docs/for-docs/get-the-most-out/screenshots), so Promptless can sign in to your application and capture product screenshots. Custom tasks, such as [turning docs analytics into doc-gap suggestions](/docs/for-docs/get-the-most-out/teach-promptless-a-custom-task/analytics-docs-gaps), read API credentials the same way.

Promptless sees each variable's name, so use a name that says what the value is for, such as `TEST_ACCOUNT_USER`, `QA_USERNAME`, or `STAGING_LOGIN_EMAIL`. Mark passwords, API keys, and other sensitive values as secrets.

## Before you start

- An admin role in your Promptless organization. Only organization admins can view and manage environment variables.
- For screenshot credentials, a dedicated test or service account. See [Keep secrets secure](#keep-secrets-secure).

## Add an environment variable

<Steps>
  1. In the Promptless dashboard, open **Settings** and select [**Agent Env Vars**](https://app.gopromptless.ai/settings/env-vars).

  2. In the **Add Variable** form, enter a **Key Name**. Key names use uppercase letters, numbers, and underscores, up to 100 characters. The form converts the letters you type to uppercase.

  3. Enter the **Value**.

  4. If the value is a password, API key, or other sensitive value, turn on the **Secret** toggle. The **Value** field then masks what you type.

  5. For a secret, select its **Credential use** and enter the destination fields for it. See [Set where Promptless can use a secret](#set-where-promptless-can-use-a-secret).

  6. Select **Add Variable**. The variable appears in the table above the form.
</Steps>

## Keep secrets secure

After you save a secret, the dashboard hides its value, and no one can view it again. Promptless also redacts secret values from the records it logs, stores, and transmits. See [How Promptless protects secrets and sensitive data](/docs/for-docs/security/secrets-and-sensitive-data#credential-redaction).

  Store credentials for dedicated test or service accounts, not personal accounts. Screenshots then contain no personal data, and results stay consistent.
</Aside>

## Set where Promptless can use a secret

Credential protection keeps secret values away from the agent. When credential protection is enabled, the agent gets a placeholder in place of each secret. Promptless puts the real value only into the request field you approve, in requests to the HTTPS destination you set. A placeholder that the agent prints or sends anywhere else contains no credential.

Each secret's **Credential use** setting records that destination and field. Under credential protection, Promptless can't start documentation work while any secret has no **Credential use** setting, so set one for every secret. Save values that don't need protection, such as usernames and login URLs, as ordinary variables.

Select the **Credential use** that matches how the service receives the secret:

| Credential use                    | Use it for                                                       | Fields to enter                                                       |
| --------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Bearer token**                  | A token the API reads from an `Authorization: Bearer` header     | **HTTPS destination**                                                 |
| **API key in a header**           | An API key the service reads from a named header                 | **HTTPS destination**, **Header name**, and an optional **Header prefix** |
| **Basic authentication password** | A password for HTTP Basic authentication                         | **HTTPS destination** and **Username**                                |
| **Browser password (form field)** | A password that a login form submits, such as a test-account password | **Login submission URL** and **Password field name**              |
| **Browser password (JSON field)** | A password that a login page submits in a JSON body              | **Login submission URL** and **JSON field pointer**, such as `/password` |

Enter destinations in these forms:

- **HTTPS destination** is the service's host only, such as `https://api.example.com`. Leave out the path, port, query, and username. The secret works on every path of that host. To limit it to one path, expand **Request restrictions** and enter a **Request path**.
- **Login submission URL** is the HTTPS URL and exact path that receive the login request, such as `https://app.yourcompany.com/login`. It can differ from the address of the login page. To find it, log in once with your browser's developer tools open and read the URL of the request that sends the password.
- **HTTP methods**, under **Request restrictions**, lists the uppercase methods separated by commas, such as `GET, POST`. Browser passwords start with `POST`, and other credential uses start with all common methods.

To set **Credential use** for a secret that you already saved, update the secret and leave the **Value** field empty. See [Update or delete a variable](#update-or-delete-a-variable).

## Example: Screenshot capture credentials

For [Promptless Capture](/docs/for-docs/get-the-most-out/screenshots), add these variables so Promptless can log in to your application:

| Variable            | Example value                       | Secret |
| ------------------- | ----------------------------------- | ------ |
| `TEST_ACCOUNT_URL`  | `https://app.yourcompany.com/login` | No     |
| `TEST_ACCOUNT_USER` | `qa-screenshots@yourcompany.com`    | No     |
| `TEST_ACCOUNT_PASS` | `(your password)`                   | Yes    |

For `TEST_ACCOUNT_PASS`, select **Browser password (form field)** as its **Credential use**. Enter the URL that your login form submits to as the **Login submission URL**, and the form's password field name, such as `password`.

<Aside type="tip">
  Give the test account access to every feature you want documented, including features that need specific permissions or plan tiers.
</Aside>

## Update or delete a variable

You can change a variable's value and a secret's **Credential use**. You can't change a key name or whether a variable is a secret. To change either, delete the variable and add it again.

To change a variable:

<Steps>
  1. In the variable's row, select **Update**.

  2. To change the value, enter the whole new value. To keep the saved value, leave the field empty.

  3. For a secret, change its **Credential use** or destination fields as needed.

  4. Select **Save**.
</Steps>

To delete a variable:

<Steps>
  1. In the variable's row, select **Delete**.

  2. Select **Confirm**.
</Steps>

Promptless removes the variable, and the agent can no longer use it.

When credential protection is enabled, changing or deleting a secret stops your organization's running documentation work. New work uses the saved settings. If Promptless can't stop all of that work, the page shows a warning. Contact [help@gopromptless.ai](mailto\:help@gopromptless.ai) to stop the remaining work.
