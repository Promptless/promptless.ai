## Overview

Teams that run more than one live version of their documentation need each change to reach the version it belongs to. Teams commonly version docs in one of two ways: each version on its own branch, or every version in its own directory on one branch. Promptless works with both, and models versions as the branches or directories your docs already use. This guide shows how to route changes under each model, and how to steer directory-based routing with your Knowledge Base.

<Aside type="tip">
  You can set this up by hand as this page describes, or ask Promptless in Slack or Microsoft Teams to do it for you. For example, "@Promptless set my acme/docs collection default branch to v2 and only trigger on PRs targeting v2." See [Ask Promptless to update your configuration](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).
</Aside>

## Before you start

- An admin role in your Promptless organization, to edit the [Configuration page](https://app.gopromptless.ai/configuration) and the Agent Knowledge Base.
- Your docs repository connected as a doc collection. See [GitHub repos](/docs/for-docs/connect/doc-locations/github-repos).

## Route versions on separate branches

When each version lives on its own branch, point the doc collection at a version branch. Then scope your triggers to the version branches you care about:

<Steps>
  1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), expand the doc collection, then expand **More filters (optional)**.

  2. Set **Default branch** to the branch where a version's documentation lives. Promptless opens its pull requests against this branch. Without it, Promptless targets the repository's default branch.

  3. Select **Save changes**.

  4. On the **Triggers** tab, open a GitHub pull requests trigger and expand **More filters (optional)**.

  5. In **Only pull requests targeting these branches**, list the version branches to watch. A change to one version then starts no documentation work for another. For a GitHub commits trigger, list the branches in **Which branches?** instead. Left empty, **Which branches?** watches only the default branch.

  6. Select **Save changes**.
</Steps>

In `promptless.yaml`, these settings are the doc collection's `default_branch` field and the trigger's `branches` field. See the [configuration reference](/docs/for-docs/reference/configuration-reference#triggers).

When a change comes from a non-default branch, Promptless opens the suggestion against the branch the change came from. A change that lands on a version branch updates that version's docs. While a suggestion is open, Promptless keeps its branch synced with its base branch, so the suggestion builds on the latest documentation.

## Route versions in separate directories

Some frameworks, such as Docusaurus and Starlight, keep every version on one branch, each in its own directory. Under this model, routing decides which directory a change lands in.

Within one collection, Promptless picks the version directory to edit by relevance, reasoning from the change and its context. No configuration field maps a source change to a target version directory. Each repository can have at most one doc collection, so all of a repository's version directories share one collection. If your versions live in separate repositories instead, see [Route changes across multiple repos](/docs/for-docs/scale/multi-repo-routing).

You steer directory targeting with path scope and with [Knowledge Base instructions](#steer-version-routing-in-your-knowledge-base). To limit which version directories Promptless can modify:

<Steps>
  1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), expand the doc collection, then expand **More filters (optional)**.

  2. In **Only watch these folders**, list each directory Promptless may modify, such as `versioned_docs/version-2.0/`. Path scope is include-only, so to keep Promptless out of a directory, list only the directories you want it to change.

  3. Select **Save changes**.
</Steps>

In `promptless.yaml`, path scope is the doc collection's `filter` field. See [Path scope](/docs/for-docs/connect/doc-locations/github-repos#path-scope-documentation-directories).

The **Only when files in these folders change** trigger filter (`trigger_directories`) works on the source side. It sets which directories must change to start documentation work, and it doesn't choose the destination version directory.

Before you approve a suggestion, check its file changes to confirm it landed in the right version directory.

## Steer version routing in your Knowledge Base

Because directory targeting is relevance-based, `PROMPTLESS.md` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base) is your main lever. Tell Promptless which directory holds the current version and which directories hold frozen releases, so it edits the right one. For example:

- "In `acme/docs`, the current version lives in `docs/`. Older versions in `versioned_docs/` are frozen. Leave them alone unless I say otherwise."
- "Apply changes to the latest version directory, `versioned_docs/version-3.0/`. Don't touch released version directories."
- "When both the current and a supported LTS version are affected, update `docs/` and `versioned_docs/version-2.0/` and note the LTS edit in the suggestion."

For the steps to edit `PROMPTLESS.md`, see [Set per-collection preferences in your Knowledge Base](/docs/for-docs/scale/multi-repo-routing#set-per-collection-preferences-in-your-knowledge-base).
