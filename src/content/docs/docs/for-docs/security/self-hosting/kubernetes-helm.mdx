## Overview

Use this guide to install self-hosted Promptless on an AWS EKS cluster with the Promptless Helm chart. It also covers verifying the installation and keeping it up to date. If you're still deciding whether to self-host, start with the [self-hosting overview](/docs/for-docs/security/self-hosting). You configure the whole deployment through `values.yaml`, and you don't edit the Helm chart itself.

The following diagram shows a typical deployment on EKS with Bedrock, a self-hosted GitHub Enterprise instance, and Slack:

In this architecture, all data stays within your AWS VPC, and VPC endpoints keep traffic to AWS services off the internet. The Kubernetes deployments scale with demand and connect directly to your self-hosted GitHub and Slack. The architecture supports SOC 2, GDPR, HIPAA, and FedRAMP requirements.

## Before you start

Install `kubectl`, `helm`, and `aws-cli` on your local machine. Then make sure you have the following infrastructure.

### Infrastructure requirements

<details>
  <summary>AWS account and EKS cluster</summary>

  - AWS account with an EKS cluster, version 1.27 or higher
  - IAM Roles for Service Accounts (IRSA) enabled
  - Node groups configured, including GPU nodes if you use local LLMs
</details>

<details>
  <summary>Database services</summary>

  - RDS PostgreSQL instance. Aurora PostgreSQL is recommended.
</details>

<details>
  <summary>Storage and networking</summary>

  - S3 bucket for document storage, such as `promptless-doc-store`
  - Route 53 hosted zone for your domain, such as `promptless.corp.com`
  - VPC endpoints for AWS services: STS, Bedrock, S3, and Secrets Manager, plus GitHub Enterprise if applicable
</details>

### IAM roles

Create these IAM roles with scoped policies:

- `promptless-api`: Access to Bedrock, S3, and Secrets Manager
- `promptless-worker`: Background job processing permissions
- `promptless-dashboard`: Web interface permissions

<Aside type="tip">
  Promptless can provide Terraform modules to provision the baseline infrastructure. For infrastructure templates and IAM policy examples, email [help@gopromptless.ai](mailto\:help@gopromptless.ai).
</Aside>

## Install Promptless

Install Promptless on your Kubernetes cluster:

<Steps>
  1. Provision the infrastructure listed in [Before you start](#before-you-start). Use the Terraform modules Promptless provides, or create the resources by hand.

  2. Choose a container image strategy:

     - **Option A: Direct pull (recommended).** EKS pulls images directly from the public registry at `public.ecr.aws/promptless/*`. No additional configuration is needed.
     - **Option B: Private registry.** Import the images to your private ECR, then set the registry in `values.yaml`:

       ```yaml title="values.yaml"
       image:
         registry: <account-id>.dkr.ecr.<region>.amazonaws.com
       ```

  3. Create the `promptless` namespace and a Kubernetes secret that holds your database credentials and other sensitive configuration:

     ```bash
     kubectl create namespace promptless
     kubectl create secret generic promptless-secrets \
       --namespace promptless \
       --from-literal=POSTGRES_URL="postgresql://<db-user>:<db-password>@<db-host>:5432/promptless" \
       --from-literal=JWT_SECRET="<jwt-secret-key>" \
       --from-literal=OIDC_CLIENT_SECRET="<oidc-client-secret>"
     ```

  4. Create a `values.yaml` file with your deployment configuration:

     ```yaml title="values.yaml"
     global:
       domain: promptless.corp.acme.com

     auth:
       provider: oidc
       oidcIssuerURL: https://sso.acme.com

     llm:
       provider: bedrock
       model: anthropic.claude-3-sonnet-20240229-v1:0

     observability:
       mode: cloudwatch

     integrations:
       github:
         enabled: true
         apiBaseURL: https://github.acme.com/api/v3

     # Resource configuration
     api:
       replicas: 2
       resources:
         requests:
           memory: "512Mi"
           cpu: "250m"
         limits:
           memory: "1Gi"
           cpu: "500m"
     ```

     <details>
       <summary>Configuration options</summary>

       Authentication providers (`auth.provider`):

       - `oidc`: OpenID Connect, recommended for enterprise
       - `saml`: SAML 2.0
       - `oauth`: OAuth 2.0 with various providers

       LLM providers (`llm.provider`):

       - `bedrock`: AWS Bedrock, recommended
       - `openai`: OpenAI API
       - `anthropic`: Anthropic Claude API
       - `local`: Self-hosted models

       Observability (`observability.mode`):

       - `cloudwatch`: AWS CloudWatch
       - `datadog`: DataDog
       - `prometheus`: Prometheus and Grafana
     </details>

  5. If cert-manager isn't already installed in the cluster, install it:

     ```bash
     helm repo add jetstack https://charts.jetstack.io
     helm install cert-manager jetstack/cert-manager \
       --namespace cert-manager \
       --create-namespace \
       --set installCRDs=true
     ```

  6. Add the Promptless Helm repository and install the chart:

     ```bash
     helm repo add promptless https://charts.promptless.com
     helm repo update
     helm upgrade --install promptless promptless/server \
       --namespace promptless \
       --create-namespace \
       -f values.yaml
     ```

     The installation typically takes 3 to 5 minutes. To watch the pods start, run:

     ```bash
     kubectl get pods -n promptless -w
     ```

  7. Verify the deployment. Check pod status, the API logs for the database migrations, and the service endpoints:

     ```bash
     kubectl get pods -n promptless
     kubectl logs -l app=promptless-api -n promptless
     kubectl get services -n promptless
     ```

     Confirm that:

     - All pods are running and ready.
     - The database migrations completed.
     - The services are accessible.
     - The SSL certificates are issued.

  8. Grant users access to Promptless through your identity provider's group mapping, as in this example:

     ```yaml title="Example IdP configuration"
     auth:
       provider: oidc
       oidcIssuerURL: https://sso.acme.com
       groupMappings:
         - idpGroup: "promptless-admins"
           role: "admin"
         - idpGroup: "promptless-users"
           role: "user"
     ```

  9. Test that users can sign in to Promptless through your identity provider.

  10. Test documentation generation:

      1. Go to your Promptless domain to open the dashboard.
      2. Set up a test project with integrations.
      3. In the dashboard, trigger a test ingestion to generate documentation.
      4. In the S3 bucket, check for the generated assets.
      5. Confirm that the LLM integration's Bedrock calls succeed.
      6. In CloudWatch logs, check for errors.
</Steps>

When documentation generation completes, your installation is ready for production use.

## Customize the configuration

### Environment variables

These environment variables customize the deployment:

| Variable       | Type   | Required | Description                                               |
| -------------- | ------ | -------- | --------------------------------------------------------- |
| `POSTGRES_URL` | string | Yes      | PostgreSQL connection string for the application database |
| `JWT_SECRET`   | string | Yes      | Secret key for signing and verifying JWT tokens           |
| `S3_BUCKET`    | string | Yes      | S3 bucket name for document and asset storage             |
| `AWS_REGION`   | string | Yes      | AWS region for Bedrock and other AWS services             |

### Helm chart values

The Promptless Helm chart supports these `values.yaml` settings:

<details>
  <summary>Global configuration</summary>

  ```yaml
  global:
    domain: promptless.example.com
    environment: production
    imageRegistry: public.ecr.aws/promptless
  ```
</details>

<details>
  <summary>Authentication settings</summary>

  ```yaml
  auth:
    provider: oidc
    oidcIssuerURL: https://auth.example.com
    sessionTimeout: 24h
    mfaRequired: true
  ```
</details>

<details>
  <summary>Resource limits</summary>

  ```yaml
  api:
    replicas: 2
    resources:
      requests:
        memory: "512Mi"
        cpu: "250m"
      limits:
        memory: "1Gi"
        cpu: "500m"
  ```
</details>

<details>
  <summary>Integration configuration</summary>

  ```yaml
  integrations:
    github:
      enabled: true
      apiBaseURL: https://api.github.com
    slack:
      enabled: true
    linear:
      enabled: true
  ```
</details>

## Secure the deployment

Apply these practices to the network, data, and compliance setup of your deployment.

### Network security

- Use private subnets for database instances.
- Configure security groups to allow only the ports the deployment needs.
- Enable VPC Flow Logs for network monitoring.
- Use AWS PrivateLink or VPC endpoints for access to AWS services.

### Data protection

- Enable encryption at rest for RDS and S3.
- Use TLS 1.2 or higher for all communications.
- Give IAM roles least-privilege access.
- Apply security updates regularly, and scan for vulnerabilities.

### Compliance

Self-hosted Promptless supports these compliance requirements:

| Framework | What the deployment provides           |
| --------- | -------------------------------------- |
| SOC 2     | Audit logging and access controls      |
| GDPR      | Data residency and privacy controls    |
| HIPAA     | Enhanced encryption and access logging |
| FedRAMP   | Government cloud deployment options    |

To discuss specific compliance requirements for your deployment, email [help@gopromptless.ai](mailto\:help@gopromptless.ai).

## Upgrade Promptless

Upgrade to the latest chart release:

<Aside type="caution">
  Before you upgrade, review the changelog and test the upgrade in a staging environment.
</Aside>

1. Update the Helm repository:

   ```bash
   helm repo update
   ```

2. Upgrade the release:

   ```bash
   helm upgrade promptless promptless/server \
     --namespace promptless \
     -f values.yaml
   ```

## Troubleshoot the installation

### Common issues

<details>
  <summary>Pods not starting</summary>

  **Symptoms:** Pods stuck in the `Pending` or `CrashLoopBackOff` state.

  **Solutions:**

  1. Check resource availability: `kubectl describe nodes`
  2. Verify that the secrets exist: `kubectl get secrets -n promptless`
  3. Check pod logs: `kubectl logs <pod-name> -n promptless`
  4. Validate the `values.yaml` configuration.
</details>

<details>
  <summary>Database connection issues</summary>

  **Symptoms:** API server logs show database connection errors.

  **Solutions:**

  1. Verify the PostgreSQL URL in the secret.
  2. Check the RDS security groups and network connectivity.
  3. Make sure the database exists and migrations can run.
  4. Test the connection from a debug pod.
</details>

<details>
  <summary>Authentication problems</summary>

  **Symptoms:** Users can't sign in, or they get authentication errors.

  **Solutions:**

  1. Verify the OIDC or SAML configuration in `values.yaml`.
  2. Check identity provider connectivity and certificate validity.
  3. Review the authentication provider logs.
  4. Validate the redirect URLs and client secrets.
</details>

<details>
  <summary>Documentation generation failures</summary>

  **Symptoms:** Jobs fail, or documents aren't generated.

  **Solutions:**

  1. Check the worker pod logs for errors.
  2. Verify connectivity to Bedrock or your LLM provider.
  3. Make sure the S3 bucket permissions are correct.
</details>
