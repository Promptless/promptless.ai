Promptless follows the principle of least privilege: each connection grants only the access its job needs. Most of that access is read-only, and you can scope or revoke it at any time. This page summarizes what Promptless can reach and links to the detailed security and integration pages.

## What Promptless reads versus writes

Promptless writes only to your documentation repository, and you can limit that access too.

- **Context sources are read-only.** Jira, Linear, Confluence, Notion, Google Drive, and Slite give Promptless read-only access. Promptless reads them for context and never writes back.
- **Source code is read-only.** Where Promptless reads source for context (for example, GitLab merge requests), it only reads. It never pushes code or modifies those projects, except a repository you configure as a documentation destination.
- **Documentation repositories need write access.** To publish, Promptless pushes a branch to your GitHub docs repository or GitLab docs project and opens a pull or merge request. Path scope limits that access (see below). You review every pull or merge request before it merges, unless you enable [`auto_merge`](/docs/for-docs/reference/configuration-reference#policies) in a publishing policy, which merges Promptless's changes without review.

Promptless stores the feedback you give it and integration auth tokens, but not the content behind those tokens. It processes source code, support conversations, and context-source data in real time without keeping a copy. It doesn't use customer data to train or fine-tune models. See [Data handling and classification](/docs/for-docs/security/data-handling-and-classification) for details.

## Scope each connection

- **Repositories:** During GitHub installation, choose **Only select repositories** and grant only the repositories Promptless needs. For per-provider access, see the [GitHub](/docs/for-docs/reference/integrations/github), [GitHub Enterprise](/docs/for-docs/reference/integrations/github-enterprise), and [GitLab](/docs/for-docs/reference/integrations/gitlab) integration pages.
- **Context sources:** These connect through OAuth, so Promptless inherits the permissions of the account that authorized the connection. It searches only the projects, spaces, or drives you configure. For the tightest scope, connect through a dedicated service account that has access only to the drives and folders you share with it.

## Read-only options

- **Read-only GitHub app.** For public repositories, the read-only GitHub app opens documentation pull requests from a fork, without write access to your repo. See the [GitHub (read-only) integration](/docs/for-docs/reference/integrations/github-read-only).
- **GitLab uses one read-write token.** The same `api`-scoped group or personal access token handles reads and writes. To limit its reach, scope a group access token to a group or subgroup that holds only documentation projects. This works when your trigger, context-source, and docs-destination projects all live in that group or subgroup. See [Token scope considerations](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations).

## Limit where Promptless can write

Path scope limits which files Promptless can change in a docs repository. When you specify directories during doc collection setup, Promptless modifies only files that match one of those paths or sit inside them. It rejects a suggestion that changes files outside that scope, with an error listing them. Path scope helps in monorepos where docs live beside source code. See [GitHub repos (docs as code)](/docs/for-docs/connect/doc-locations/github-repos) and [GitLab projects (docs as code)](/docs/for-docs/connect/doc-locations/gitlab-projects).

## Revoke or rotate access

You or Promptless can revoke the GitHub App connection at any time. You can also rotate or remove provider tokens, such as a GitLab access token, in the provider.

## Roles inside Promptless

Role-based access control governs access to Promptless itself, with three roles:

- **Admin**: full access to organization settings, team management, integrations, projects, and all suggestions, including the Agent Knowledge Base.
- **Editor**: can edit suggestions and create tasks, but cannot manage organization settings, integrations, or team members.
- **Collaborator**: can view suggestions and leave feedback comments, but cannot edit or modify them.

For sign-in and identity, see [Single sign-on (SSO) setup](/docs/for-docs/security/single-sign-on) and [Data handling and classification](/docs/for-docs/security/data-handling-and-classification). For multi-tenant isolation, encryption, and the broader security model, see [Network architecture](/docs/for-docs/security/network-architecture) and [Compliance and certifications](/docs/for-docs/security/compliance-and-certifications).
