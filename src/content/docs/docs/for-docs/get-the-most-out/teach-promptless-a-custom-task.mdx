## Overview

Promptless ships with default behaviors, such as reviewing code PRs for documentation impact. Teach it a custom task when you want it to do something new on a regular basis. For example, it can review contributor PRs in your docs repository or turn weekly analytics into doc-gap suggestions.

A custom task has two parts:

| Part               | What it decides                   | Where it lives                                                                              |
| ------------------ | --------------------------------- | ------------------------------------------------------------------------------------------- |
| A trigger          | When Promptless runs              | The **Triggers** tab of the [Configuration page](https://app.gopromptless.ai/configuration) |
| A written workflow | What Promptless does when it runs | A file under `doc_workflow/` in your Knowledge Base, or an Agent Skill in a doc collection  |

An "If, then" hook in `PROMPTLESS.md` connects the two, so Promptless follows the workflow when the trigger activates. You can pair a workflow with [any supported trigger type](/docs/for-docs/reference/configuration-reference#trigger-types). Your instructions can add to Promptless's default behavior or change it.

Event triggers, such as a GitHub PR trigger, act on new events, such as a PR opening. They don't scan or audit the pages you already have. A schedule trigger runs on a repeating clock, so it suits recurring checks such as a link audit. For one-time work across your whole docs set, such as an audit, a retrofit, or writing from scratch, use [Deep Analysis](/docs/for-docs/get-the-most-out/pay-down-docs-debt).

<Aside type="tip">
  You can also ask Promptless in Slack or Microsoft Teams to set up a custom task. For example, "@Promptless I have a new workflow I'd like you to support. Can you help me set it up?" See [Ask Promptless to update your configuration](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).
</Aside>

## Before you start

- The integration that the trigger depends on, connected to Promptless. For example, the GitHub integration for a task that starts from a GitHub PR.
- An admin role in your Promptless organization, to edit the Knowledge Base and Configuration page. Alternatively, ask Promptless in Slack or Microsoft Teams to make the edits for you.

## Write the workflow

The workflow holds the instructions Promptless follows once the trigger activates. Make it concrete. Say what to check, what to prioritize, and what output to produce, so Promptless knows what a successful run looks like.

<Steps>
  1. Write the workflow in one of these places:

     - A Markdown file under `doc_workflow/` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base), such as `doc_workflow/review-inbound-doc-prs.md`.

     - An Agent Skill in a doc collection, under `.claude/skills/`, `.agents/skills/`, or `.cursor/skills/` in your docs repository.

  2. In `PROMPTLESS.md`, add an "If, then" hook that points to the workflow, in the form "If \[condition], then \[do this]." When the workflow is an Agent Skill, name the doc collection it lives in. For example: "When a contributor PR is opened in `acme/docs`, use the `contributor-workflow` skill from the Acme doc collection."

  3. Save your changes. An organization admin can edit the files in the [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base). You can also ask Promptless to make the edits, and it commits them for you.
</Steps>

<Aside type="caution">
  Add the "If, then" hook even when the workflow is complete on its own. Promptless loads `PROMPTLESS.md` into every run, so a hook there is always in front of it. It loads workflow files and Agent Skills only when it needs them, so a workflow with no hook may not run consistently. Promptless also reads guidance from `AGENTS.md` and `CLAUDE.md` in your docs repository. See [How Promptless learns your docs](/docs/for-docs/connect/doc-locations/how-promptless-learns-your-docs).
</Aside>

## Add the trigger

The trigger decides when your workflow runs. For example, a GitHub PR trigger can activate when a PR is opened. A Slack channel trigger can act on messages that meet criteria you describe.

<Steps>
  1. On the [Configuration page](https://app.gopromptless.ai/configuration), open the **Triggers** tab.

  2. Select **Add an automatic or scheduled trigger**, then select the trigger type.

  3. Fill in the trigger's settings, such as the repositories or channels to watch.

  4. Select **Add trigger**.
</Steps>

<Aside type="note">
  In the dashboard, a GitHub PR trigger can run when a PR is opened, first approved, or merged. To run on every new push to a PR, set `trigger_on: [updated]` in `promptless.yaml`. See [Trigger modes](/docs/for-docs/connect/triggers/github-prs#choose-trigger-modes). For a one-off review outside your triggers, mention `@promptless` in a PR comment.
</Aside>

When the trigger activates on a qualifying event, Promptless reads the context for that event, follows your workflow, and produces the output your instructions define. The context it reads and the output it produces depend on the workflow you write.
