## Overview

The Agent Knowledge Base holds the files Promptless reads to understand your documentation style, product context, and workflow preferences. Promptless updates these files as it learns from your feedback. Open the Knowledge Base to check what Promptless has learned, correct an assumption it made, or add instructions it follows on every task.

All organization members can view the files. Only organization admins can edit or create them, in the dashboard or by [pushing changes with Git](#clone-and-push-the-knowledge-base-with-git).

## View files

<Steps>
  1. In the left sidebar, open **Settings** and select **Agent Knowledge Base**.

  2. In the file tree, select a file to open it in the editor.
</Steps>

The URL updates with a `?file=<path>` query parameter for the open file. Bookmark or share that URL to open the editor to the file. Recipients need their own access to your organization to open it. Your browser's back and forward buttons move between the files you've viewed.

## Know the files that shape every task

Four files shape how Promptless works for your whole organization. The file tree marks each one with the Promptless logo, and the editor explains the file's role above its contents. Promptless marks only these exact paths, so a file with the same name in another folder, such as `notes/PROMPTLESS.md`, has no logo.

| File                                       | What it controls                                                                                                                                                                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PROMPTLESS.md`                            | Instructions Promptless receives at the start of every session. Put rules Promptless must always follow here, including the "If, then" hooks that [activate custom tasks](/docs/for-docs/get-the-most-out/teach-promptless-a-custom-task). |
| `promptless.yaml`                          | Your triggers, doc collections, context sources, and policies. Edit it on the [Configuration page](https://app.gopromptless.ai/configuration). See the [Configuration reference](/docs/for-docs/reference/configuration-reference).        |
| `style/client_style_guide.md`              | Your documentation style guide, which Promptless reads before it writes or revises your docs. Reference your repository's style guide or Vale rules here. Promptless adds the style preferences it learns from feedback.                   |
| `doc_workflow/notification_preferences.md` | Your preferences for the notifications Promptless sends, such as whom it mentions and how it formats messages. Promptless reads it when it writes a notification.                                                                          |

Promptless reads the other files in the Knowledge Base when a task calls for them.

## Review the doc collection analysis

When you connect a docs repository, Promptless studies your existing documentation, the repository's full commit history, and your public docs site. It records what it learns in a `collection_analyses/` folder, with one subfolder for each connected docs repository. Promptless reads this analysis at the start of every documentation task, so its suggestions reflect how your product and docs work.

Each analysis folder contains these files:

| File                       | Contents                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `README.md`                | An index of the analysis and its headline findings.                                                             |
| `product-overview.md`      | What your product does, its key concepts, and terminology.                                                      |
| `audience-and-personas.md` | Who your documentation serves and what knowledge each reader is assumed to have.                                |
| `content-strategy.md`      | Critical user journeys, where new content belongs, and gaps in your information architecture.                   |
| `team-workflows.md`        | Patterns from your commit history, such as update cadence, authorship, and which pages tend to change together. |
| `style-observations.md`    | Voice, formatting, and terminology patterns observed in your docs.                                              |

Promptless generates the analysis when you connect the repository, so it reflects your documentation at that time. If you've connected Slack or Microsoft Teams, Promptless notifies your configured channel when the analysis finishes. Otherwise, the files appear in the Agent Knowledge Base when it's done.

During analysis, Promptless also proposes Vale rules from your style guidance. It records them under a `style/vale/` folder and, when it can place them in your documentation repository, opens a suggestion to add them. See [Propose Vale rules from your style guidance](/docs/for-docs/audit/standards-enforcement#propose-vale-rules-from-your-style-guidance).

<Aside type="note">
  The analysis files are Promptless's best inferences from your docs, commit history, and public site, not confirmed facts. Organization admins can [edit any of them](#edit-files) to correct or refine what Promptless assumes. Promptless treats those edits as ground truth on future tasks.
</Aside>

<Aside type="caution">
  If you point a collection at a different repository, Promptless analyzes the new repository from scratch. It replaces all six files, including any edits you've made. Copy anything you want to keep first.
</Aside>

## Track what Promptless changed

Promptless can update these files when you give feedback on suggestions through PR comments, the Promptless dashboard, or Slack. It applies what it learned to future tasks. The **Recent updates by Promptless** list shows its latest changes. Each entry shows:

- The date of the update
- The files changed, with a diff for each
- A link to the suggestion that prompted the update, when there is one

## Edit files

Only organization admins can edit Knowledge Base files. Other members see each file as view-only, with no **Save** button.

<Steps>
  1. Open the file and make your changes in the editor.

  2. Select **Save**.
</Steps>

Promptless commits your changes directly to the Knowledge Base repository.

<Aside type="caution">
  Leaving a file with unsaved changes discards them. Promptless asks you to confirm first when you switch files or use your browser's back or forward buttons. It also asks when you follow the configuration page link above `promptless.yaml`. Select **Cancel** to stay on the file and keep your edits. Opening the configuration page link in a new tab keeps your edits and doesn't ask.
</Aside>

## Create files

<Steps>
  1. Select the **+** button next to a folder to create a file in it. To create a top-level file, select the new-file icon at the root.

  2. In the **New file** dialog, enter a file name without the `.md` extension. Promptless adds the extension. To create the file in new folders, enter a path such as `nested/path/filename`, and Promptless creates the folders.

  3. Select **Create**.
</Steps>

The new file opens in the editor.

## Clone and push the Knowledge Base with Git

The Agent Knowledge Base is a Git repository. Clone it to read and change these files from your own editor, scripts, or CI pipeline. Promptless serves your organization's repository at `https://api.gopromptless.ai/v1/knowledge-base.git` and picks it from the organization your API key belongs to.

You need a Promptless API key. Organization admins create keys on **Settings > API Access**. See [Create an API key](/docs/for-docs/connect/triggers/api#create-an-api-key).

### Clone the repository

Clone the repository:

```bash
git clone https://api.gopromptless.ai/v1/knowledge-base.git
```

When Git asks for credentials, enter any username, and enter your API key as the password. Any active API key can clone, fetch, and pull.

To skip the prompt, for example in a CI job, put the key in the URL:

```bash
git clone https://x-access-token:<your-api-key>@api.gopromptless.ai/v1/knowledge-base.git
```

<Aside type="caution">
  Git saves a clone URL in the clone's `.git/config` file, so a key in the URL stays on disk in plain text. In a shared or long-lived checkout, use a [Git credential helper](https://git-scm.com/docs/gitcredentials) to store the key instead.
</Aside>

### Push changes

Pushing needs the same admin role as editing in the dashboard. Keys created on **Settings > API Access** can push. A key tied to a person's account can push only while that person is an organization admin.

Promptless agents and dashboard edits commit to the same `main` branch, so pull before you edit:

1. Run `git pull` to get the latest commits.
2. Edit the files, and commit your changes.
3. Run `git push`.

If someone else committed to `main` after your last pull, Git refuses the push. Run `git pull`, resolve any conflicts, and push again.

Promptless checks each push against these rules:

- Push one update to `main` per push. Promptless refuses pushes to other branches, branch deletions, and force-pushes.
- Keep each push to 100 MB or less.
- Give your commits any author except an address that Promptless agents commit with, such as `agent+<id>@gopromptless.ai`. Promptless uses those addresses to link a commit to the agent session that made it. Commits that are already on a branch of the repository pass this check, so you can merge a branch that Promptless created.

When a push includes a commit with a Promptless agent address, Git prints the refused commits. To fix them, set your own email address and rewrite the commits:

```bash
git config user.email <your-email>
git rebase --exec 'git commit --amend --no-edit --reset-author' origin/main
```

Promptless records which API key made each accepted push.

### After you push

Promptless stores your commits unchanged, so their SHAs match your local clone. Your changes appear in the dashboard's file tree, and the next Promptless session reads them.

Promptless validates `promptless.yaml` after each push. If a push leaves the file invalid, Git still accepts the push. Promptless keeps using your last valid configuration, and the [Configuration page](https://app.gopromptless.ai/configuration) shows the error until a later change fixes the file.
