Promptless can audit your published documentation site for broken and outdated links and fix them in one suggestion. Ask for an audit whenever you need one, or run it on a schedule trigger so broken links get caught every week. A link audit is built into Promptless, so this example needs no workflow file or `PROMPTLESS.md` hook. The schedule trigger's instructions are enough. For the general trigger-plus-instructions pattern, see [Teach Promptless a custom task](/docs/for-docs/get-the-most-out/teach-promptless-a-custom-task).

## Prerequisites

Before you set up an audit, make sure you have:

- **An active doc collection for the site you want to audit.**
- **`docs_root_url` set on that doc collection.** Promptless crawls the published site starting from this URL. It's a field on the collection in `promptless.yaml`. See [Doc collections](/docs/for-docs/reference/configuration-reference#doc-collections). For a one-off audit, you can name the site URL in your request.
- **The ability to chat with Promptless** in Slack or Teams, or **admin access** to edit triggers on the Configuration page.

## Run a one-off audit

Ask Promptless for an audit in Slack or Microsoft Teams, or from the [New Task page](https://app.gopromptless.ai/new-task) in the dashboard. For example:

```text
@Promptless audit docs.acme.com for broken or outdated links and fix what you find.
```

Promptless crawls the site, fixes the links it can, and opens one suggestion.

## Schedule a recurring audit

A recurring audit runs on a [schedule trigger](/docs/for-docs/connect/triggers/schedule). Ask Promptless to add it, as the tip at the top of this page shows, or add it yourself:

<Steps>
  1. In the left sidebar, open **Settings** and select **Configuration**, then open the **Triggers** tab and choose **Add a trigger**.

  2. Choose the **"On a schedule"** group and its catalog entry, "A recurring schedule".

  3. Set the schedule and timezone, and enter the standing instructions shown in the following YAML.

  4. Save your configuration.
</Steps>

The trigger's `promptless.yaml` entry looks like this:

```yaml
triggers:
  weekly-link-audit:
    trigger_type: schedule
    match:
      - cron: "0 9 * * 1"
        timezone: America/Los_Angeles
    instructions: |
      Audit the docs site for broken or outdated links using the link audit
      workflow, and open one suggestion that fixes them.
```

The cron `0 9 * * 1` runs the audit every Monday at 9am in the given timezone. Change the `cron` and `timezone` values to the cadence you want. Keep the `instructions` text, because it tells Promptless to run its link audit. For cron and timezone rules, see [Schedule triggers](/docs/for-docs/connect/triggers/schedule#cron-schedule-rules).

## What Promptless does on each audit

On each audit, Promptless:

1. Crawls your published site from the collection's `docs_root_url` and records each broken link, each redirect, and the page that contains it.
2. Rechecks each broken link to another site once. A link that returns 403 or 429 is marked unverified, because sites with bot protection send those codes to crawlers.
3. Finds each reported link in your docs source.
4. Fixes the links:
   - A permanently redirected link (301 or 308) is updated to the redirect target.
   - A broken link to a page on your own site is pointed at the page that now holds the content.
   - A broken link to another site is pointed at its replacement page on that site, or at an archived copy.
5. Opens one suggestion with the fixes. Its description lists each link Promptless couldn't fix with confidence, and each unverified link, with the source file and the reason.

A scheduled audit that finds nothing to fix finishes quietly, with no suggestion. Set a [notification channel](/docs/for-docs/tune/notifications) to see what each run produces.
