Links rot as pages move and other sites reorganize. Promptless has a built-in link checker that crawls your published docs site and reports the links that need attention. Promptless then fixes those links in your docs source and opens a suggestion. Ask for an audit whenever you need one, or put it on a schedule trigger so moved and broken links get caught every week. The audit needs no workflow file or `PROMPTLESS.md` hook. For the general trigger-plus-instructions pattern, see [Teach Promptless a custom task](/docs/for-docs/get-the-most-out/teach-promptless-a-custom-task).

## Prerequisites

Before you set up an audit, make sure you have:

- A published docs site on a public URL. Promptless crawls the site over the internet. It can't reach `localhost`, a staging server behind a VPN, or other hosts on a private network.
- An active doc collection for the repository that holds the site's source, so Promptless can edit the links it finds.
- The ability to chat with Promptless in Slack or Teams, or admin access to edit triggers on the Configuration page.

Name the site URL in your request or in the trigger's instructions. You can also set `docs_root_url` on the doc collection in `promptless.yaml`, so Promptless knows where that collection is published. See [Doc collections](/docs/for-docs/reference/configuration-reference#doc-collections).

## Run a one-off audit

Ask Promptless for an audit in Slack or Microsoft Teams, or from the [New Task page](https://app.gopromptless.ai/new-task) in the dashboard. For example:

```text
@Promptless audit https://docs.acme.com for broken links and fix what you find.
```

By default the audit checks the links between pages of your own site, including their anchors. To also check links to other sites, say so in the request, for example "include external links."

## Schedule a recurring audit

A recurring audit runs on a [schedule trigger](/docs/for-docs/connect/triggers/schedule). Ask Promptless to add it, as the tip at the top of this page shows, or add it yourself:

<Steps>
  1. Open your organization's [Configuration page](https://app.gopromptless.ai/configuration) and select the **Triggers** tab.

  2. Choose the **"On a schedule"** group and its catalog entry, "A recurring schedule".

  3. Set the schedule and timezone, and enter standing instructions like the ones in the following YAML.

  4. Save your configuration.
</Steps>

The trigger's `promptless.yaml` entry looks like this:

```yaml
triggers:
  weekly-link-audit:
    trigger_type: schedule
    match:
      - cron: "0 9 * * 1"
        timezone: America/Los_Angeles
    instructions: |
      Check https://docs.acme.com for broken links, including external links,
      and open one suggestion that fixes them.
```

The cron `0 9 * * 1` runs the audit every Monday at 9am in the given timezone. Change the `cron` and `timezone` values to the cadence you want, and replace the URL with your site's. For cron and timezone rules, see [Schedule triggers](/docs/for-docs/connect/triggers/schedule#cron-schedule-rules).

## What the audit reports

The link checker starts at the URL you give it and follows links to every page on the same site. It checks each link it finds on those pages and reports two kinds of results.

Broken links:

- A link whose page returns an error status, such as 404 or 500, or doesn't respond in time.
- A link to an anchor, such as `#install`, that doesn't exist on the target page.
- A link to a site that keeps rate-limiting the checker. It's reported with HTTP 429, so you can recheck it by hand.

Permanently redirected links:

- A link that answers with a permanent redirect (301 or 308) and ends on a working page. The report names the destination, including any anchor, so Promptless can update the link to point there directly.

A temporary redirect (302, 303, or 307) that ends on a working page counts as a working link. Its source link is still the right one to use.

Promptless finds each reported link in your docs source and fixes it in a suggestion. It updates a redirected link to its destination and points a broken link at the page or anchor that now holds the content. Review the fixes for links to other sites before you merge, because the right replacement for a removed page is a judgment call.
