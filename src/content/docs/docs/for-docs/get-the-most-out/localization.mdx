## Overview

When your docs ship in more than one language, the translated pages fall behind each time the source content changes. Most teams write in one language, often English, and mirror it into the others. To keep the translations current, pair a trigger on the directory you write in with translation instructions. When source pages change, Promptless drafts the matching updates for your other languages.

<Aside type="caution">
  AI-assisted drafting speeds up translation, but a person still needs to review it. Idiom, tone, terminology, and locale conventions are easy to get subtly wrong. Plan for a reviewer fluent in each target language to check every translated suggestion before it ships.
</Aside>

## Before you start

- The GitHub repository that holds your docs, connected to Promptless.
- An admin role in your Promptless organization, to edit the [Configuration page](https://app.gopromptless.ai/configuration) and `PROMPTLESS.md`. You can also [ask Promptless to make the changes](/docs/for-docs/get-the-most-out/ask-promptless-to-update-config).

## Add a trigger on your source-language directory

A [GitHub commits trigger](/docs/for-docs/connect/triggers/github-commits) runs when new commits are pushed to a branch, whether or not the commits came through a pull request.

<Steps>
  1. On the [Configuration page](https://app.gopromptless.ai/configuration), open the **Triggers** tab.
  2. Select **Add an automatic or scheduled trigger**, then select **GitHub commits**.
  3. Expand **More filters (optional)**.
  4. Under **Only when files in these folders change**, enter the directory you write in, such as `docs/en`, and press Enter.
  5. Select **Add trigger**.
</Steps>

Only commits that change files in that directory start a run, so a commit that touches only translated directories doesn't.

## Write translation instructions

The trigger decides when Promptless runs. Your instructions tell it how to handle the translation. Put them in `PROMPTLESS.md`, which Promptless loads at the start of every run.

<Steps>
  1. Open `PROMPTLESS.md` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base).
  2. Name the directory you write in, the directories to update, and any terms to keep in the source language. For example: "`docs/en` is the documentation source directory. Localize changes into `docs/es` and `docs/ja`, and keep product names untranslated."
  3. Select **Save**.
</Steps>

For the "If, then" hook format and where longer workflows live, see [Teach Promptless a custom task](/docs/for-docs/get-the-most-out/teach-promptless-a-custom-task).

## Review translated suggestions

When a source page changes, Promptless opens a suggestion with the translated changes. Have someone fluent in the target language review and publish it. You can't judge a translation's correctness from the diff alone.

## Teach translation conventions with feedback

Expect to refine your translation instructions over the first few suggestions, especially when you maintain several target languages or are catching up a backlog. Product names, terms of art, and phrases you leave untranslated need to come out the same way every time.

When you correct a translation, [teach the convention with feedback](/docs/for-docs/tune/teaching-conventions). When you close a suggestion with a reason, leave **Send to Promptless** checked so the feedback shapes future suggestions. Promptless records what it learns in your Agent Knowledge Base. For example, it records which terms stay in the source language or how to render a feature name.

## Catch up translations that are already behind

The trigger acts on new commits. It doesn't scan pages that are already out of date. For one-time work across all your translated pages, use [Deep Analysis](/docs/for-docs/get-the-most-out/pay-down-docs-debt). Describe the catch-up in its instructions, and Promptless returns a coordinated set of suggestions. Once your translations are current, new commits to your source-language directory start runs as usual.

## Publish translated updates automatically

Review localization pull requests at first. Once a fluent reviewer trusts the output, you can have Promptless merge them automatically:

<Steps>
  1. On the [Configuration page](https://app.gopromptless.ai/configuration), open the **Policies** tab.
  2. Add a rule, and under **When this matches**, choose your translation trigger.
  3. Turn on **Open a pull request automatically** and **Merge the pull request automatically**. Auto-merge requires automatic pull request creation.
  4. Select **Save policies**.
</Steps>

The rule applies only to your translation trigger. Your other suggestions follow your default policy. Promptless doesn't auto-merge into a protected branch. With the [GitHub (read-only) app](/docs/for-docs/reference/integrations/github-read-only), Promptless opens pull requests from a fork and doesn't merge them automatically, so merge those yourself.

<Aside type="caution">
  Auto-merge on a trigger applies to every target language that trigger drafts for, and publishes all of them without review. Turn it on only once a reviewer fluent in each language trusts Promptless's output. To automate some languages and keep reviewing others, scope a separate trigger to each language.
</Aside>

## Work with a translation management system

Promptless drafts translations from the instructions you provide. It has no documented integration with a translation management system (TMS) such as Phrase, Crowdin, or Lokalise. If your team uses a TMS and wants Promptless to hand off to it, email [help@gopromptless.ai](mailto\:help@gopromptless.ai) to discuss your requirements.
