After Promptless opens a docs PR, you can provide follow-on instructions by commenting on it. This works whether Promptless opened a pull request or a merge request for your documentation. Promptless automatically handles quality issues (like linter failures, Vale warnings, or broken links) that arise in documentation PRs. Manual feedback can focus on content improvements rather than technical fixes.

<Aside type="note">
  You can also @mention Promptless in comments on source code PRs to request documentation updates. See [Request documentation via PR comments](/docs/for-docs/connect/triggers/github-prs#request-documentation-via-pr-comments) for details.
</Aside>

## Comment trigger modes

One organization setting governs how Promptless responds to comments on documentation pull requests (GitHub) and merge requests (GitLab):

**Listen to all comments** (default for new organizations): Promptless processes all human comments automatically. To have Promptless ignore a specific comment, start it with `aside` or `/aside`.

**Require @promptless mentions** (default for existing organizations): Promptless responds when you tag `@promptless` in a comment.

To invoke Promptless, mention `@promptless` (or `@promptless-for-oss`) anywhere in a comment, or start a line with `/promptless`. Both forms work on GitHub pull requests and GitLab merge requests.

In **Listen to all comments** mode, Promptless also looks at who a comment addresses. If a comment's question or request goes only to someone else, Promptless leaves it alone. A comment that doesn't clearly address someone else still gets a reply.

<Aside type="note">
  Change this setting anytime in [Settings → **Organization**](https://app.gopromptless.ai/settings/org).

  Changing organization settings requires the [Admin role](/docs/for-docs/security/access-and-permissions).
</Aside>

## Mentions from automated accounts

Promptless acts on a direct `@promptless` mention (or a line-leading `/promptless`) the same way, whether it comes from a teammate or an automated account. In **Listen to all comments** mode, Promptless may skip some unmentioned comments from automated or bot accounts. For example, it may skip a staging-summary comment posted by a continuous integration (CI) or service account. Tagging `@promptless` (or using a line-leading `/promptless`) always ensures Promptless acts on the comment. To keep Promptless from acting on a known-noisy automated comment in **Listen to all comments** mode, start the comment with `aside` (or `/aside`). You can also set the mode to **Require @promptless mentions**.

## Review in the dashboard

Every PR that Promptless opens links to its suggestion in the dashboard, at the top of the PR description. The suggestion holds what you need to judge a change before you merge it. Suggestions that don't have a PR yet open from the [review queue](/docs/for-docs/work-the-queue/assignment-and-routing#triage-the-review-queue).

- **Evidence:** Citations tie each change to the files, PRs, and commits Promptless relied on. The [research breakdown](/docs/for-docs/connect/triggers#see-what-promptless-researched) lists everything Promptless read before drafting, such as source files and Slack threads.
- **History:** A timeline records each commit to the suggestion's branch with its author, time, and changed files. It shows what Promptless and your teammates changed, and when.
- **Collaboration:** Assignees, labels, and overall comments let your team coordinate on the suggestion.

From the suggestion, you can edit the changes yourself, ask Promptless for changes, publish the suggestion as a PR or MR, or close it.

### Check how changes render

Review a change as readers will see it, not only as a diff. Markdown and MDX files render with added and removed content highlighted, so you can check headings, lists, tables, and code blocks in context.

Changed images appear as before-and-after versions side by side. SVG files render as images, and their markup diff is also available. You can reject a single image change to restore its previous version while keeping the rest of the suggestion. Image previews cover PNG, JPEG, GIF, BMP, WebP, AVIF, and SVG files.

### Rename a suggestion

When you rename a suggestion that has an open or draft PR on GitHub, Promptless renames the PR to match. The new title takes effect only after GitHub accepts it, so the suggestion and the PR keep the same title. Renaming the PR on GitHub updates the suggestion the next time you open it. Renaming changes only the title, not the branch or its commits.

### When the suggestion changes during your review

Promptless or a teammate can update a suggestion while you have it open. When an update changes files you're reviewing, a **This suggestion was updated** notice appears. It stays at the top of the suggestion as you scroll. Until you refresh, you can't edit or reject files, save, or open a PR.

Select **Refresh suggestion** to load the latest version. Refreshing reapplies your unsaved edits to the new version and keeps your pending rejections. If an edit can't merge cleanly, the file shows conflict markers for you to resolve before you save. Refreshing drops edits and rejections for files that left the suggestion. To keep a copy of your unsaved edits before you refresh, select **Copy my edits**.

## Review workspace preview

The review workspace is a preview of a suggestion page that puts your conversation with Promptless beside all of the suggestion's changed files. To try it, open a suggestion and change `/suggestions/<id>` in its URL to `/suggestions/v2/<id>`. To return to the standard page, remove `/v2` from the URL.

The dashboard sidebar starts collapsed to icons in the workspace. If you expand it, the workspace remembers your choice separately from other dashboard pages. To give the files the full width, select **Hide chat**. Select **Show chat** to bring it back.

### Work with Promptless in the chat

The chat lists the suggestion's history, oldest first: trigger events, commits, messages, and how the suggestion ended. Promptless's summary of the suggestion follows the Promptless commit it describes. Select a trigger event to open its source, or select a commit to see its diff.

To ask Promptless for a change, type your request in the composer. Then select the send button or press **⌘+Enter** (**Ctrl+Enter** on Windows and Linux). To ask about specific lines, select them in the diff and select **Add to chat** first. Turn off **Send to Promptless** to post a comment for your team only. Collaborators can comment but can't send requests to Promptless.

### Review the changed files

Every changed file appears in one scrolling list. Select a file in the file tree to jump to it. Select **Viewed** in a file's header to mark it reviewed and collapse it. The chat counts the files you've viewed and rejected.

- **Edit a file**: Type in its diff. Select **Save** or **Discard** in the file's header. **Save all** in the chat, or **⌘+S** (**Ctrl+S**), saves every file's edits and pending rejections.
- **Undo a suggested change**: Select **Undo** below the change, then save the file.
- **Reject a file**: Open **File actions** in the file's header and select **Reject file**. The file shows **Pending rejection**, even when collapsed, and Promptless removes it from the suggestion when you save. To cancel, select **Keep file** in the same menu, or **Keep the file** in the file.

### Check citations

Citations link a suggested line to the source that supports it, such as a line of code or a ticket. Cited lines carry a gutter marker. Each file lists its citations, ordered by line, in a **Sources** section below its diff. Expand a citation to read Promptless's note and reply to it. Select **Show lines** to jump to the cited lines. A citation whose lines have changed keeps its original line and shows a status such as **Outdated**. To hide or show citations across the review, select the citations button in a file's header.

### Comment on lines

Select text in the diff, or select line numbers. With the chat shown, select **Add to chat** and send your message from the composer. With the chat hidden, select **Comment** and write in the form that opens on the diff. Clear **Send to Promptless** to comment for your team only.

Select **Reply** to continue a thread and **Resolve** to close it. When later edits rewrite the lines a GitHub review comment is on, the comment moves to the replacement lines. Its header names the line it was originally on. Comments that can't be placed appear at the top of the file under **Discussions outside visible lines**.

### Publish or close the suggestion

For a GitHub doc collection, select **Open PR** in the chat, review the PR title, branch name, and description, then select **Create Pull Request**. Promptless saves your unsaved changes first. Once the PR or MR is open, select **Merge PR** or **Merge MR** to merge it from the workspace. To close the suggestion, select **Close** and give [close feedback](/docs/for-docs/tune/teaching-conventions#4-close-suggestion-feedback).

## Open PRs for several suggestions at once

When several suggestions are ready to publish, select them in the suggestions list and open their PRs in one batch. You can select suggestions one at a time, as a range, or as everything that matches your current filters. Promptless skips suggestions that are closed, have no changed files, or already have an open or draft PR. Before it starts, it confirms how many PRs it opens. You can retry any PR that fails to open.

## Two ways of providing feedback

### 1. Individual comments

Leave individual comments on specific lines or sections of the documentation PR or MR for targeted feedback.

In **Listen to all comments** mode, leave your comment and Promptless processes it automatically. In **Require @promptless mentions** mode, tag @promptless in the comment. The mention doesn't appear in autocomplete, but Promptless still sees it.

Promptless reads all previous comments in the PR or MR to understand the full context. This means your instructions can be as short as "Same here" or "Apply this change to the other section too."

### 2. PR reviews

Use a GitHub pull request review to give several pieces of feedback at once. Promptless handles all of the review's comments together after you submit it. In **Listen to all comments** mode, Promptless processes the submitted review automatically. In **Require @promptless mentions** mode, tag @promptless in the review summary.

## Examples of feedback you can give to Promptless

### Content updates

Request specific changes to the documentation content:

```txt wordWrap
Please add a section about error handling for this API endpoint
```

```txt wordWrap
This example should use TypeScript instead of JavaScript
```

```txt wordWrap
Add a note that this feature requires admin permissions
```

### Structural changes

Suggest improvements to the documentation structure:

```txt wordWrap
Move this section to the beginning of the page for better flow
```

```txt wordWrap
Split this into two separate sections: "Basic Usage" and "Advanced Configuration"
```

```txt wordWrap
Add a table of contents at the top of this page
```

### Technical corrections

Point out technical inaccuracies or missing details:

```txt wordWrap
The API endpoint should be /v2/users, not /v1/users
```

```txt wordWrap
Add the required headers for authentication
```

```txt wordWrap
Include the response status codes for each endpoint
```

### Style and formatting

Request improvements to presentation and readability:

```txt wordWrap
Format this as a code block instead of inline code
```

```txt wordWrap
Add syntax highlighting for the JSON examples
```

```txt wordWrap
Use a callout box to highlight this important warning
```
