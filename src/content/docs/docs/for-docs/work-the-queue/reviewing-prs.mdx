After Promptless opens a docs PR, you can provide follow-on instructions by commenting on it. This works whether Promptless opened a pull request or a merge request for your documentation. Promptless automatically handles quality issues (like linter failures, Vale warnings, or broken links) that arise in documentation PRs. Manual feedback can focus on content improvements rather than technical fixes.

<Aside type="note">
  You can also @mention Promptless in comments on source code PRs to request documentation updates. See [Request documentation via PR comments](/docs/for-docs/connect/triggers/github-prs#request-documentation-via-pr-comments) for details.
</Aside>

## Comment trigger modes

One organization setting governs how Promptless responds to comments on documentation pull requests (GitHub) and merge requests (GitLab):

**Listen to all comments** (default for new organizations): Promptless processes all human comments automatically. To have Promptless ignore a specific comment, start it with `aside` or `/aside`.

**Require @promptless mentions** (default for existing organizations): Promptless responds when you tag `@promptless` in a comment.

To invoke Promptless, mention `@promptless` (or `@promptless-for-oss`) anywhere in a comment, or start a line with `/promptless`. Both forms work on GitHub pull requests and GitLab merge requests.

In **Listen to all comments** mode, Promptless also looks at who a comment addresses. If a comment's question or request goes only to someone else, Promptless leaves it alone. A comment that doesn't clearly address someone else still gets a reply.

<Aside type="note">
  Change this setting anytime in [Settings → **Organization**](https://app.gopromptless.ai/settings/org).

  Changing organization settings requires the [Admin role](/docs/for-docs/security/access-and-permissions).
</Aside>

## Mentions from automated accounts

Promptless acts on a direct `@promptless` mention (or a line-leading `/promptless`) the same way, whether it comes from a teammate or an automated account. In **Listen to all comments** mode, Promptless may skip some unmentioned comments from automated or bot accounts. For example, it may skip a staging-summary comment posted by a continuous integration (CI) or service account. Tagging `@promptless` (or using a line-leading `/promptless`) always ensures Promptless acts on the comment. To keep Promptless from acting on a known-noisy automated comment in **Listen to all comments** mode, start the comment with `aside` (or `/aside`). You can also set the mode to **Require @promptless mentions**.

## Review in the dashboard

Every PR that Promptless opens includes a dashboard link at the top of its description. The link opens the suggestion behind the PR, where you can check the evidence for each change, preview how it renders, and edit it. Suggestions that don't have a PR yet open the same way from the [review queue](/docs/for-docs/work-the-queue/assignment-and-routing#triage-the-review-queue).

A suggestion opens on its **Review Suggestion** tab, which shows the suggested file changes. Citations on the changes link to the exact files, PRs, and commits Promptless referenced. From this tab, you can edit the changes, publish them as a PR or MR, request changes, or close the suggestion. Two other tabs hold the background:

- **Triggers & Analysis** shows the events that produced the suggestion. Its [research breakdown](/docs/for-docs/connect/triggers#see-what-promptless-researched) lists what Promptless read before drafting, such as source files and Slack threads.
- **History & Collaboration** shows assignees, labels, the change timeline, and overall comments.

The commit timeline lists each change to the suggestion's branch, with who made it, when, and which files it touched. Select **View diff** to inspect a commit.

### Check how changes render

To see a Markdown or MDX file as readers will, select **Preview Markdown** on any `.md`, `.mdx`, or `.markdown` file. The preview highlights added content in green and removed content in red, so you can check headings, lists, tables, and code blocks in context.

When a suggestion changes an image, the **Before** and **After** panes show the old and new versions side by side. Select an image to open it full size. SVG files open rendered. To review an SVG's markup diff, select **View source** in the file header. Rejecting a single image restores its previous version. Previews cover PNG, JPEG, GIF, BMP, WebP, AVIF, and SVG files. Other file types and very large files show a message in place of a preview.

### Rename a suggestion

Select the pencil next to a suggestion's title, enter a new name, and press **Enter**. When the suggestion has an open or draft PR on GitHub, Promptless renames the PR first. It keeps the new title only after GitHub accepts it, so the dashboard and the PR always match. The branch and commits stay as they are. If you rename the PR on GitHub instead, the dashboard picks up the new title the next time you open the suggestion.

### When a suggestion shows no changes

If a suggestion's branch matches its base branch, the viewer shows a "No changes against" panel naming the base branch. Usually the changes already landed on the base branch, or a sync merge replaced them. Select **Request Changes** to ask Promptless for a different approach, or **Close Suggestion** to end the suggestion with [feedback](/docs/for-docs/tune/teaching-conventions#4-close-suggestion-feedback). If you think the empty result is a mistake, contact [help@gopromptless.ai](mailto\:help@gopromptless.ai).

## Open PRs for several suggestions at once

When several suggestions are ready to publish, open their PRs in one pass from the suggestions list.

<Steps>
  1. **Select the suggestions.** In the suggestions list, hover over a row and select its checkbox. To select a range, hold **Shift** and select a second checkbox. To select everything that matches your current filters, select the checkbox at the start of the toolbar.

  2. **Start the batch.** In the toolbar, select **Open N PRs**.

  3. **Confirm.** The confirmation dialog shows how many PRs Promptless opens and how many it skips. Select **Open N PRs**.
</Steps>

A progress banner tracks each suggestion as its PR opens. Promptless skips suggestions that are closed, have no changed files, or already have an open or draft PR. If any request fails, select **Retry failed**.

## Two ways of providing feedback

### 1. Individual comments

Leave individual comments on specific lines or sections of the documentation PR or MR for targeted feedback.

If your organization uses **Listen to all comments** mode, just leave your comment. Promptless will process it automatically. In **Require @promptless mentions** mode, tag @promptless in the comment (it won't show up in auto-complete, but Promptless will still see it).

Promptless automatically reads all previous comments in the PR or MR to understand the full context. This means your instructions can be as simple as "Same here" or "Apply this change to the other section too."

### 2. PR reviews

Start a review to provide multiple pieces of feedback that Promptless can handle all at once.

<Steps>
  1. **Start a Review.** Click "Review changes" to begin a formal review process, or select "Start a review" when adding an in-line comment.

  2. **Add Multiple Comments.** Continue adding comments as part of the review.

  3. **Submit Your Review.** Click "Finish your review" and submit. In **Listen to all comments** mode, Promptless processes the review automatically. In **Require @promptless mentions** mode, tag @promptless in the review summary.
</Steps>

## Examples of feedback you can give to Promptless

### Content updates

Request specific changes to the documentation content:

```txt wordWrap
Please add a section about error handling for this API endpoint
```

```txt wordWrap
This example should use TypeScript instead of JavaScript
```

```txt wordWrap
Add a note that this feature requires admin permissions
```

### Structural changes

Suggest improvements to the documentation structure:

```txt wordWrap
Move this section to the beginning of the page for better flow
```

```txt wordWrap
Split this into two separate sections: "Basic Usage" and "Advanced Configuration"
```

```txt wordWrap
Add a table of contents at the top of this page
```

### Technical corrections

Point out technical inaccuracies or missing details:

```txt wordWrap
The API endpoint should be /v2/users, not /v1/users
```

```txt wordWrap
Add the required headers for authentication
```

```txt wordWrap
Include the response status codes for each endpoint
```

### Style and formatting

Request improvements to presentation and readability:

```txt wordWrap
Format this as a code block instead of inline code
```

```txt wordWrap
Add syntax highlighting for the JSON examples
```

```txt wordWrap
Use a callout box to highlight this important warning
```
