Some feedback fixes the suggestion you're reviewing right now. Other feedback also teaches Promptless a durable convention it applies to every future suggestion. This page helps you decide among three common situations:

- You need to fix the suggestion in front of you right now.
- You're closing this suggestion but want Promptless to remember the feedback for next time.
- The docs PR is already open and you want to comment there.

These are decision paths, not the full set of feedback options. The [Teach conventions with feedback](/docs/for-docs/tune/teaching-conventions) guide documents every dashboard method and walks through each in full.

## Request changes on the current suggestion

To update the suggestion in front of you before it's published, use the **Request Changes** button. Your typed feedback addresses the suggestion you're reviewing. You can also ask, in that same request, for your feedback to carry forward to future suggestions. To make a preference durable without repeating it, use the **Remember this feedback for future suggestions** checkbox (next section) instead. For the step-by-step walkthrough, see [Request changes](/docs/for-docs/tune/teaching-conventions#1-request-changes).

## Remember feedback for future suggestions

The **Remember this feedback for future suggestions** checkbox appears when you close (reject) a suggestion. It teaches Promptless a durable, team-wide standard for future suggestions. Closing the suggestion doesn't publish or apply any changes to the one in front of you. To fix the current suggestion and carry the preference forward, use **Request Changes** (the first method) instead. See [Close suggestion feedback](/docs/for-docs/tune/teaching-conventions#4-close-suggestion-feedback).

## Comment on the GitHub PR

Once the docs PR is open, you can give feedback directly on GitHub by tagging @Promptless in a PR comment or review. See the full [Review and edit Promptless PRs](/docs/for-docs/work-the-queue/reviewing-prs) guide, and [GitHub PR comments](/docs/for-docs/tune/teaching-conventions#5-github-pr-comments) for how it fits with the other methods.

## Which method to use

| Situation                                                           | Method                                   | Where to go                                                                                       |
| ------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Updating the suggestion you're reviewing now                        | Request changes                          | [Request changes](/docs/for-docs/tune/teaching-conventions#1-request-changes)                     |
| Closing a suggestion while teaching a durable, team-wide convention | Remember feedback for future suggestions | [Close suggestion feedback](/docs/for-docs/tune/teaching-conventions#4-close-suggestion-feedback) |
| Leaving feedback after the PR is already open                       | GitHub PR comment                        | [Review and edit Promptless PRs](/docs/for-docs/work-the-queue/reviewing-prs)                     |
