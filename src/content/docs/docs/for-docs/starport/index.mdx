Starport is a managed docs-as-code framework, built on the open-source [Astro Starlight](https://starlight.astro.build/). Promptless stands up your documentation site, sets up its build and deploy pipeline, and keeps its content current as your product changes. The content lives in a Git repository your team owns. The site runs on a hosting provider you choose, such as Vercel, on an account you own.

<Aside type="tip" title="Migration is included, and optional">
  You don't need Starport to use Promptless. Promptless keeps your docs current on your existing setup. When you do want to move, every annual Promptless plan includes migration to Starport at no cost.
</Aside>

<Aside type="note">
  The documentation you are reading runs on Starport. Promptless migrated promptless.ai onto the Starport template and keeps it current.
</Aside>

## Use cases

Starport fits teams who want docs-as-code run as a service, on hosting they control:

| Your situation                                                                             | How Starport helps                                                                                                                                                               |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Your docs live on a hosted platform, and you want the content in a Git repository you own. | Promptless migrates the content onto Starport as Markdown and MDX files in your repository. See [Migrate to Starport](/docs/for-docs/starport/migration).                        |
| No one on your team has time to run a docs build, search, and redirects.                   | Promptless sets up the pipeline, which then runs in CI. Your team adjusts settings in plain configuration files. See [How Starport works](/docs/for-docs/starport/how-it-works). |
| AI agents and coding assistants need to read your docs.                                    | Every Starport site ships llms.txt files and, by default, a read-only docs MCP server and page actions. See [Agent-ready docs](/docs/for-docs/starport/agent-ready).             |

## What Starport gives you

<CardGrid>
  <Card title="Build pipeline set up for you, hosting you own" icon="rocket">
    Promptless sets up your build and deploy pipeline, which then runs in CI, so your team spends its time on content. Your site runs on a provider you choose, such as Vercel, on an account you own.
  </Card>

  <Card title="Agent-ready by default" icon="seti:default">
    Starport sites ship llms.txt files, a read-only docs Model Context Protocol (MCP) server, and page actions. AI agents use them to read and search your docs.
  </Card>

  <Card title="Self-service configuration" icon="setting">
    After onboarding, set site metadata, branding, search, redirects, and deploy options yourself, in plain configuration files.
  </Card>

  <Card title="Kept current by Promptless" icon="approve-check">
    Promptless detects when your product changes and opens documentation pull requests against the Git repository you own.
  </Card>
</CardGrid>
