Every Starport site ships the capabilities below, built on the open-source Astro Starlight framework. Two of them have their own pages: [agent-ready docs](/docs/for-docs/starport/agent-ready) and [analytics](/docs/for-docs/starport/analytics). To change any of them after onboarding, see [Configure your Starport site](/docs/for-docs/starport/configuring-starport).

## Use cases

- Compare Starport with your current docs platform before you migrate, for example to confirm that your API reference, translated pages, and old URLs carry over.
- Answer a requirement that AI agents and coding assistants can read your docs.
- Check which quality checks run on your docs, from broken-link validation at build time to scheduled procedure tests.

## Capabilities

| Capability                | What you get                                                                                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Internationalization      | Locale routing through Starlight i18n. The template ships English with a sample Spanish locale.                                               |
| Multi-section navigation  | Group your pages into topic sections, each with its own sidebar.                                                                              |
| OpenAPI API reference     | Render a reference from one or more OpenAPI specs, each with its own sidebar group.                                                           |
| llms.txt files            | The build generates `llms.txt`, `llms-full.txt`, and `llms-small.txt` so AI agents can load your docs as plain text.                          |
| Docs MCP server           | A read-only Model Context Protocol (MCP) server at `/mcp` lets AI clients search and read your docs. It's on by default.                      |
| Page actions              | Each page has controls to copy it as Markdown or open it in ChatGPT or Claude.                                                                |
| Agent-readiness scoring   | A daily check scores your published site against the agent-friendly docs spec and fails when the score drops below your minimum.              |
| Broken-link validation    | The build checks your internal links and fails on a broken one.                                                                               |
| Redirects                 | Author redirects in `redirects.json`, and the build emits them as permanent redirects.                                                        |
| Sitemap                   | The build generates a sitemap for search engines.                                                                                             |
| Site search and assistant | Full-text search across your docs and API reference. Add an Anthropic API key to turn on an assistant that answers questions from your pages. |
| PDF export                | Print any page to PDF, and export named sets of pages to PDF on a weekly schedule.                                                            |
| Content linting           | Frontmatter validation, Vale prose linting, and Markdown structure linting run over your content.                                             |
| Doc Detective testing     | Runs the procedures in your docs as tests. A weekly run opens a GitHub issue when a test fails, and Promptless proposes a fix.                |
| Hosting                   | Deploy to Vercel by default. The template also documents deploys to GitHub Pages and Cloudflare Pages.                                        |
