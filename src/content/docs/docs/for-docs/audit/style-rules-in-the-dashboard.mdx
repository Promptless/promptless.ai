## Overview

Promptless checks every draft against your organization's [style rules](/docs/for-docs/audit/standards-enforcement#turn-your-style-guidance-into-rules) before it creates a suggestion. The **Rules** page in the dashboard lists those rules. Use it to see which rules your docs break most often and where each rule comes from. You can also change a Vale rule's level, message, or patterns without editing YAML files in your Agent Knowledge Base.

## Before you start

- Any member of your Promptless organization can view the rules.
- To save a change, you need an admin role in the organization.

## Find a rule

On the [Promptless dashboard](https://app.gopromptless.ai), select **Rules** under **Style guide** in the sidebar.

The list shows each Vale rule's level, its source, and its violations. The violations count is how many matches the rule has on your connected doc collections in the latest style check. Use **Counts in** to count one collection's pages. To narrow the list, search by a rule's name, message, or pattern, or filter by level or source. Sort by violations to see the rules your docs break most.

Judgment rules appear in their own group at the end of the list. Vale can't check them, so Promptless applies them while it drafts. To change a judgment rule, edit your style guide or `style/rules/judgment-rules.md` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base).

## See where a rule comes from

Open a rule to see its source under the rule name. Each rule comes from one of these sources:

- Your style guide. Promptless wrote the rule from stated guidance, and the rule cites the guide's file and line.
- Your docs. Promptless observed the convention across your pages and wrote it as a suggestion-level rule.
- Promptless defaults. The rule belongs to the default styles Promptless applies for every organization.

Check the source before you change a rule. When a rule from your style guide is wrong, fix the guide too. The next analysis then writes the rule the way you want it.

## Edit a rule

Edit a rule when its level is too strict or too lenient, or when its message doesn't help writers fix the text. Edit its patterns when they match text they shouldn't.

<Steps>
  1. On the **Rules** page, select the rule.

  2. Change the rule's **Level**, **Message**, or the fields for its Vale rule type. To see the rule file your change produces, select **Raw YAML**.

  3. Select **Save**.
</Steps>

Promptless checks that Vale can compile the changed rule and saves it to `style/rules/` in your Agent Knowledge Base. It then checks your connected collections again, so the violation counts reflect the change. Later analyses treat a rule you saved as your team's and keep it as you wrote it.

<Aside type="note">
  Your organization might keep its rules in a [rules collection](/docs/for-docs/audit/standards-enforcement#keep-your-rules-in-a-repository). That repository then holds the canonical rules. The dashboard shows them, and you edit them in the repository.
</Aside>

## Turn off a Promptless default

Promptless defaults are read-only in the dashboard. Your style guide might take a different position than a default rule. To turn the default off for your organization, set it to `NO` in `style/rules/vale.ini` in your Agent Knowledge Base. Put the setting under the section for the files it covers:

```ini
[*.md]
Direct.Hedging = NO
```

Open a default rule to see whether it can be turned off. Promptless keeps some defaults on for every organization. A doc collection that sets the same rule in its own Vale configuration keeps its own setting. To review your organization's overrides, select **vale.ini** on the **Rules** page.
