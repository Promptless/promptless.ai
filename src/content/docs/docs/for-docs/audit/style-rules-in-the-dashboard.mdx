## Overview

Promptless lints every suggestion with your organization's [Vale rules](/docs/for-docs/audit/vale-rules). The **Rules** page in the dashboard lists those rules with how often your docs break each one. Use it to find the rules your docs break most and to check where each rule comes from. You can also fix a rule that is too strict or that flags correct text. You edit the rule in a form, and Promptless writes the YAML file for you.

## Before you start

- Any member of your organization can view the rules. To save a change, you need the admin role.
- If your organization keeps its rules in a [rules collection](/docs/for-docs/audit/vale-rules#where-the-rules-live), the **Rules** page shows the rules from that repository. Edit those rules in the repository.

## Find the rules your docs break most

In the [Promptless dashboard](https://app.gopromptless.ai), select **Style guide** > **Rules**.

The **Violations** column counts each rule's matches in the latest style check of your GitHub and GitLab doc collections. Sort by **Violations** to see the rules your docs break most. To count one doc collection, select it in **Counts in**. To narrow the list, search by a rule's name, message, or pattern, or filter by level or **Source**.

Judgment rules are rules that Vale can't check, such as a rule about tone. Promptless applies them as it writes. To change a judgment rule, edit your style guide or `style/rules/judgment-rules.md` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base).

## Check where a rule comes from

Open a rule to see its source. Check the source before you edit, because it tells you where to make a change that lasts:

| Source              | What it means                                                                                            | Where to change the rule                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Your style guide    | Promptless wrote the rule from a rule your style guide states. The rule cites the guide's file and line. | Fix the style guide, then edit the rule in the dashboard if you need it now. |
| Your docs           | Promptless observed the convention across your pages and set the rule to suggestion level.               | To enforce the convention, add it to your style guide.                       |
| Your team           | A person wrote the rule or last saved it from the dashboard.                                             | Edit the rule in the dashboard.                                              |
| Promptless defaults | The rule is one of the default rules Promptless runs for every organization.                             | Turn the rule off in `style/rules/vale.ini`. See the next section.           |

Promptless rewrites the rules that come from your style guide and your docs when it updates your rule set. To keep a change to one of those rules, make the same change in your style guide.

## Edit a rule

Edit a rule when its level is too strict or too lenient, or when its message doesn't help a writer fix the text. Edit its patterns when they match correct text.

<Steps>
  1. On the **Rules** page, select the rule.

  2. Change **Level**, **Message**, or the fields for the rule's Vale type.

  3. Optional. To review the YAML file your change produces, select **Raw YAML**.

  4. Select **Save**.
</Steps>

When you select **Save**, Promptless checks that Vale can compile the rule. If Vale can't compile it, Promptless doesn't save the rule and names the line to fix. Promptless then commits the rule file to `style/rules/` in your Agent Knowledge Base and lints its next suggestion with the changed rule. The violation counts update after the next style check of your doc collections.

## Turn off a Promptless default

Promptless default rules are read-only in the dashboard. When your style guide takes a different position than a default rule, turn the default off for your organization. Open the default rule to see whether it can be turned off. Promptless keeps some defaults on for every organization.

<Steps>
  1. In your Agent Knowledge Base, open `style/rules/vale.ini`.

  2. Under the section for the files the setting covers, set the rule to `NO`:

     ```ini
     [*.md]
     Direct.Hedging = NO
     ```

  3. Select **Save**.
</Steps>

A default rule accepts only `NO`, not a different level. A doc collection that sets the same rule in its own Vale config keeps its own setting. To review your organization's overrides, select **vale.ini** on the **Rules** page.
