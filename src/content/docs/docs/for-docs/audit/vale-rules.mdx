Promptless keeps one Vale rule set for your organization and lints every doc collection with it. This page covers how the rule set gets created, where it lives, and how it changes.

For how Promptless runs Vale on a suggestion, see [Vale integration](/docs/for-docs/audit/standards-enforcement).

## Use cases

| Problem                                                              | What to do                                                                                              |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| You have a style guide but no Vale rules.                            | Share the style guide. Promptless [writes the rules](#how-the-rules-get-created) from it.               |
| Your organization keeps its Vale rules in a Git repository.          | Set the repository as your [rules collection](#where-the-rules-live).                                   |
| Reviewers repeat the same style comment on Promptless suggestions.   | Give the feedback once. Promptless [adds a rule](#how-the-rules-change) for it.                         |

## How the rules get created

During your [pilot](/docs/for-docs/start-here/run-a-pilot), the Promptless team works with your technical writers to turn your style guidance into Vale rules. Share your style guide and your Vale configuration, if you have one, before the pilot starts.

Promptless also writes rules on its own. When it analyzes a doc collection, it reads the collection's style guidance and writes a Vale rule for each rule that Vale can check.

The source of a rule sets its severity:

| Source                                         | Severity           |
| ---------------------------------------------- | ------------------ |
| A rule your style guide states                 | error or warning   |
| A strong convention observed across your docs  | suggestion         |

To enforce an observed convention, add it to your style guide. Promptless then raises the rule to error or warning.

## Where the rules live

Promptless records the rule set under `style/rules/` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base).

If your organization keeps its Vale rules in a Git repository, add the repository as a doc collection and set it as the rules collection:

```yaml
style:
  rules_collection: acme/style-rules
```

Promptless then syncs the rule set from that repository before each update. When it writes or changes a rule, it proposes the change to the repository as a suggestion.

Without a rules collection, Promptless proposes the rules to your documentation repository as a suggestion when it can place them there:

- When the repository has a Vale configuration, the suggestion adds the rules to it.
- When the repository has no Vale configuration, the suggestion can add one.

Promptless checks each rule against the Vale version your CI pins. When a rule needs a newer version, the suggestion raises your pin or rewrites the rule for the pinned version.

## How the rules change

Promptless updates the rule set when your style guidance changes:

- **You give feedback.** Promptless adds the style preferences it learns from your feedback to `style/client_style_guide.md` in your Agent Knowledge Base. It then writes or extends the Vale rules that enforce them.
- **You change your style guide.** Promptless updates the rules that came from the changed guidance.
- **A rule flags correct text.** Promptless narrows the rule.

Each change reaches your repository as a suggestion, so you review it before it merges.
