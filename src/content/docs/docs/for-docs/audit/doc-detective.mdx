## Overview

Docs describe how your product works. Every setup guide, UI walkthrough, CLI example, and API tutorial contains product assertions: this button exists, this command succeeds, this page appears, this link works.

Promptless uses [Doc Detective](https://docs.doc-detective.com/) to make each of those assertions executable. Doc Detective is an open-source implementation of the [Docs as Tests](https://www.docsastests.com/docs-as-tests/concept/2024/01/09/intro-docs-as-tests.html) framework. That framework tests documentation against the real product experience, beyond proofreading it for style and checking it for broken links.

Enable Doc Detective on a doc collection when you want Promptless to keep tests current along with the prose. When a new feature changes the product, Promptless can document the change and add the tests that prove the documented workflow still works. With Doc Detective enabled, Promptless:

- Creates Doc Detective tests when new documented workflows, UI paths, commands, or setup procedures are added
- Updates existing Doc Detective tests when product changes make the old workflow stale
- Reuses your existing Doc Detective config and test layout
- Responds to CI failures on its documentation PRs, and updates the suggestion branch when the docs change caused the failure

Executable tests are one of the tools behind [Audit and keep your docs healthy](/docs/for-docs/audit/keep-docs-healthy). They keep remediated procedures accurate as the product changes, so a workflow you just fixed doesn't quietly go stale again.

<Aside type="note">
  Doc Detective is an open-source documentation testing framework. You can view the core project at [doc-detective/doc-detective](https://github.com/doc-detective/doc-detective). The agent tooling Promptless uses is at [doc-detective/agent-tools](https://github.com/doc-detective/agent-tools).
</Aside>

## Before you start

- An admin role in your Promptless organization, to edit the [Configuration page](https://app.gopromptless.ai/configuration).
- Optional. A Doc Detective config file in your docs repository, such as `.doc-detective.json`, `.doc-detective.yaml`, or `.doc-detective.yml`.

## Enable Doc Detective on a doc collection

To enable Doc Detective with a config file:

<Steps>
  1. On the **Doc collections** tab of the [Configuration page](https://app.gopromptless.ai/configuration), expand the doc collection.

  2. Select **More filters (optional)**.

  3. In **Doc Detective config path**, enter the repo-relative path to your Doc Detective config file, such as `.doc-detective.json`, `.doc-detective.yaml`, or `.doc-detective.yml`.

  4. Select **Save changes**.
</Steps>

Leave **Doc Detective config path** blank to keep Doc Detective off. Clearing the field and saving turns Doc Detective off for the collection.

To enable Doc Detective without a config file, switch the Configuration page to **YAML** mode and add an empty `doc_detective` key to the doc collection:

```yaml
doc_collections:
  acme/docs:
    doc_detective: {}
```

Without a config path, Doc Detective looks for `.doc-detective.json`, `.doc-detective.yaml`, or `.doc-detective.yml` at the repository root, in that order, and uses its defaults when it finds none. Promptless also inspects the repository for existing Doc Detective specs before it adds coverage. To set the path in YAML, add it under the same key, as `doc_detective.config_path`. See the [Configuration reference](/docs/for-docs/reference/configuration-reference#doc-collections) for the full doc collection schema.

## Default behavior

When Doc Detective is on for a doc collection, Promptless handles tests this way by default:

- **Test coverage:** Promptless writes or updates tests for the workflows a docs change touches and commits them in the same suggestion.
- **Validation:** Promptless runs your configured syntax check, when you have one, before it opens the suggestion. A syntax check confirms that the test files are valid; only a test run exercises your product.
- **Test runs:** Promptless runs your tests against your product only when someone asks, in the task request or in a comment on the suggestion. If your CI runs Doc Detective, your tests also run there on the docs PR. See [CI failure handling](#ci-failure-handling).
- **Results:** Promptless records the checks it ran and their results in the suggestion description. Citations on the docs PR link changed passages to the source evidence behind them.

A test run needs whatever your tests depend on, such as a test account and its credentials. Store credentials as [environment variables](/docs/for-docs/scale/environment-variables) in Promptless. When something a test needs is missing, Promptless reports what blocked the run.

To change these defaults, add an instruction to `PROMPTLESS.md` in your [Agent Knowledge Base](/docs/for-docs/get-the-most-out/agent-knowledge-base). For example, tell Promptless to run your Doc Detective tests before it opens every suggestion. Promptless loads `PROMPTLESS.md` into every session.

## CI failure handling

Doc Detective is most useful when it runs in CI with the rest of your documentation checks.

When a GitHub check suite fails on an open Promptless docs PR, Promptless:

1. Resolves the failing PR back to the Promptless suggestion that created it.
2. Fetches the failing check runs and a preview of the logs.
3. Starts a follow-on investigation with the PR, failing check names, conclusions, and log preview.
4. Determines whether the suggestion caused the failure.

If the suggestion caused the failure, Promptless updates the suggestion branch with the fix. If the failure is pre-existing or unrelated, Promptless keeps the suggestion scoped to its original work. If it finds a separate docs issue outside the suggestion's scope, it can create separate work for that issue without expanding the original PR.
