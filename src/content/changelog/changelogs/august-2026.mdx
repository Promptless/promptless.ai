**New Features:**

* **Re-review GitHub PRs as new commits land:** A `github_pr` trigger accepts a new opt-in `trigger_on` value, `updated`. When new commits land on an open pull request, Promptless re-reviews it and keeps its suggestions current. The value requires an explicit `repos` list (`repos: all` isn't allowed) and applies to GitHub only. See [Trigger modes](/docs/for-docs/connect/triggers/github-prs#trigger-modes).

* **Start a Promptless session from a Jira ticket:** A Jira ticket can start a Promptless session. Assign the ticket to Promptless, label it `promptless`, mention Promptless in a comment, or set a trigger on a Jira project, label, or status. Promptless replies on the ticket with the documentation PR linked. See [Jira triggers](/docs/for-docs/connect/triggers/jira).

* **Trigger documentation work from a GitLab merge-request comment:** Mention `@promptless` anywhere in a merge-request comment to start documentation work, as on GitHub. Matching is case-insensitive, and OSS projects use `@promptless-for-oss`. GitLab also recognizes `/promptless` at the start of a comment line, though less reliably. A comment on a merge request Promptless opened revises that suggestion. A comment on any other merge request starts a new documentation review. Promptless reviews the merge request even if its project isn't in your trigger's repo list, if your GitLab connection can access it. Only comments trigger work, not merge-request titles or descriptions. See [GitLab merge requests](/docs/for-docs/connect/triggers/gitlab-merge-requests#request-documentation-via-merge-request-comments).

* **Acknowledge GitLab merge-request comment mentions with a 👀 reaction:** Promptless adds a 👀 reaction to GitLab merge-request comments that mention `@promptless`, as on GitHub. The reaction shows it saw the request, even when no documentation change is needed. See [GitLab merge requests](/docs/for-docs/connect/triggers/gitlab-merge-requests#comment-mention-acknowledgment).

* **Post citations as inline comments on GitLab merge requests:** Citations post as discussion threads on the GitLab merge request diff, as on GitHub. A citation that can't be anchored to the diff posts as an unanchored thread naming the file and line. See [GitLab projects](/docs/for-docs/connect/doc-locations/gitlab-projects#automatic-merge-request-creation).

* **Run documentation checks on a schedule:** Schedule triggers run standing instructions on a cron schedule, at most once an hour, in the timezone you pick. For example, check every Monday morning that the changelog and release-notes page agree. See [Schedule triggers](/docs/for-docs/connect/triggers/schedule).

* **Triage every screenshot in one place:** The new Screenshot Updates tab shows every screenshot on open suggestions in one gallery, grouped by doc collection. Click a screenshot to open its suggestion. See [Screenshot Updates](/docs/for-docs/work-the-queue/web-interface#screenshot-updates).

* **Start documentation tasks from your editor over MCP:** Connect Promptless to an MCP client like Claude Code or Cursor. From your editor, start documentation tasks, search suggestions, list your collections, and check task status. The connection authorizes with OAuth, so every org member can set it up without an API key. Server-to-server callers keep using API keys. See [MCP triggers](/docs/for-docs/connect/triggers/mcp).

* **Run the whole documentation loop from your editor over MCP:** Ask Promptless to revise a suggestion, and it updates the same docs PR. You can also set a suggestion's labels, assignees, and title, open its docs PR, or close it. Check a task to get its outcome and docs PR link, or list your recent tasks to find one. You can connect from Cursor, VS Code, Codex CLI, or Claude Code. See [MCP triggers](/docs/for-docs/connect/triggers/mcp).

* **Serve workflow guidance to your editor as MCP skills:** MCP skills load in editors that support the draft Skills extension (SEP-2640). The first skill is a backlog-triage workflow that walks through your suggestion queue and gives each suggestion an outcome. To support it, `search_suggestions` gains a `labels` filter, so you can pull a labeled queue, such as every `P0` suggestion, in one call. The extension is a draft, so its shape can change. See [MCP triggers](/docs/for-docs/connect/triggers/mcp).

* **Read suggestions and submit tasks over the `/v1` HTTP API:** The external HTTP API accepts documentation tasks from any client. It also serves a suggestion lifecycle feed and lists your doc collections. Requests authenticate with your organization's `sk-pl-` API key. Task submission accepts an optional `Idempotency-Key` header, so a retried request doesn't create a duplicate. See [API triggers](/docs/for-docs/connect/triggers/api).

* **Hold multiple named API keys:** Your organization can hold multiple named API keys. Name each key for its purpose, and create or revoke it without affecting other keys or their callers. See [API triggers](/docs/for-docs/connect/triggers/api).

**Improvements:**

* **CI failures appear as a "CI failed" event:** A failed docs PR check shows as a GitHub-branded "CI failed" event on the suggestion. The event is separate from human feedback and names the failed checks, for example "build, lint failed." Past three checks, it abbreviates, as in "build, lint, e2e and 2 more failed."

* **Research breakdown shows Knowledge Base reads inline and attributes delegated research:** The research breakdown lists Knowledge Base reads in read order. It appears on the Triggers page and a suggestion's **Triggers & Analysis** tab. Delegated research appears as a branch labeled with the subagent type and its tool-call count. A "research agents" callout appears next to the summary. See [Research breakdown](/docs/for-docs/work-the-queue/web-interface#research-breakdown).

* **Connect GitLab with a group or personal access token:** Connect a GitLab group with its path and an `api`-scoped group or personal access token. Promptless checks the scope as you connect and installs merge-request webhooks on the projects where the token has Maintainer access. The connection's card shows each project's state: visible, webhook-eligible, active, ineligible, or failed. See [GitLab integration](/docs/for-docs/reference/integrations/gitlab#token-scope-considerations).

* **`search_suggestions` requires a search query:** The MCP `search_suggestions` tool requires a `query` of at least 3 characters. See [MCP triggers](/docs/connect/triggers/mcp).

* **Backfill first-approval GitHub PR triggers:** You can backfill a GitHub PR trigger that activates only on first approval. The backfill preview lists open pull requests whose first approval landed within the selected window, including pull requests opened before it. See [Backfill suggestions](/docs/for-docs/connect/triggers#backfill-suggestions).

* **Trigger cards show the agent's response and research breakdown:** Completed trigger cards show an **Agent Response:** preview. It often explains why a trigger finished without a suggestion. Expand **Show details** to open the trigger's research breakdown on the card. See [the Triggers page](/docs/for-docs/work-the-queue/web-interface#triggers-page).

**Bug Fixes:**

* **Image changes show a before/after diff and apply correctly:** The suggestion viewer shows image changes as a side-by-side before/after diff. An added or deleted image shows only the side that exists. Suggestions that change only images show their real status and can be applied and published. Rejecting an image in a suggestion restores the original version, the same as rejecting a text file.
